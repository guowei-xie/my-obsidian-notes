
# 假设验证方法论

---

## 验证逻辑总览

三个假设构成递进的验证链：

```
假设 1: 分层有效
  不同意向层级和因素信号之间的转化率存在显著差异
  → 证明：AI 标签体系能有效区分用户状态，分层策略有意义
        ↓
假设 2: 销售做功空间存在 & 干预节点可定位
  不同销售在各节点的意向分布存在差异，且方差在特定节点发生变化
  → 证明：销售能力差异真实存在，方差拐点即为最佳干预时机
        ↓
假设 3: 干预有效
  策略上线后，通过 AB 测试验证副驾干预对转化的提升效果
  → 证明：系统确实能改善销售行为和转化结果
```

**如果假设 1 不成立** → 标签体系无区分度，需重新设计分层逻辑
**如果假设 2 不成立** → 销售行为对意向推进影响有限，或干预节点无法定位
**如果假设 3 不成立** → 策略本身无效，需迭代干预方式

---

## 假设 1: 不同意向层级和因素信号的转化率存在显著差异

### 待证命题

> AI 提取的意向阶段（S0-S4）和因素标签（驱动/阻塞）对最终转化有显著的区分度，即标签分层体系具有业务价值。

### 为什么需要验证

标签体系是整个系统的基础。如果不同意向层级、不同因素组合之间的转化率没有显著差异，后续所有基于标签的策略推荐和资源分配都失去了根基。

### 数据需求

| 数据 | 来源 | 说明 |
|------|------|------|
| AI 提取的意向标签 | 标签提取 Agent 输出 | 需先完成 Phase 1 |
| AI 提取的因素标签 | 同上 | 驱动因素 & 阻塞因素 |
| 转化结果 | 订单表 | 续报 (0/1) |
| 用户画像 | 数仓 | 作为控制变量 |

### 分析方法

#### 方法 A: 意向阶段与转化的关联分析

```
预期: 转化率应随意向阶段单调递增
  S0 < S1 < S2 < S3 < S4 （转化率）

验证:
  1. 计算各意向阶段的转化率 + 95% CI
  2. 趋势检验（Cochran-Armitage trend test）
  3. 计算 AUC: 用意向阶段预测转化的 ROC 曲线
```

#### 方法 B: 因素标签与转化的关联分析

```
分别分析驱动因素和阻塞因素:

驱动因素:
  - 每种驱动因素出现 vs 不出现时的转化率差异
  - 多种驱动因素叠加的效果（是否存在协同效应）
  - 排列各驱动因素对转化的边际贡献

阻塞因素:
  - 每种阻塞因素的"杀伤力"排序
  - 不同阻塞因素的"可化解性"（出现后仍能成交的比例）
  - 同时存在多种阻塞因素时的转化概率
```

#### 方法 C: 多因素 Logistic 回归

```
Model 1 (基线): conversion ~ user_features
Model 2 (加入意向): conversion ~ user_features + intent_stage
Model 3 (加入因素): conversion ~ user_features + intent_stage + factors

比较:
  - Model 2 vs Model 1: 意向阶段的增量解释力（ΔR² / ΔAIC）
  - Model 3 vs Model 2: 因素标签的增量解释力
  
  → 如果增量显著，说明标签体系提供了用户特征之外的额外信息
```

## 假设 2: 销售在意向推进上存在显著能力差异，且干预节点可定位

### 待证命题

> 控制用户条件后，不同销售在各服务节点上的用户意向分布存在显著差异；且意向分布的方差在特定节点发生变化（方差拐点），该拐点即为最佳策略干预时机。

### 为什么需要验证

两层含义：
1. **能力差异**：如果所有销售在各节点的意向推进效果差不多，说明结果主要由用户自身条件决定，AI 干预 ROI 有限。
2. **干预节点**：即使差异存在，也需要找到"方差爆发点"——在这个节点之前销售差异尚小（还没来得及做功），之后差异急剧拉大（做功效果显现）。这个拐点就是副驾介入的最佳时机。

### 分析方法

#### 方法 A: 各节点的销售间意向分布差异

```
关键节点序列: 进班 → 首课开始 → 末课结束 → 续报窗口

在每个节点:
  1. 按销售分组，计算其用户在该节点的意向分布 P(S0, S1, S2, S3, S4)
  2. 控制用户初始条件（leads_score 分位数 × city_tier × grade_band）
  3. 对比不同销售的意向分布差异
     - χ² 检验 / Fisher 精确检验
     - 混合效应有序 Logistic 回归:
         intent_stage ~ user_features + node + (1|counselor_id)
       检验 counselor_id 随机效应的方差
```

#### 方法 B: 方差拐点分析（核心）

```
目标: 找到销售能力差异"爆发"的节点

方法:
  对每个节点 t，计算:
    σ²(t) = Var(各销售的标准化意向推进率)

  其中标准化意向推进率 = 控制用户条件后，某销售的用户从 S_init 到 S(t) 的推进幅度

  绘制 σ²(t) vs 节点 的曲线:

  σ²
  │              ╱ 
  │             ╱
  │          ╱     ← 方差拐点: 最佳干预时机
  │      ╱
  │───── 
  └──────────────→ 节点
  进班  首课前  首课后  期中  续报

解读:
  - 拐点前: 销售尚未充分做功，差异小 → 干预太早，信号不够
  - 拐点处: 差异开始拉大 → 最佳干预时机，此时干预可改变轨迹
  - 拐点后: 差异已成定局 → 干预太晚，改变空间有限
```

#### 方法 C: Top/Bottom 销售对比

```
Step 1: 构建"销售能力"排序
  在控制用户质量后，按标准化转化率将销售分为 Top 20% / Bottom 20%

Step 2: 对比两组在各节点的意向分布
  - Top 组在哪些节点上的意向推进显著优于 Bottom 组？
  - 差距在哪个节点开始显现？ → 与方法 B 的拐点交叉验证

Step 3: 行为归因
  - Top 组在拐点前后的行为有什么不同？（对话频次、响应速度、话术特征）
  → 为副驾策略提供具体的干预内容
```

### 成功标准

| 指标                             | 阈值（仅作示意）             | 含义             |
| ------------------------------ | -------------------- | -------------- |
| 混合效应模型中 counselor 随机效应         | ICC > 0.05, p < 0.05 | 销售个体效应显著       |
| Top 20% vs Bottom 20% 标准化转化率之比 | > 1.3                | 好销售比差销售至少高 30% |
| 方差曲线存在明确拐点                     | σ²(t+1)/σ²(t) > 2    | 可定位干预节点        |
| 拐点节点在续报窗口之前                    | 是                    | 干预时机有意义（还来得及）  |

## 假设 3: 副驾策略上线后能有效提升转化

### 待证命题

> 通过 AB 测试验证：接受副驾策略推荐的实验组，在目标指标（意向推进率、转化率）上显著优于对照组。

### 为什么需要验证

假设 1 和 2 证明了"问题存在"和"干预时机可定位"，但不能证明"我们的解决方案有效"。只有通过 AB 测试，才能从关联走向因果，确认副驾系统的实际价值。

### 实验设计

#### 分组方案

```
分组单位: 销售顾问（非用户）
原因: 避免同一销售对不同用户执行不同策略导致的行为污染

实验组: 使用副驾系统，接收策略推荐
对照组: 不使用副驾系统，维持现有工作方式

分组方法:
  - 按历史业绩分层随机化（stratified randomization）
  - 分层因素: 历史转化率分位、团队、城市
  → 确保两组的销售能力基线可比
```

#### 实验周期

```
前置期（1-2 周）:
  - 两组均不开启副驾
  - 收集基线数据，验证两组可比性

实验期（至少 1 个完整服务周期）:
  - 实验组开启副驾
  - 对照组维持现状

观察期（实验结束后 2-4 周）:
  - 跟踪滞后转化
  - 评估长期效果
```

### 评估指标

#### 主要指标

```
核心指标:
  - 转化率: 实验组 vs 对照组的续报率差异
  - 意向推进率: 方差拐点处的意向阶段分布差异

统计方法:
  - 双侧 t 检验 / Mann-Whitney U 检验
  - 分层分析: 不同能力层级的销售，副驾效果是否不同
    （预期: Bottom 销售受益更大）
```

#### 次要指标

```
过程指标（诊断策略是否被执行）:
  - 策略采纳率: 销售是否查看/执行了推荐的策略
  - 响应时效: 推荐发出后，销售的行动延迟
  - 覆盖率: 副驾在目标节点的推荐覆盖比例

效率指标:
  - 人均产出: 每个销售的成交用户数
  - 精力分配: 销售在高/低价值用户上的时间分配变化
```

### 成功标准

| 指标                  | 阈值（仅作示意）        | 含义         |
| ------------------- | --------------- | ---------- |
| 转化率提升               | > 2pp, p < 0.05 | 有统计显著的转化提升 |
| Bottom 50% 销售的转化率提升 | > 3pp           | 对弱销售帮助更大   |
| 策略采纳率               | > 60%           | 销售愿意使用推荐   |
| 意向推进率提升             | 显著, p < 0.05    | 过程指标也有改善   |

### 如果假设不成立

- 检查策略采纳率：如果采纳率低，问题在产品体验而非策略本身
- 检查策略内容：推荐是否足够具体、可执行？
- 分层分析：是否对某些类型的销售有效但整体被稀释？
- 检查实验污染：对照组是否通过非正式渠道获取了策略信息？
- 延长观察期：效果可能需要更长时间才能显现

## 验证执行计划

### 优先级与依赖

```
假设 1 ─── 需等 Phase 1 完成（AI 标签提取后才能验证标签价值）
  │
  │ 通过后
  ↓
假设 2 ─── 可部分验证（用历史转化率做销售间差异分析）
  │         完整验证需假设 1 通过 + 各节点意向标签
  │
  │ 通过后
  ↓
假设 3 ─── 需等策略引擎上线（Phase 2+），设计 AB 实验
```
