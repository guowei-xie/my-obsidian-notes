# 四阶段方法：Probe · Harvest · Refine · Apply

> 展开总览的「核心功能逻辑/方法论」：四阶段各答一个不同的问题，各把一个更精炼的对象交给下一阶段，各买一样东西（精度/覆盖/可读/规模）并付一种代价。主源 whitepaper §4。

一句话总览：**模糊直觉 → 一组人评例子 → 一个几何 cohort → 一份可读判据 → 全库标签**。

---

## Phase 1 · Probe — 调检索这面镜头

唯一交互、唯一循环的阶段。一「轮」= harness loop 转一圈：

```
agent 用锁死配置跑混合检索 ─▶ 工作台展示 top_k 融合 chunk
  ─▶ 操作者逐条评 FIT / NOT_FIT / DISCARD
  ─▶ agent 三段式反思：observe（证据显示什么）→ diagnose（为什么）→ hypothesise（下一轮会出什么）
  ─▶ append 到 progress log；已评 chunk 从后续搜索滤除（每轮出新料）
```

**三重收敛门**（whitepaper §4.1，判定代码见 [[01-架构与数据底座]]）：三条同时成立才算收敛——① 最新轮 P@K 过线（证明当前配置确在捞相关料）；② 累计不同 FIT ≥ 下限（够定义概念）；③ 累计不同 NOT_FIT ≥ 下限。**第三条是微妙点**：Phase 3 推导 rubric 需要**对比性反例**（概念「不是什么」的例子），零 NOT_FIT 收敛会饿死下游画边界的证据。操作者也可满意后手动停。

**受控例外：path audit**（whitepaper §4.1；`src/session/state.py`）。锁死配置唯一的中途松口：操作者怀疑某路只贡献噪声时可触发 audit——工作台把融合平时藏起来的 per-path 候选翻出来给评，只有证据过特定门才把该路 drop 掉、余下 session 生效。两种 drop 路径的安全网不同：

- **操作者手动 audit drop**（`apply_path_drop`）：过 **Rule B1**（融合 top-K 里没有 `source_paths` 恰为 `[待 drop 路]` 的 FIT 行，否则这些 FIT 会被静默丢失）+ **Rule B2**（该路的 per-path 候选里没有 FIT）+ 通用机械门（路仍活跃、不能 drop 最后一路）。
- **agent 推荐 drop**（`apply_recommended_drop`）：**跳过 Rule B**——agent 被要求在推荐前自己对着 progress log 核过 Rule B1（见 `harness/prompts/SYSTEM.md` 的 path-drop 契约）；操作者一键 `[a]pply` 即是门，apply 本身是机械的。一 session 只允许一次 agent 推荐 drop 落地（`recommended_drop_applied` 一次性保险）。

**Probe 也是探索发生的地方**（whitepaper §4.1，易被忽略的设计意图）：高质量查询很少一开始就有，而是操作者**探出来的**——用不同措辞探语料、读每次探回的反思、让累积图景同时磨利「对语料的理解」和「查询本身」。下游阶段只在查询值得 commit 时才跑。**配置锁死后，per-turn 反思主要不是控制信号，而是操作者理解语料的仪器。**

**产物**：不是调好的配置（那是副产品），而是**一组人评的 FIT/NOT_FIT 例子**。代价是人的注意力，一轮一轮付——这正是它不能充当「覆盖全库」机制的原因。

## Phase 2 · Harvest — 从例子到 cohort

**关键动作：把 FIT 从「结果」翻转成「查询」**（whitepaper §4.2）——当作概念范例（不是训练标签）：给定这 n 个人评例子，它们紧邻的 embedding 邻域里还有哪些 chunk？这一步兑现「所有相关 chunk」的承诺。

每个 FIT 带两个 dense 向量：**span 向量 `s_i`**（嵌操作者标出的概念承载片段，最紧的读法，Phase 2 从它发起搜索）+ **chunk 向量 `c_i`**（该 chunk 在 Milvus 被索引的向量）。两者落在 embedding 空间稍不同的区域，这个 gap 决定了标定方式。

**标定：从 FIT 自身导出半径**（whitepaper §4.2；数学落点 `src/anchor/threshold.py`）

- **session 级基准半径 T**：取每个 span 的 leave-one-out 最近邻距离 `ℓ_i = min_{j≠i} d(s_i, s_j)`，`T = p90({ℓ_i})`。用 90 百分位吸收集合内部大部分散布，又不让单个离群 span 撑大半径。**p90 硬编码为非可调轴**（`_T_QUANTILE=0.90`）。
- **per-anchor slack `δ_i = d(s_i, c_i)`**：桥接 span 流形到 chunk 流形——因为搜索从 span 向量发起而语料按 chunk 向量索引，连 FIT 自己的 chunk 都离它的 span 有 `δ_i`。
- **有效半径 `T'_i = T + δ_i`**：一个概念级散布（T）同时服务紧引用型（δ 大）和近整块型（δ 小）的锚点。度量全程是 cosine 距离 `d(u,v)=1 - cos_sim`，匹配 dense 字段的索引。

**两道健康检查**：

1. **anchor-quality gate**：drop 掉 `δ_i` 大得离谱的 FIT（退化锚点，半径会收进 cohort 散布之外的 chunk）。`δ_i > T` 恒开；`δ_i > k·median(δ)` 由 `s2c_outlier_multiple`（默认 3.0）控。
2. **leave-one-out recovery check**：防「例子各自没问题但整体不连贯 → 邻域不重叠 → cohort 成一堆不相连孤岛」。逐个把 FIT 藏起、其余重标定，问「藏起的那条还能在某个剩余锚点邻域里冒出来吗」。判为不健康则**中止整轮**——太不连贯的标定不该被信任来定义邻域。

**主搜索：单调加宽**（whitepaper §4.2）。对每个存活锚点开一次 dense k-NN 搜索，用 `s_i` 当查询向量打全库。Milvus 按 cosine 距离升序返回，**半径本身就是停机规则**——一页最后一个命中超过 `T'_i` 就关迭代器，无 probe-width 调、无候选上限。安全帽 `M`（`max_k`，默认 200000）防病态过宽，命中则**大声记日志而非静默截断**。n 个邻域 union 成候选集，每条候选记下它的最近-FIT 距离（下游 proximity 分）和收入它的全部锚点集合。

**anchor-frequency gate**（whitepaper §4.2；`config.yaml` 的 `harvest.anchor_frequency_gate`，默认 f=2）：**一条候选只有被 ≥ f 个不同 FIT 锚点收入才保留。** 几何直觉——各锚点球的 union 很宽松、吸收单锚点噪声；任意两球的**交集**紧得多，单锚点噪声很少同时落进两个独立评出的邻域；而真正的概念承载 chunk 贴近*每个*锚点的 span，基本不受影响。实践中要求双锚点一致能把 dense 查询的 cohort 缩数倍、常近一个数量级。每条保留 chunk 都记下最近锚点和全部收入锚点集，所以门可**离线**收紧/放松而无需重跑搜索。

**产物**：一个跨全库的**几何 cohort**。它的局限也在于此——完全由**距离**定义，而「近」与「表达同一概念」重叠但不等同，这正是下一阶段存在的理由。

## Phase 3 · Refine — 从几何到语言

把几何边界变成一条显式、语言级、可争论的边界（whitepaper §4.3）。

**交付物：rubric prompt**——一份自足文档，任何有 JSON mode 的 LLM 都能把它应用到任何 chunk：命名定义「属于该概念」的检查项、固定裁决结构，并携带 session 里的 FIT 范例 + NOT_FIT 反例（每个都标注它违反的具体检查项）。rubric 因此**可移植**：能被读、改、版本控制、独立于 Deka 下发。

**真正的工程点：meta-prompt**（whitepaper §4.3）。harness 贡献的不是某一份 rubric，而是**写 rubric 的那个 meta-prompt**——强模型对收敛 session 跑一遍就产出约定形状的 rubric，操作者可在锁定前改任意部分。让 rubric 推导**可复现**（而非每个查询做一次定制 prompt 工程）才是要害；每个衍生 artifact 都盖上**产生它的 meta-prompt 的 SHA-256**，任何 rubric 都能追到确切生成器。（meta-prompt 见 `harness/prompts/RUBRIC_DERIVE.md`）

**四步流程**（`src/refine/`）：

| 步 | 做什么 |
|---|---|
| **Derive** | 强模型（贵）产出 rubric，一轮一次 LLM 调用。FIT/NOT_FIT 范例超过上限（默认各 6，`max_fit/not_fit_examples`）时，用贪心 farthest-first 按 cosine 距离挑最语义多样的子集，防 prompt 溢出（只在需截断时才 embed，零额外成本给未超限 session）。 |
| **Sample** | 从 Phase 2 cohort 抽可控评测集（默认 ~500，`sample_size`），按到最近 FIT 的距离**分层（decile）**——保证从核心到边缘全覆盖，不只抽好抽的中心。Phase 1 已评的排除；已知 NOT_FIT 的直接 DROP 不花模型调用（`auto_drop_known_intruders`）。 |
| **Judge** | 快模型（便宜）逐 chunk 套锁定 rubric，限速异步 fan-out（`judge_concurrency`/`qps`/`tpm`），每个响应对 rubric 声明的 schema 校验。 |
| **Review** | 操作者面对裁决：**finalise**（rubric + 判过样本落盘、结束）或 **discard**（rubric 版本 +1、回编辑器）——保证每轮判都对着单一锁定谓词。 |

**两模型两职**（`config.yaml` refine 段）：derive 用强模型（authors rubric），judge 用快模型（applies per-chunk）。可设成同一个；拆开是为了默认不把强模型浪费在易事、也不饿死难事。

**产物**：一条可读、可审计的语言边界 + 一份判过标签的样本——而这个样本恰好是系统本来会扔掉的**训练集**。

## Phase 4 · Apply — 从样本到规模

rubric 本要铺满整个 Phase 2 cohort（可达数十万 chunk）。对每条都用 LLM judge（一条一调）会贵到超过 session 其余全部之和。但 Phase 3 刚顺手产出了几百条 KEEP/DROP 标签——**那就是训练集**。（whitepaper §4.4）

**廉价分类器**（`src/apply/`）：在这些标签上 fit 一个逻辑回归。特征 = **`[*dense_embedding, nearest_fit_distance]`**（`src/apply/features.py`）——dense 向量直接按 PK 从 Milvus 取（不重嵌），nearest_fit_distance 从 Phase 2 sidecar 来、**唯一被标准化的特征**（dense 分量留原样，BGE-M3 已单位化，标准化只会加噪）。类权重 balanced 防小类被淹。**rubric 仍是边界的*定义者*，分类器只是*应用者***，一次点积/chunk 铺满全库。

**偏向精度**（whitepaper §4.4）：为不污染下游消费者，分类器**调精度而非召回**——KEEP 类须过精度地板（`min_precision` 默认 0.75），低于此发货要操作者显式 override。理由非对称：错 drop 的相关 chunk 以后能靠更宽松一遍捞回；错 keep 的无关 chunk 会静默污染上层一切。**精度诚实估计**：对*全部*标注行做**重复分层 k-fold 交叉验证**（默认 5 折 ×5 次，`kfold_splits`/`eval_n_repeats`），不吊死在一次幸运划分上。

**操作者只碰阈值，不碰单条 chunk**：校准屏给出 P-R 曲线、当前阈值下的精度/召回、cohort 会怎么切成 KEEP/DROP、一组临界 chunk 轮播供 sanity check；操作者拖 slider 选工作点。确认后每条 cohort chunk 过一次持久化分类器、连裁决+keep 概率写出。**分类器文件记录训练时的 rubric 版本和 meta-prompt 哈希——rubric 之后变了，重跑就拒绝运行。**

**产物**：把「昂贵的逐条 LLM 判」变成「全库规模近零成本分类」。始于模糊直觉的弧，终于对语料库每条相关 chunk 一个可辩护的标签。

## 精度 / 成本 / 可读性 三轴

whitepaper §4 反复强调：四阶段各是沿三条轴（precision / cost / legibility）的一次**刻意变换**，每步买到的东西正是下一步的动机——

| 阶段 | 答的问题 | 买到 | 付出的代价 |
|---|---|---|---|
| Probe | 概念到底是什么？ | 精度（人评例子） | 人的注意力，一轮一付 |
| Harvest | 库里还有哪些像的？ | 覆盖（几何 cohort） | 只由距离定义（→ 需 Refine 补语义） |
| Refine | 为什么算数（用词说清）？ | 可读/可审计（语言 rubric） | 几百次模型调用 |
| Apply | 怎么铺满全库？ | 规模（廉价分类器标签） | 一次点积/chunk |
