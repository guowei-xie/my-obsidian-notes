# 模块 6 · 上线之后要操心的事

> 时长:30 min | 形式:讲解 | 受众:PM/管理层/BI分析师

---

## 一、本节目标

恭喜,东西上线了,同事点开链接就能用。但「开门营业」不是终点,而是另一摊事的开始。这一节我们讲清楚:产品活在线上之后,你这个非工程的「店主」要持续操心哪四件事。

- 看懂上线后的**钱**从哪儿花、怎么估、怎么不被「跑爆」。
- 记住一条最重要的**合规红线**:哪些内部数据**绝对不能**直接喂给外部 AI 服务。
- 知道怎么发现「有没有人用、出没出错、谁来修」——这就是「持续运营」。
- 想清楚一个边界:**原型自己做,规模化交给研发**——什么时候该松手。

一句话:**上一节是「开了餐厅」,这一节告诉你「餐厅开起来之后,水电费、食品安全、客流统计、招大厨,这些事谁来管」。**

---

## 二、讲师讲稿

### 2.1 成本:钱从哪儿花、怎么不被「跑爆」(⏱ 8 min)

**讲解要点**:上线后主要两笔钱——托管费(房租,相对固定)和 API 调用费(按用量,可能失控)。重点讲「为什么 API 费会突然爆掉」和「怎么设上限」。

**讲解词(可照念)**:
「上线之后,有两笔钱在持续地走。第一笔是**托管费**,就是租那台『永远开着的电脑』的钱,这笔像房租,大小固定、心里有数。第二笔才是真正要盯紧的——**API 调用费**。你的工具每问一次 AI,就花一次钱,按字数(token)算。自己测的时候一天问几十次,几毛钱;可一旦上线、几十人天天用,或者写错了一行代码让它陷入死循环不停地问,一夜之间账单从几块变几千,这叫『跑爆』。怎么防?**去 AI 平台后台设一个消费上限**,比如『每月最多 100 块,到顶就停』。这一步五分钟,能帮你省下一场事故。」

**类比**:托管费像家里的固定宽带月费;API 费像打车,平时没事,但万一程序「一脚油门踩死」不停叫车,账单能吓死人。所以要设一个「钱包额度」,刷爆就自动停。

**互动提问**:「你们现在用的任何按量付费的服务——云盘、短信、打车——有没有被某个月账单吓到过?上线产品的 API 费就是这种,而且没人盯就更危险。」

---

### 2.2 安全与合规:重点是「内部数据红线」(⏱ 10 min)

**讲解要点**:三层——密钥保护(上一节已讲,这里只点一句)、用户隐私、**以及对本受众最关键的:内部敏感数据能不能传给外部 AI**。这一节是全模块的重中之重,要敲死。

**讲解词(可照念)**:
「安全这块有三件事。第一,**钥匙**——上一节讲过,API Key 不能写在代码里,这里不重复,只提醒一句:钥匙泄露=别人花你的钱。第二,**用户隐私**——如果你的工具收集了用户的手机号、身份信息,这些得妥善存、不能乱发。

「但今天我要重点、反复敲的是第三件:**内部数据的合规红线**。你们手里都握着公司很敏感的东西——客户名单、销售数据、未公开的财报、源代码、合同。AI 工具好用,你很自然就想把一份真实的客户表丢给它『帮我分析一下』。**停。** 你要先问一句:**这份数据,一旦发给外部的 AI 服务,等于发给了一家外部公司的服务器。** 它可能被对方存下来、可能被用来训练模型、甚至可能在别人的回答里被『说漏嘴』。**有些数据,一旦出门就再也收不回来了。**」

**类比**:把内部数据发给外部 AI,就像把公司保险柜里的文件,复印一份塞进一个**你管不着的陌生人**的口袋——你不知道他会拿去干嘛,也要不回来了。

**讲解词(红线清单,可照念)**:
「给你们一条简单的判断标准——**『这东西能不能发到公司外部的邮箱?』** 不能发邮件出去的,就不能贴进外部 AI。典型不能传的:客户个人信息、未公开的经营/财务数据、合同与法务文件、公司源代码、带密码密钥的配置。真要用 AI 处理这类数据,正确做法是:**先脱敏**(把姓名、手机号换成『客户A』『138****』),**或者走公司批准的内部/私有部署模型**,而不是图省事直接贴进公网工具。**这条红线具体怎么划、哪些模型是公司批准的,务必去问咱们的法务/安全/IT 团队——这不是你一个人能拍板的事。**」

**互动提问**:「想一个你最近用 AI 处理过的数据——如果当时那份数据里有真实客户姓名,你现在回想,它合规吗?」(留 30 秒,让大家真出一身冷汗)

---

### 2.3 持续运营:有没有人用、出错了怎么知道、谁来修(⏱ 7 min)

**讲解要点**:上线不等于撒手不管。三个问题——用量(有没有人用)、监控/报错(出事怎么第一时间知道)、责任人(谁维护)。

**讲解词(可照念)**:
「东西上线了,接下来三个问题你逃不掉。第一,**有没有人用?** 做完不看数据,你都不知道它是宝贝还是没人理。简单加个访问统计,或者看托管平台自带的访问量,就能知道。第二,**出错了你怎么知道?** 不能等用户来骂你才发现挂了。好的做法是让平台在出错或宕机时**自动给你发个通知**(邮件、微信),你才能第一时间救火。第三,也是管理层最该想的:**谁来维护?** 这个工具是不是只有你一个人懂?你休假了、离职了,它坏了谁修?上线那天就该指定一个『责任人』,而不是变成一个没人认领的『孤儿应用』。」

**类比**:开了店没装客流计数器、没装烟雾报警器、还没排班表——生意好不好不知道,着火了不知道,老板不在店就没人管。运营就是把这三样补上。

**互动提问**:「你们公司有没有那种『当年某人做的表格/小工具,那人走了之后没人敢动、也没人会修』?上线的产品如果不指定责任人,就会变成这个。」

---

### 2.4 何时该交给研发:原型自己做,规模化交给研发(⏱ 5 min)

**讲解要点**:厘清边界。AI + 自己动手,适合做「原型、内部小工具、验证想法」;一旦要对外、要规模、要扛责任,就该交给专业工程团队。给出几条「该松手」的信号。

**讲解词(可照念)**:
「最后一个认知,也是给管理层的。今天教你们的这套本事,威力很大,但它有个**舒适区**:**做原型、做内部小工具、快速验证一个想法——你自己就能干,又快又省。** 但什么时候该把它交给研发团队?记几个信号:① 要给**公司外部的真实客户**用了;② 用的人从几十变成**成千上万**;③ 它开始处理**钱、合同、敏感个人信息**这类出事要担责的东西;④ 它已经**重要到不能挂**,挂一小时业务就出事。出现这些信号,就别再一个人扛了——你的角色这时候应该从『自己做』变成『讲清需求、做技术决策、和研发配合』。**自己做出原型这件事本身,就已经让你和研发的沟通效率高了十倍。**」

**类比**:你能在家做出一道超好吃的菜,甚至摆个周末小摊试卖——这很棒。但要开一家能稳定接待上千人、还得过食品安全检查的连锁店,你需要专业厨师团队和正规后厨。**自己会做菜,不等于要自己开连锁。**

**互动提问**:「对照刚才四个信号,看看你心里那个最想做的工具——它属于『自己做就够了』,还是『迟早得拉上研发』?」

## 三、上线后检查清单

上线后照着过一遍,绿灯了再安心。

| 类别 | 检查项 | 做到了吗 |
|---|---|---|
| 💰 成本 | 估算过每月托管费,心里有数 | ☐ |
| 💰 成本 | **在 AI 平台后台设了消费上限**,防「跑爆」 | ☐ |
| 💰 成本 | 知道用量大概多少、谁在买单 | ☐ |
| 🔒 安全合规 | API Key 没写在代码里,单独安全存放 | ☐ |
| 🔒 安全合规 | **没有把客户信息/财务/合同/源代码直接贴进外部 AI** | ☐ |
| 🔒 安全合规 | 处理敏感数据前先脱敏,或走公司批准的内部模型 | ☐ |
| 🔒 安全合规 | 合规红线已跟法务/安全/IT 确认过 | ☐ |
| 📈 运营 | 能看到有没有人用(访问统计) | ☐ |
| 📈 运营 | 出错/宕机会自动通知到人 | ☐ |
| 📈 运营 | 指定了明确的「维护责任人」 | ☐ |
| 🚦 边界 | 判断过现在该自己维护,还是该交给研发 | ☐ |

## 四、一页速查小结

**核心一句**:上线不是终点,接下来要持续操心四件事——花钱、合规、运营、边界。

| 要操心的事 | 一句话记忆 |
|---|---|
| ① 成本 | 托管费是房租(固定),API 费像打车(会爆)——**去后台设个消费上限** |
| ② 安全与合规 | **不能发出公司邮箱的数据,就不能贴进外部 AI**;敏感数据先脱敏,红线问法务 |
| ③ 持续运营 | 装好「客流计数器(用量)+ 烟雾报警(报错通知)+ 排班表(责任人)」 |
| ④ 何时交给研发 | 对外、上规模、担责任、不能挂——四个信号一出现,就拉研发 |

**最该刻进脑子的一句**:**有些数据一旦发给外部 AI 就收不回来了——发之前先问「这能发出公司吗?」**

## 五、讲师备注与易错点

- **本模块的灵魂是 2.2 的「数据红线」**。受众是 PM/管理层/BI,他们手里恰恰握着最敏感的数据,又最容易因为「AI 真好用」而顺手贴真实数据。这段一定要慢、要重、要敲到大家心里发紧。把「能不能发到公司外部邮箱」这条土办法标准重复两遍,它比任何技术解释都管用。
- **务必给出「找谁」的出口**。反复强调:具体红线、批准了哪些内部模型,**让大家去问法务/安全/IT**,而不是自己拍脑袋。讲师千万不要在课上替公司「定规矩」,只给方法和警觉。如课前能拿到公司实际的数据分级/合规政策,直接念出来代入感最强(对应框架待确认点 3)。
- **成本部分,最实用的一句是「去后台设消费上限」**。这是唯一一个学员当场就能记住、回去五分钟就能做、能真正避免事故的动作。别讲 token 计费的数学细节,讲了也记不住,留一句「按字数算钱」即可。
- **「跑爆」的痛感要给足**。用「死循环一夜烧几千块」这种具体后果,比抽象说「注意成本」有用十倍。可以接着模块 3「Key 被刷爆」的恐惧继续加码。
- **运营部分别展开技术**。监控、日志、告警这些词最多点一下,核心就讲「用量、报错通知、责任人」三件大白话事。重点敲「孤儿应用」这个公司里普遍存在的痛点,容易引起共鸣。
- **「何时交给研发」是给管理层的台阶**。要让业务方/管理层放心:今天学的东西不是要大家取代研发,而是让大家「能做原型、会提需求、看得懂全流程」。强调「自己做过原型,跟研发沟通效率高十倍」,消解「学了也白学」的顾虑。
- **时间紧,卡好节奏**。本模块只有 30 min,安全合规必须保住 10 min,其余三节各砍到位。若超时,优先压缩 2.1 成本和 2.3 运营,2.2 红线一分钟都不能少。
- **常见误区澄清**:① 「做出来=一劳永逸」——错,持续花钱、要人维护;② 「内部用用没关系吧」——错,数据出门的风险跟内外部用无关,只跟「发给了谁的服务器」有关;③ 「脱敏太麻烦」——比起数据泄露的代价,脱敏是最便宜的保险。
