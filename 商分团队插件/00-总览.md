# 商分团队插件 — 总览

> 产品代号待定（暂用「商分团队插件」），与本仓库 SalesCopilot 系列**完全独立**。

## 一、产品定位

一款面向公司**内部商分团队**的 Claude Code 插件，承载"角色化数据分析能力 + 安全可控的数据访问 + 持续迭代的知识沉淀"。

不是另一个 BI，不是通用 ChatBI。它解决的是：

- 把资深商分的**口径、方法学、报告模板**外化成"角色能力包"，按岗位发放
- 把 MySQL 的**表/列级权限**前置到调用入口，统一审计
- 把用户使用过程中暴露的**问题与经验**自动采集回流，驱动能力包持续迭代

## 二、目标用户

| 角色 | 画像 | 在本系统中要的东西 |
|------|------|----|
| 商分团队成员 | 业务侧岗位，多数不写代码，会写一点 SQL | 一个能听懂业务话、按本岗位口径出活的助手 |
| 资深商分 / 商分负责人 | 业务专家 | 一个低成本把自己的口径和经验固化下去，让团队都用对的工具 |
| 平台运营 | 后台维护人员 | 一个简单的后台管 token、内容版本、灰度 |
| 数据安全 / 合规 | 风控视角 | 一份能看清"谁在什么时间用什么 token 查了什么表"的审计记录 |

## 三、典型业务场景

- 用户增长商分：每周渠道质量复盘、新用户漏斗诊断、活动效果归因
- 教研商分：课程完课率、教学效果、教师产能
- 续费商分：续费率拆解、流失预警、续费策略 A/B

每个岗位的"常用表 + 口径 + 模板 + 报告"差异显著 → 一份通用 prompt 无法覆盖 → 需要**按角色装载**。

## 五、关键设计决策

| # | 决策 | 说明 |
|---|------|------|
| 1 | Claude Code 插件 + **内部分发** | 公司私有 marketplace，不对外发布 |
| 2 | **Token 化授权 + OA 外部审批** | 用户从 OA 申请 → 运营在后台**手工录单**生成 token → `/<插件名> token set <token>` 即用。**一用户一 token，后台为该 token 绑定多个角色包**，token 持有者可在已绑定范围内任选 |
| 3 | **MCP 网关代执行** | 客户端无 DB 直连凭证；网关做 ACL + AST 校验 + 审计 |
| 4 | **单插件壳 + 服务端动态返回角色包** | 启动时按 token 拉对应角色的 skill/SQL 模板/口径/表清单 |
| 5 | **个人习惯文件本地常驻** | 与角色包**物理分离**，覆盖更新永不丢失个人偏好 |
| 6 | 启动时**自动拉取**最新角色包 | 用户零感知，灰度由后台控制 |
| 7 | 采集做成**本地 Agent**，主动征询上报 | 用户控制 + 本地脱敏 + 智能摘要 |
| 8 | 平台元数据存 **MySQL**（与业务库可共用实例） | 不引入新依赖 |
| 9 | 表元数据来自**业务 MySQL schema 反射**，后台补字段中文/口径/敏感度 | 无外部表元数据系统可对接 |
| 10 | 角色包内容以 **references 三件套**（tables/metrics/methods.md）固化 | skill 强制先查口径，找不到则停手 + 产候选变更 |
| 11 | data-collector 输出**结构化候选变更包**（带 diff） | 反馈池审核即 review diff，效率倍增 |
