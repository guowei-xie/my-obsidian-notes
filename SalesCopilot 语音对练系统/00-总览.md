> 🔗 它是 SalesCopilot 图谱生态的**第三个消费者**：蒸馏服务把成功对话写进 Neo4j → [[SalesCopilot 策略生成服务/00-总览|策略生成服务]] 在线读图谱生成策略卡片 → **本系统读同一份图谱做「对练评价的经验锚定」**。三者共享 Neo4j schema（Factor/Approach/Experience）、S0-S4 意向坐标系；本项目 `src/graph/neo4j_client.py` 顶部注明「复用自 SalesCopilot-Strategy」。

## 一句话是什么

SalesCopilot-Coach 是一个**销售岗前语音对练系统**：新销售（界面里统一叫"老师"）在正式上岗前，选一个真实通话蒸馏样本或自定义模板，系统用 LLM 生成一个"AI 家长"人设 + 一套隐藏的异议/机会信号剧本，销售戴耳机与这个 AI 家长做**全双工实时语音对话**（火山引擎端到端语音）；练完后 LLM 把销售的实际话术**逐条对照 Neo4j 图谱里 Top 销售的处理方法**，输出总分、与 Top 的差距、雷达图和逐信号的改进建议，全程可回放双声道录音。

## 场景叙事与价值

**问题**：销售经验蒸馏服务已经把「什么情境下用什么方法有效」沉淀成 Neo4j 图谱，策略服务能把它变成"面对某个真实家长下一步怎么聊"。但**新销售的技能是练出来的，不是看出来的**——看再多策略卡片，第一次真人电访照样卡壳。传统岗前培训靠老带新陪练，成本高、标准不一、没有客观打分。

**这个系统把"陪练 + 复盘 + 对标"三件事自动化**：
- **陪练**：AI 家长按剧本和难度真实地提异议、挤牙膏式释放机会信号，销售必须用嘴实时应对（不是打字），逼近真实电访压力。
- **复盘**：全程双声道录音（左=老师 / 右=家长）+ 逐字稿，练完可回放。
- **对标**：评价不是拍脑袋打分，而是把销售话术和图谱里 **Top 销售在同类信号上的真实做法**对齐，算出"你达到了 Top 经验的百分之几"（`rule_anchor_score`），并指出具体差在哪、该怎么改。

**典型用法**（README 使用说明）：老师在【采样对练】页选样本 + 难度（困难/中等/简单）+ 可选音色 → 等十几秒出"本次对练要点"卡片（只给家长背景，**不剧透异议**）→ 点【开始对练】家长先开口 → 逐字稿实时滚动 → 处理完所有异议或家长同意报名后【结束对练】→ 出"对练结果"卡片（总分 + 与 Top 差距双进度条 + 信号雷达图 + 逐信号评价与建议 + 完整剧本折叠）。

**产品定位**：这是**训练场**，不是话术生成器——它给的是"你哪里没接住、Top 会怎么做"，让销售在无真实客户损耗的环境里试错。

## 核心功能逻辑

系统由三条管线串起，前两条分别走 REST 和 WebSocket，第三条在对练结束后触发。

### 管线一：剧本准备（REST `POST /api/sessions/start` → `src/api/sessions.py`）

两种模式：
- **sample 模式**：`src/db/mysql.py` 从 `distill_key_moments`（`human_reviewed=1 AND density='high'`）筛候选 sample_id → `fetch_dialogue_text` 取 `distill_conversations` 中该样本最后一行的 `dialogue_text`（超 12000 字截断）→ 若 Neo4j 可用，取 `CatalogCache` 的 factors 清单渲染进 prompt → LLM（deepseek-r1, temp 0.5, `prompts/script_gen_v2`）产出 `PracticeScript`。
- **template 模式**：直接把用户存的自定义模板转成 `PracticeScript`，**跳过 LLM**，不依赖任何外部数据（README 说"只想跑通流程用这个"）。

`PracticeScript`（`src/models/script.py`）= persona（家长人设，单值字段有数组兜底）+ objections（异议 2~4）+ opportunities（机会信号 1~4，总信号 3~7）+ 每个信号可挂 `mapped_factors`（对齐图谱 Factor.name）+ pre_brief（**只给背景不剧透异议**）+ success_criteria。详见 [[02-剧本生成与家长角色建模]]。

### 管线二：实时语音对练（WebSocket `/ws/practice/{session_id}` → `src/api/ws_practice.py`）

浏览器 AudioWorklet 采集麦克风 48kHz Float32 → 二进制帧发后端 → `float32_to_pcm16` + `resample_pcm16` 降到 16k → 送火山 `dialog` WS。火山下行 24kHz Float32 TTS 音频 → 转 PCM16 → 回浏览器播放。两个协程 `pump_browser_to_volc` / `pump_volc_to_browser` 全双工对拷。AI 家长的行为由 `build_system_role` 按难度（hard/medium/easy）拼出的 `system_role` 控制：难度决定家长释放机会信号的主动程度、异议的坚持强度。上下行 PCM **边到边写盘**（`sales.16k.pcm` / `parent.24k.pcm`），结束时合成**双声道** `audio.wav`（左=老师 右=家长）。火山协议是**自实现的私有二进制帧编解码**（`src/voice/volc_dialog.py`）。详见 [[01-实时语音全双工桥（火山 dialog 协议）]]。

### 管线三：图谱锚定评价（`src/pipeline/evaluator.py`）

对练结束后 `asyncio.to_thread` 跑评价：
- **v2（有 Neo4j 且检索到经验）**：`_collect_signals` 收集所有异议+机会 → `ThreadPoolExecutor` 并发 `retrieve_for_signal`（objection 走 `query_resolve`，opportunity 走 `query_advance`，图谱因素主查空则用信号 title/content 抽关键词兜底）→ `build_reference_block` 渲染成 prompt（跨信号去重同一 approach 防膨胀）→ LLM（deepseek-r1, temp 0.2, `prompts/evaluation_v2`）输出每信号 `handled/llm_score/evidence/top_methods/matched_approach_ids/gap/advice` → Python 层 `compute_rule_score`（用 `example_count` 加权命中率算 1~5）→ 与 `llm_score` **等权融合**（0.5/0.5）成最终 `score` → `rule_anchor_score` = 各有效 rule_score 均值 ×20（0~100）。
- **v1（降级）**：Neo4j 不可用 / 检索全空 / v2 抛异常 → 只跑老 prompt，仅产 `objection_resolution`，`rule_anchor_score=0`。

详见 [[03-图谱锚定评价与规则锚融合]]。

### 降级链（贯穿三管线的容错设计）

| 情形 | 处理 | 语义 |
|---|---|---|
| 缺 neo4j Python 驱动 | `app.py` lifespan 打 **ERROR** 日志 + 明确提示 pip install | 部署错误，v2 永久失效 |
| Neo4j 网络/认证临时不可用 | 打 **WARNING**，进降级模式 | 开发场景允许 |
| v2 运行异常 / 检索全空 / max_tokens 截断 | 回退 v1 | 功能降级 |
| LLM 输出被 max_tokens 截断 | `finish_reason=='length'` 直接 raise（不喂残缺 JSON） | 错误显性化 |

这套"按依赖性质区分严重度"的降级是本项目多次线上事故复盘的结晶（见 git log `38448c` / `2691dd7`），是 [[04-方法论·可迁移模式]] 的重点。

## 方法论 · 可迁移的做法

以下是从本项目提炼、可搬到别处的模式（详细证据在 [[04-方法论·可迁移模式]]）：

1. **LLM 主观分 + 规则客观锚双轨融合**：评价既要 LLM 的语义理解（`llm_score`），又要一个不随 LLM 漂移的客观基准（`rule_score`，用图谱 `example_count` 加权命中率）。等权融合，并把"和 Top 比"落成可追溯数字 `rule_anchor_score`。
2. **同一知识资产多消费者的读写生态**：蒸馏(写图谱)/策略(在线读生成)/对练(读做评价锚定)复用同一 Neo4j + `Neo4jReadClient` + `CatalogCache` + 受控词表 catalog + S0-S4 坐标系，避免知识重复建设。
3. **按依赖性质分级降级 + 静默故障显性化**：部署错 ERROR、临时不可用 WARNING、功能降级回退——最危险的是"静默降级"（服务表面正常但核心功能永久失效），要专门检测并升级日志级别。
4. **难度即 prompt 参数**：同一剧本三档难度只替换 `system_role` 里一段行为规则文本，控制 AI 家长的对抗强度，零额外代码/模型。
5. **端到端实时语音的工程手法**：边到边写盘防内存堆积、双声道分轨录音便于复盘、采样率转换 stride 快路径 + 线性插值兜底、自实现私有二进制协议 + websockets 双版本兼容。
6. **LLM 输出防御性解析**：单值字段的数组兜底、分数 clamp、`matched_approach_ids` 只保留候选集内的 id 防幻觉、截断检测。

## 关键概念与术语表

| 术语 | 含义 |
|---|---|
| **objection / 异议** | 家长对推进意向最具杀伤力的阻力点（价格贵、担心效果），id 形如 O1/O2 |
| **opportunity / 机会信号** | 家长自然释放的正向信号（主动询价、夸孩子），销售要识别并跟进，id 形如 P1/P2 |
| **signal / 信号** | objection 与 opportunity 的统称；评价以信号为单位 |
| **mapped_factors** | 信号挂载的图谱 Factor.name（负向因素给异议、正向给机会），用于图谱检索对齐 |
| **Factor / Approach / Experience** | Neo4j 图谱三类节点：因素 / 方法 / 经验；`Experience-[:EVIDENCE_OF]->Approach` |
| **example_count** | 某 Approach 被多少条真实经验支撑，作为"Top 程度"的权重 |
| **rule_score / llm_score / score** | 单信号的规则锚分 / LLM 对照分 / 二者等权融合分（均 1~5） |
| **rule_anchor_score** | 全场各信号有效 rule_score 均值 ×20（0~100），"达到 Top 经验的百分之几" |
| **blocker_resolve / intent_advance** | Experience 的 experience_type：化解阻碍 / 推进意向；决定检索走 resolve 还是 advance |
| **catalog** | 图谱的受控词表 {factors, topics}，`CatalogCache` 缓存 TTL 600s，约束剧本生成用词 |
| **pre_brief** | 对练前给销售的背景简介 + 考核要点，**不含异议内容**（不剧透） |
| **system_role / hello_text** | 注入火山 dialog 的家长角色设定文本 / 家长开场第一句 |
| **difficulty** | easy/medium/hard，控制 AI 家长释放机会信号与坚持异议的强度 |
| **did_close** | 销售是否推进到"报名/缴费/约时间"闭环 |
| **S0-S4** | 意向阶段坐标系，与蒸馏/策略服务共享 |

## 上手 / 使用路径

**开发者跑起来**（README 快速启动）：
```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt      # 必须装齐含 neo4j，漏装会永久降级 v1
cp config.ini.example config.ini     # 填 MySQL / LLM / Volcengine / Neo4j 凭据
python -m src.app                    # 或 uvicorn src.app:app --port 8088
```
启动后 `logs/coach.log` 应见 `Neo4j 已连接，catalog 预热已下发`；出现 `Neo4j Python 驱动未安装` ERROR 说明会永久走 v1。浏览器开 `http://localhost:8088`（非 localhost 必须 HTTPS，因浏览器麦克风限制）。

**读代码的建议顺序**：
1. `src/app.py`（lifespan：图谱初始化 + 降级链 + 路由装配）
2. `src/api/sessions.py` + `src/pipeline/script_generator.py`（剧本怎么来）→ [[02-剧本生成与家长角色建模]]
3. `src/api/ws_practice.py` + `src/voice/*`（语音怎么跑）→ [[01-实时语音全双工桥（火山 dialog 协议）]]
4. `src/pipeline/evaluator.py` + `src/graph/*`（怎么评价）→ [[03-图谱锚定评价与规则锚融合]]

**纯跑通不依赖外部**：用【自定义模板】1~2 条异议即可，不碰 MySQL / Neo4j。
