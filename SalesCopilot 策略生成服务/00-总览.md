## 一句话是什么

SalesCopilot-Strategy 是一个**销售策略在线生成服务**：销售在给某个家长回访/电访前，用 `(user_id, counselor_id, moment)` 点一下"生成策略"，服务自动拉出这个用户截至该时刻的全部对话、补上他的订单背景，用 LLM 判断其购买意向阶段（S0-S4）与话题/因素，再去 Neo4j 经验图谱里检索"这种情境下历史上有效的方法"，最后用重量级 LLM 生成一张结构化 + markdown 双输出的**策略卡片**（当前阶段、推进目标、2-4 条带优先级的行动、话题推进顺序、备选方案、证据引用）。

## 场景叙事与价值

**问题**：经验蒸馏服务已经把「什么情境下用什么方法有效」沉淀成了 Neo4j 图谱，但这份知识是**离线的、给分析用的**。一线销售面对一个具体家长时，没法自己去查图谱——他需要的是"**就这个用户、现在、我下一步该聊什么怎么聊**"的直接答案。

**这个服务把图谱知识"落到具体人身上"**：它是图谱与一线销售之间的翻译层。图谱里存的是抽象经验（"S2→S3 阶段化解时间冲突：先肯定再给 2-3 个方案"），服务把它和"这个家长现在正卡在 S2、有时间冲突顾虑"对上，产出针对性的行动建议。

**典型用法**：销售在首课电访前 5 分钟，对每个待联系用户点"生成策略"，10-30s 拿到沟通方向、行动序列、应对预案。产品理念是**给策略不给逐字话术**——它是策略顾问，不是话术生成器（prompt 里反复强调）。

**没有它 vs 有了它**：

| 维度 | 没有它（销售凭经验 / 图谱只能离线查） | 有了它 |
|---|---|---|
| 意向判断 | 销售主观感觉 | LLM 按受控词表推导 S0-S4，附原文证据 |
| 经验调用 | 记不住、查不到历史成功打法 | 按当前阶段 + 因素自动检索图谱 Top-8 经验 |
| 用户背景 | 靠翻记录 | 自动拉当前单 + 上一单 + 历史对话 LLM 摘要 |
| 产出 | 无 | 结构化策略卡片 + 可渲染 markdown + 证据引用 |
| 可回溯 | 无 | 每条行动引用 approach_id，debug_meta 记录延迟/模型/命中数 |

## 核心功能逻辑

**一条五阶段同步管线**，由 `pipeline/orchestrator.py` 的 `Orchestrator.run()` 串起，每阶段独立计时（详见 [[01-五阶段在线管线与容错]]）：

```
POST /strategy {user_id, counselor_id, moment}
  │
[Stage 1 Fetch]    hetao API 拉 call+wechat 对话 → 归一 Asia/Shanghai → 按 moment 截断 → fulltext
  │                └ msg_count==0：不报错，直接置意向=S1、跳过 Stage3（降级）
[Stage 2 Profile]  拉当前单 + lag 上一单（MySQL/Hive）→ 补问卷 + 通话对话 → 过往单再过 LLM 摘要
  │                └ 可被 skip_user_profile=true 跳过；任何异常降级为 {}
[Stage 3 Intent]   轻量 LLM（qwen-plus）+ 注入图谱 catalog 快照 → 判 S0-S4 + 话题×因素 + 正/负因素
  │                └ 非法 stage 回退 S2；标签严格过滤到 catalog 内
[Stage 4 Graph]    advance + resolve 两类 Cypher 并行 → 按 approach_id 去重(advance 优先) → example_count Top-8
  │                └ S4 跳过 advance；无负因素跳过 resolve；都空则经验列表为 []
[Stage 5 Strategy] 重量 LLM（deepseek-r1）+ 经验 + 对话 + 背景 → StrategyCard(含 markdown) + evidence_references
  │
返回 5 顶层字段；（旁路）异步写 MySQL 结果表，不阻塞响应
```

- **输入→输出主链**：`(user_id, counselor_id, moment)` → 对话全文 + 用户背景 → 意向分析(S0-S4) → Top-K 图谱经验 → 策略卡片 JSON + markdown。
- **意向阶段 S0-S4**：贯穿全程的坐标系，与蒸馏服务同一套（S0 暂缓/流失 → S4 强购买意愿）。Stage 3 判当前阶段，Stage 4 用它选经验（`from_stage = 当前阶段`），Stage 5 用它定推进目标。见 [[03-图谱检索·数据契约·Prompt]]。
- **三处 LLM、一份词表**：意向分析、历史对话摘要、策略生成三处调用 LLM，前两处都被同一份 Neo4j catalog（话题/因素全集）约束用词，程序端再逐字段过滤——这是保证跨用户、跨时间标签口径一致的关键（方法论见 [[04-方法论·可迁移模式]]）。
- **三种入口同一编排**：在线 `POST /strategy`、一次性脚本 `run_strategy_persist_once.py`、批量脚本 `batch_strategy_from_mid_table.py` 都走同一个 `build_orchestrator()`。

## 方法论 · 可迁移的做法

这个项目最值得学的，是**如何把一份离线沉淀的知识图谱，包装成一个"对着具体实体实时出决策"的在线服务**，以及在一条多处调用 LLM 的在线链路里怎么控成本、控一致性、控失败。核心套路（展开见 [[04-方法论·可迁移模式]]）：

1. **一份受控词表约束全部 LLM 用词**：每次从 Neo4j 读话题/因素快照注入 prompt，程序端再逐字段过滤掉词表外的标签——LLM 产内容、词表保证可检索一致，与蒸馏服务一脉相承。
2. **分阶段异构 LLM**：延迟敏感的意向/摘要用轻量模型（qwen-plus），质量敏感的策略生成用重量推理模型（deepseek-r1），缺字段自动回退 `[llm.default]`——按环节的成本/质量诉求分别配置。
3. **"失败即失败"与"优雅降级"按依赖性质混用**：外部硬依赖失败（hetao/Neo4j/LLM 异常）直接抛错映射 HTTP 码，不造伪产物；但"对话为空/图谱无命中/背景拉取异常"是可容忍的信息缺失，降级继续并记 `warnings`。
4. **LLM 只产语义，程序做校验兜底**：非法意向阶段回退 S2、非法 confidence 回退 medium、topic_flow 兼容 list/string、多层 JSON 防御解析（去围栏 + raw_decode 容忍尾部噪声）。
5. **旁路异步落库 + 进程内共享**：结果用 `asyncio.create_task` 异步写库，落库失败不影响主响应；catalog 缓存与 Neo4j driver 是进程内单例，故约束 `workers=1`，横向扩展靠多实例 + 反代。

## 关键概念与术语表

| 术语 | 含义 |
|---|---|
| 意向阶段 (IntentStage, S0-S4) | 用户购买意向 5 级有序状态机：S0 暂缓/流失、S1 沉默、S2 需求模糊、S3 需求明确、S4 强购买意愿。**由话题×因素推导**，非独立打标 |
| 话题 (Topic) | 对话在聊什么（学习情况、价格费用、时间安排…）；取值以 Neo4j `Topic` 节点 catalog 为准 |
| 因素 (Factor) | 话题下的积极/消极信号，带极性 polarity（如"价格敏感"负、"学习兴趣"正）；取值以 `Factor` 节点 catalog 为准 |
| catalog 快照 | 每任务从 Neo4j 读一次的全局话题/因素全集，注入三处 LLM prompt 约束用词；进程内 TTL 600s 缓存 |
| Experience / Approach | 图谱节点：Approach 是归一化的销售方法（`APR-####`，带 `example_count`），Experience 是佐证它的具体经验（带 `from_stage→to_stage`、`factors_addressed`、三段式话术证据），关系 `(Experience)-[:EVIDENCE_OF]->(Approach)` |
| advance / resolve 查询 | Stage 4 两类检索：advance 找"推进意向"经验（intent_advance/pacing/context_leverage），resolve 找"化解阻塞"经验（blocker_resolve） |
| 策略卡片 (StrategyCard) | 最终产物：current/target_stage、confidence、user_summary、key_insight、actions[]、topic_flow、fallback、markdown |
| moment | 请求入参，ISO8601 带时区的"截至时刻"；只考虑此刻之前的消息（对话按此截断） |
| skip_user_profile | 请求可选布尔；true 时跳过 Stage 2，`{user_profile}` 置空对象（调试/加速用） |

## 上手 / 使用路径

- **入口**：`src/main.py`（FastAPI app + lifespan：装配 Neo4j/catalog/orchestrator，按配置挂载结果看板）。
- **跑起来**：`python3 -m venv .venv && pip install -r requirements.txt` → `cp config.ini.example config.ini` 填 `[hetao_data]/[neo4j]/[llm.*]`（落库/看板还需 `[mysql]` 或 `[hive]`）→ `python src/main.py`（默认 `0.0.0.0:8100`）。
- **最小用法**：`POST /strategy` 传 `{user_id, counselor_id, moment}`，拿回策略卡片；`GET /healthz` 存活探针；`GET /catalog?refresh=true` 看/刷图谱词表；`GET /results` 结果看板。
- **批量/离线**：`scripts/batch_strategy_from_mid_table.py` 从订单宽表拉用户列表逐条跑并落库；`run_strategy_persist_once.py` 单条跑一次入库。
- **环境要求**：Python 3.12、Neo4j（必需）；MySQL/Hive（落库 + 看板 + Stage2 订单宽表）；网络可达 hetao 对话 API 与 LLM 网关。生产用 `uvicorn src.main:app --workers 1`。
- 详见 [[01-五阶段在线管线与容错]] 的「配置与运行」。
