# 架构与部署

> 子笔记，回链 [[00-总览]]。

## 三层架构

```
用户侧（Claude Code / Codex / openclaw 客户端）
  htba-team 插件壳（薄壳 loader）
    ├─ SessionStart hook：拉角色包 + 拉全局 data-collector + 注入 system_prompt/preferences
    ├─ PreToolUse hook：保护 preferences.md / token / cache（仅 data-collector 放行）
    ├─ MCP 配置：指向网关，请求头携带 Bearer token
    └─ ~/.htba-team/：token · cache/<role>.json · preferences.md
        │ HTTPS + Authorization: Bearer <token>
        ▼
MCP 网关（核心，单一数据出口）—— gateway/server.py
    工具：19 个 MCP tool（见 [[02-MCP网关与SQL安全]]）
    横切：Token 鉴权 · 表/列 ACL · SQL AST 白名单 · 限流 · 脱敏 · 审计
    Transport：REST POST /mcp/v1/{tool} + MCP JSON-RPC POST /mcp/v1（共享同一 registry）
    另有对外 /api/v1（数据应用通道，enabled 才挂载）
        │ read_only 单文件          │ 读写
        ▼                           ▼
   业务 DuckDB（本地单文件）    平台 MySQL（schema=htba_team）
                               tokens/role_packs/acl/feedback/audit/proposals...
                                        ▲
运营后台（FastAPI + 内嵌 Vue3 SPA，同进程同端口 admin/server.py:8090）
    Token · 表元数据 · 内容仓库 · 角色包编排 · 全局 Agent · 反馈池 · 素材池 · 内容提案 · 审计 · RBAC
```

## 两类数据源（关键取舍）

| | 业务库 | 平台库 |
|---|---|---|
| 引擎 | DuckDB **单文件** | MySQL 8.0+（云端） |
| 打开方式 | gateway 以 `read_only=True` 持有，无账号密码，部署机直接挂载 `.duckdb` | `aiomysql` + SQLAlchemy async |
| 存什么 | 业务明细/事实表 | token / role_pack / 反馈 / 审计 / 提案等元数据 |
| 注意 | 单文件锁：外部系统**不要**再以 read-write 直连同一份文件 | schema 名 `htba_team` |

设计取舍：业务数据本地只读单文件 → 零 DB 凭证下发、天然只读、部署简单；平台元数据放云端 MySQL → 多实例共享、事务能力。

## 进程与部署形态

- **两个独立进程**：gateway（:8089，`htba_team.gateway.server:app`）+ admin（:8090，`htba_team.admin.server:app`），`pyproject.toml [project.scripts]` 声明 `htba-gateway` / `htba-admin` 入口。
- **裸机 + systemd**：`deploy/systemd/htba-gateway.service` / `htba-admin.service`，默认 `User=root` + `WorkingDirectory=/opt/htba-team`；配置与代码同目录（`deploy/config/config.ini`，gitignore 兜底），服务从 CWD 自动发现，无需 `HTBA_CONFIG`。
- **前端内嵌**：Vue3 SPA 构建产物 `web/dist/` 由 admin 进程 `StaticFiles` 挂载，`/admin/assets` 提供资源，`/admin` 与 `/admin/{path}` fallback 到 `index.html`；API 路由先注册故不被 SPA fallback 抢占（`admin/server.py:137-151`）。
- **反代子路径**：`_PublicPrefixStripMiddleware` 支持反代以子路径透传时剥前缀（`admin/server.py:59-82`）；对外通常 nginx/LB 反代 8089/8090，TLS 前置层终结。
- **配置格式**：INI（`*.secret.ini` 被 gitignore）。

## 运维脚本

- `scripts/server_bootstrap.sh`：幂等 bootstrap——构建前端 SPA → 创建 `.venv` → `uv pip install -e .`；开关 `--with-migrate` / `--with-plugins` / `--skip-frontend`；已存在的 `.venv`/`dist/` 复用，不覆盖 config、不动 systemd。
- `scripts/rollout.sh`：一键滚动升级串「git pull → bootstrap(--with-migrate --with-plugins) → 重启双进程 → 双端健康检查」；失败自动打印回滚 commit；开关 `--skip-frontend` / `--no-migrate` / `--no-plugins` / `--no-pull` 透传给 bootstrap。
- `scripts/build_plugin_release.sh all <version>`：为 claude-code / codex / openclaw / skill-htba-team-operate 四目标产出 `*-latest.tar.gz` + 版本化 tar + `plugin-version.json`（含 sha256）；openclaw 端需 `pnpm build` 产 `dist/index.mjs`。产物写 `static/download/`。
- 健康检查：`GET /healthz`（gateway/admin 皆有，admin 还有 `/admin/healthz`）。

## 关键设计决策（PRD §4.1）

- 客户端内部分发（公司私有 marketplace），不做用户身份系统（只有 token + user_label）。
- Token 化授权：一用户一 token，可绑多角色包，OA 外部审批 + 运营手工录单。
- MCP 网关代执行所有业务库 SQL，客户端无 DB 凭证或文件访问。
- 单插件壳 + 服务端动态返回角色包；个人习惯文件本地常驻，与角色包物理分离。
- 启动时自动拉最新角色包；版本切换/定向指派由后台控制（pin）。
- 采集做成本地 Agent（用户控制 + 本地脱敏 + 智能摘要），后全局化为 SystemAgent。
- 表元数据由 schema 反射 + 运营补字段；内容以 references 三件套固化。
- 工作流独立资产化（`htba_team_workflows` 表），与 metric/method/sql_template 同构。

## 明确不在范围（PRD §2.2）

不做 OA 对接、不做用户身份系统、不做可视化报表渲染（结果以表格返回，可视化交给用户自有 BI）、不做权限申请自助化（走 OA）、不做飞书/钉钉 IM 集成（注：后台登录后来接了飞书 OAuth，属后续演进）。
