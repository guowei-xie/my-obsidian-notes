## 1. 客户端：插件薄壳

### 1.1 目录结构

```
<插件名>/
├── plugin.json
├── .claude-plugin/marketplace.json
├── hooks/
│   ├── session-start.sh      # 拉角色包 + 注入 preferences
│   └── stop.sh               # 触发 data-collector agent
├── mcp/
│   └── server-config.json    # 指向网关，请求头注入 token
├── commands/
│   ├── token-set.md          # /<插件名> token set <token>
│   ├── prefs-edit.md         # /<插件名> prefs edit
│   └── doctor.md             # 自检（token 是否有效、网关可达、缓存状态）
└── README.md
```

### 1.2 设计原则

- **薄壳**：插件代码不含任何业务知识、SQL、口径——这些**全部**来自网关
- **本地状态最小化**：本地只持有
  1. `~/.<插件名>/token`（权限 600）
  2. `~/.<插件名>/cache/role_pack.json`（offline fallback）
  3. `~/.<插件名>/preferences.md`（用户个人习惯，永不被覆盖）
- **会话级装载**：每次启动把角色包写到 `<project>/.claude/skills/` 与 `.claude/agents/`，覆盖更新只影响下次会话

### 1.3 关键 Hook

**SessionStart**（伪代码）：
```bash
TOKEN=$(cat ~/.<插件名>/token)
RESP=$(curl -fsS -H "Authorization: Bearer $TOKEN" \
  "$GATEWAY/role_pack?local_version=$LOCAL_VER")

# 200: 新版本，写入会话目录并更新本地缓存
# 304: 已是最新，使用本地缓存
# 401/403: 提示用户检查 token / 联系运营

write_skills_to .claude/skills/<role>/
write_agents_to .claude/agents/data-collector.md

# 注入个人习惯
PREFS=$(cat ~/.<插件名>/preferences.md 2>/dev/null || echo "")
inject_to_session_system_prompt "$PREFS"
```

**Stop**：
```bash
# 仅当本轮调用过本插件的 MCP 工具时才触发
if recent_session_used_mcp; then
  run_agent data-collector --transcript=$TRANSCRIPT
fi
```

## 2. 个人习惯文件 `preferences.md`

> 本设计的核心，用以解决"角色包覆盖更新会丢失个人沉淀"的问题。

### 2.1 位置与生命周期

- 路径：`~/.<插件名>/preferences.md`
- **永不被本系统的任何流程覆盖或删除**
- 与角色包**物理分离**：角色包写到会话级 `.claude/skills/`，preferences 始终在用户家目录

### 2.2 内容模板（首次安装由插件生成）

```markdown
# 我的使用偏好

## 默认口径
- 例：「新用户」按"注册当天首单完成"

## 常用维度
- 例：渠道分析默认按 source_id

## 我的提问习惯
- 例：我喜欢先看趋势再看明细

## 不要做的事
- 例：不要主动给结论建议，我自己判断
```

### 2.3 注入机制

SessionStart hook 读到文件内容后，作为 system prompt 的一段拼到会话上下文中（在角色包的 system_prompt 之后，确保个人偏好覆盖默认行为）。

### 2.4 双通道写入

1. **用户手编**：`/<插件名> prefs edit` 用默认编辑器打开
2. **Agent 建议追加**：data-collector 发现稳定使用模式时（连续 N 次同样的口径选择/维度选择），征得用户同意后**追加**到对应段落（不删除既有内容）

## 3. MCP 网关

### 3.1 技术栈与部署

- Python + FastAPI + `mcp` SDK
- 部署在公司内网，**所有客户端的唯一 MySQL 出口**
- 业务 MySQL：只读账号；平台 MySQL：读写账号，与业务库可同实例不同 schema

### 3.2 工具清单

| 工具 | 入参 | 出参 | 权限校验 |
|------|------|------|----------|
| `list_role_packs` | - | 该 token 已绑定的角色包清单（code/name/current_version） | Token 有效 |
| `get_role_pack` | `role_code, local_version?` | role pack JSON 或 304 | Token 必须已绑定该 role_code |
| `list_tables` | `role_code` | 该角色可见表清单（带描述） | Token + role_code 在绑定列表内 |
| `describe_table` | `role_code, table` | 字段、口径、样例值 | 该表必须在该角色 ACL 内 |
| `run_template_sql` | `role_code, template_id, params` | 结果集 | 模板必须在该角色资产清单 |
| `run_query` | `role_code, sql` | 结果集 | AST 校验该角色表/列白名单 |
| `submit_feedback` | `role_code, payload` | ack | Token 有效 |
| `update_preferences_hint` | `text` | 仅返回建议字符串供客户端落盘（不在服务端落） | Token 有效 |

> 所有数据类工具都需要显式传 `role_code`：网关用它去取对应角色的 ACL，避免"混角色"调用。客户端在 SessionStart 选定角色后，把 `role_code` 注入到所有 MCP 工具调用参数中（通过 MCP server 的 default args 或 wrapper）。

### 3.3 Token 验证

```
请求 → Authorization: Bearer <token>
  ↓
SHA256(token) → 查 tokens 表
  ↓
检查 status=active 且 expires_at > now()
  ↓
取该 token 绑定的角色包集合（token_role_packs）
  ↓
对本次请求的 role_code 做归属校验：必须在绑定集合内
  ↓
取该 role_code 的 ACL 注入到本次请求上下文
```

失败码：
- `401`：token 不存在或已吊销 → 客户端提示"请到 OA 重新获取"
- `403`：token 有效但越权 → 审计后拒绝

### 3.4 SQL 安全（AST 白名单）

```python
import sqlglot

def validate_sql(sql, role_acl):
    tree = sqlglot.parse_one(sql, dialect="mysql")

    # 1. 只允许 SELECT
    if not isinstance(tree, exp.Select):
        raise Forbidden("only SELECT allowed")

    # 2. 提取所有引用的表与列
    refs_tables = {t.name for t in tree.find_all(exp.Table)}
    refs_columns = {(c.table, c.name) for c in tree.find_all(exp.Column)}

    # 3. 与 ACL 求交集
    for t in refs_tables:
        if t not in role_acl.allowed_tables:
            raise Forbidden(f"table {t} not allowed")
        for col_table, col_name in refs_columns:
            if (col_table == t or col_table == "") and \
               col_name not in role_acl.allowed_columns[t]:
                raise Forbidden(f"column {t}.{col_name} not allowed")

    # 4. 行级过滤注入（如有 row_filter_sql）
    sql = inject_row_filters(tree, role_acl)

    # 5. 强制 LIMIT、禁用 INFORMATION_SCHEMA、禁用多语句
    sql = enforce_limit(sql, default=1000)
    return sql
```

### 3.5 审计

每次工具调用入 `audit_log`：

```
token_hash · role_pack_id · tool · payload_hash · tables[] · ok · latency_ms · ts
```

- `payload_hash`：SHA256(SQL) 或 SHA256(template_id+params) — 避免明文 SQL 大量入库
- `tables`：本次调用涉及的表名列表

## 4. Token 模型

### 4.1 一用户一 Token，可绑定多个角色包

- **每个用户全局只有一个 token**（终身唯一，到期换发后仍是"一个"）
- 一个 token 在后台可绑定 **N 个角色包**（N≥1）
- token 持有者在客户端可任选已绑定的角色包使用
- 跨角色的人无需多 token：后台勾上对应角色包即可

### 4.2 生命周期

```
OA 提单（用户首次申请：写明所需角色）
   ↓
OA 审批通过
   ↓
运营后台：
  - 用户已有 token？→ 在该 token 上勾选追加角色包
  - 用户无 token？  → 新建 token，绑定本次审批的角色包
   ↓
新增角色包：token 字符串无需变（用户无感）
新建 token：token 字符串通过 OA 工单或 IM 发回，仅展示一次
   ↓
用户 /<插件名> token set <token>（首次）
       /<插件名> role use <code>（每次选择本会话角色）
   ↓
token 有效期内可用；可在后台一键吊销；到期自动 expire
```

### 4.3 Token 字符串

- 随机 32 字节 → base64url 编码（约 43 字符）
- **入库只存 SHA256(token)**，明文只在生成时返回一次
- 建议有效期 90 天，到期前 7 天客户端开始提醒

### 4.4 客户端角色选择

新增命令：

| 命令 | 用途 |
|------|------|
| `/<插件名> role list` | 列出当前 token 可用的角色包 |
| `/<插件名> role use <code>` | 选定本会话使用的角色包（写入本地状态文件） |
| `/<插件名> role current` | 查看当前已选角色 |

本地状态：`~/.<插件名>/active_role`（仅一行，存当前选定的 `role_code`）

SessionStart hook 行为：
1. 读取 `active_role`
   - 已设置：调 `get_role_pack(role_code=active_role)` 拉取并注入
   - 未设置 + token 仅绑定 1 个角色包：自动选定该角色
   - 未设置 + token 绑定多个：在 system 上下文中提示用户运行 `role use`，本会话不装载任何角色
2. 个人 `preferences.md` 不受角色选择影响，始终注入

## 5. 平台数据模型（MySQL）

> 单独一个 schema `bizanalyst_meta`，与业务 MySQL 物理可分可合（M0 阶段可同实例）。

```sql
-- 1. 平台账户与授权（一用户一 token）
CREATE TABLE tokens (
  id           BIGINT PRIMARY KEY AUTO_INCREMENT,
  token_hash   CHAR(64) NOT NULL UNIQUE,
  user_label   VARCHAR(64) NOT NULL UNIQUE,  -- OA 单号或工号；同一用户唯一
  expires_at   DATETIME NOT NULL,
  status       ENUM('active','revoked','expired') DEFAULT 'active',
  oa_ref       VARCHAR(64),
  created_at   DATETIME DEFAULT CURRENT_TIMESTAMP,
  revoked_at   DATETIME NULL,
  INDEX(status), INDEX(expires_at)
);

-- Token 与角色包的多对多绑定
CREATE TABLE token_role_packs (
  token_id     BIGINT NOT NULL,
  role_pack_id BIGINT NOT NULL,
  granted_at   DATETIME DEFAULT CURRENT_TIMESTAMP,
  granted_by   VARCHAR(64),
  oa_ref       VARCHAR(64),                -- 本次授权对应的 OA 单号
  PRIMARY KEY (token_id, role_pack_id),
  INDEX(role_pack_id)
);

-- 2. 角色包与版本
CREATE TABLE role_packs (
  id              BIGINT PRIMARY KEY AUTO_INCREMENT,
  code            VARCHAR(64) UNIQUE NOT NULL,
  name            VARCHAR(128) NOT NULL,
  current_version VARCHAR(32),
  status          ENUM('draft','active','archived') DEFAULT 'draft'
);

CREATE TABLE role_pack_versions (
  id              BIGINT PRIMARY KEY AUTO_INCREMENT,
  role_pack_id    BIGINT NOT NULL,
  version         VARCHAR(32) NOT NULL,
  manifest_json   JSON NOT NULL,
  checksum        CHAR(64) NOT NULL,
  status          ENUM('draft','gray','released','rolled_back') DEFAULT 'draft',
  released_at     DATETIME NULL,
  gray_rule_json  JSON NULL,                -- 如 {"token_whitelist": [...]} 或 {"ratio": 0.2}
  UNIQUE KEY (role_pack_id, version)
);

-- 3. 内容资产
CREATE TABLE sql_templates (
  id           BIGINT PRIMARY KEY AUTO_INCREMENT,
  code         VARCHAR(64) NOT NULL,
  name         VARCHAR(128) NOT NULL,
  sql          MEDIUMTEXT NOT NULL,
  params_schema JSON,
  owner        VARCHAR(64),
  version      VARCHAR(32),
  status       ENUM('draft','active','archived') DEFAULT 'draft',
  UNIQUE KEY (code, version)
);

CREATE TABLE metric_defs (
  id         BIGINT PRIMARY KEY AUTO_INCREMENT,
  code       VARCHAR(64) NOT NULL,
  name       VARCHAR(128) NOT NULL,
  definition TEXT NOT NULL,
  unit       VARCHAR(32),                     -- 单位（"元"/"人"/"%" 等）
  drilldown_dims JSON,                        -- 可下钻维度
  version    VARCHAR(32),
  status     VARCHAR(16),
  UNIQUE KEY (code, version)
);

-- 方法定义（references 三件套之一）：时间窗、显著性、归因方法、异常阈值等
CREATE TABLE method_defs (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  code        VARCHAR(64) NOT NULL,
  name        VARCHAR(128) NOT NULL,
  description TEXT NOT NULL,
  version     VARCHAR(32),
  status      ENUM('draft','active','archived') DEFAULT 'draft',
  UNIQUE KEY (code, version)
);

-- 4. 表元数据（由 schema 反射初始化）
CREATE TABLE tables_meta (
  name          VARCHAR(128) PRIMARY KEY,
  schema_name   VARCHAR(64),
  columns_json  JSON NOT NULL,
  owner         VARCHAR(64),
  sensitivity   ENUM('public','internal','sensitive') DEFAULT 'internal',
  description   TEXT,
  last_synced_at DATETIME
);

-- 5. 权限与绑定
CREATE TABLE table_acl (
  role_pack_id     BIGINT NOT NULL,
  table_name       VARCHAR(128) NOT NULL,
  allowed_columns  JSON NOT NULL,          -- ["col1","col2"] 或 ["*"]
  row_filter_sql   TEXT NULL,
  PRIMARY KEY (role_pack_id, table_name)
);

CREATE TABLE role_assets (
  role_pack_id BIGINT NOT NULL,
  asset_type   ENUM('skill','sql_template','metric','method','report') NOT NULL,
  asset_id     BIGINT NOT NULL,
  version      VARCHAR(32),
  PRIMARY KEY (role_pack_id, asset_type, asset_id)
);

-- 6. 反馈与审计
-- 反馈：data-collector 产出的结构化候选变更包（详见 02-内容与迭代 §2）
CREATE TABLE feedback (
  id              BIGINT PRIMARY KEY AUTO_INCREMENT,
  token_hash      CHAR(64),
  role_pack_id    BIGINT,
  batch_id        VARCHAR(64),                  -- data-collector 产出批次 ID
  candidates_json JSON NOT NULL,                -- candidate_changes[]（带 diff）
  status          ENUM('new','triaged','accepted','rejected') DEFAULT 'new',
  assignee        VARCHAR(64),
  created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
  INDEX(status), INDEX(created_at), INDEX(batch_id)
);

CREATE TABLE audit_log (
  id           BIGINT PRIMARY KEY AUTO_INCREMENT,
  token_hash   CHAR(64),
  role_pack_id BIGINT,
  tool         VARCHAR(64),
  payload_hash CHAR(64),
  tables       JSON,
  ok           TINYINT,
  latency_ms   INT,
  ts           DATETIME DEFAULT CURRENT_TIMESTAMP,
  INDEX(ts), INDEX(token_hash)
);
```

> 隐私：**不存用户身份明文**，只存 `token_hash` 与 `user_label`（OA 单号/工号）。

## 6. 安全风险与对策

| 风险 | 对策 |
|------|------|
| SQL 注入 / 越权 | sqlglot AST 解析白名单；只读账号；强制 LIMIT；禁多语句 |
| Token 泄漏 | 入库存 hash；后台一键吊销；建议 90 天有效期；客户端文件 600 权限 |
| 本地缓存被翻 | 缓存只放会话级目录与用户家目录；preferences 是用户自己的内容；不缓存敏感结果集 |
| 网关单点 | 双活部署；客户端 offline fallback（用本地旧角色包） |
| 数据出域 | 审计中心可查询所有调用；敏感表标记 `sensitivity=sensitive` 时强制列脱敏 |
