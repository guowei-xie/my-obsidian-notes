# 方法论 · Harness 与可迁移模式

> 本篇是这份萃取的灵魂。拿掉「销售对话」「中文语料」两个具体前提后，Deka 教会了什么、哪些套路能搬到别处。主源 whitepaper §2、§5、Conclusion。

## 核心命题：Agent = Model + Harness

> *When the model is unreliable and the human is expensive, the leverage is in the harness between them.*（whitepaper Conclusion）

大模型供推理，但**推理本身不是系统**——放任不管它会漂移、编造、忘记试过什么、悄悄回答另一个问题。Harness 是模型周围让推理变可靠的一切。Deka 的贡献不是新模型、不是新 embedding（两者都是现成的），而是**把通用模型 + 忙碌的领域专家编排成可靠检索调参仪器的那套 harness**。

这对做任何「用 LLM 干正事」的系统都是可迁移的底层视角：**先问「模型不可靠会怎样错」，再用 harness 一条条堵住**，而不是指望换更强的模型。

## Harness 的三个承重构件（Phase 1 loop）

whitepaper §2 把 loop 拆成三件承重的东西——这是一份可复用的「LLM harness 检查清单」：

| 构件 | 作用 | Deka 里的具体形态 |
|---|---|---|
| **Feedforward guides**（前馈约束） | 在动作*发生前*收窄空间：把 agent *能*做的收窄到*该*做的 | 每轮递交查询 + 锁死配置 + 硬约束（永不编造 chunk、永远引 chunk ID、永远记日志）→ 单次疏忽不能污染整个 session |
| **Feedback sensors**（反馈传感） | 动作*之后*报告发生了什么 | 两种信号：人的裁决（FIT/NOT_FIT/DISCARD，系统对齐的 ground truth）+ 机器自算的指标（P@K、per-path 贡献，agent 用来推理「为什么这轮这样」） |
| **Externalised state**（外化状态） | 把 session 记忆挪出模型 | 每轮 append 到磁盘 progress log（查询/配置/评分/反思）；模型从不记 session，它**读日志**→ 可续跑、可审计、可复现，且让 agent 能对整段历史而非最后一轮推理 |

## 两条稳住 loop 的纪律

1. **锁死配置（locked configuration）**：四个搜索参数第一轮开始即冻结。反思**不提议新参数值**，只产 observe→diagnose→hypothesise 的推理轨迹。中途改旋钮会 confound 操作者正在读的信号；唯一许可的中途变更是门控严格的 path drop。
   - *可迁移点*：当你要用人的反馈来 tune 一个系统时，**别让系统在人观察期间自己变**——否则你不知道效果变化来自旋钮还是来自数据。
2. **叙事优于指标（narrative over metrics）**：progress log 写成人可读散文，不是数字堆。因为没人能直读语料，累积的反思成了「从每个查询的角度看语料长什么样」的地图——一张指标表会丢掉的直觉。

## 五条贯穿全系统的设计原则（§5）

拿掉项目名仍能指导别的事，逐条给出「为什么」与「能搬到哪」：

1. **把人钉在判断、绝不钉在机制**（Keep the human on judgement, never on mechanics）。每一阶段人的输入都是关于*内容*的裁决（这条相关吗 / 这 rubric 读着对吗 / 这阈值可接受吗），从不是检索参数或数学。→ 这才让「有业务判断力、零检索背景」的产品负责人能开动系统。**可迁移**：任何 human-in-the-loop 系统，先划清「机制归机器、判断归人」这条线，并让 UI 只向人要判断。

2. **偏向精度，并把犯错代价显式写出来**（Prefer precision, make the cost of error explicit）。从 Harvest 的双锚点一致门到 Apply 的精度地板，系统一致压制 false positive——因为**错收污染下游一切，错漏以后能捞回**。Recall 被刻意当成更便宜的错误。**可迁移**：任何「产出会被下游消费」的管线，先判断两类错误哪个不可逆、哪个可补救，把不可逆的那类调到最严。

3. **一切外化、一切可复现**（Externalise everything, make it reproducible）。状态以叙事日志 + 带版本 artifact 存磁盘，不在模型 context。**rubric 盖生成它的 meta-prompt 的 SHA-256；分类器拒绝在 rubric 漂移后的数据上运行。**→ 每个 artifact 都能追到确切生成器，管线不会用旧规则跑新数据还不自知。**可迁移**：给每个自动生成的 artifact 打上「生成者指纹」，并让下游对指纹不匹配**硬失败**而非静默继续。

4. **可复现的推导，而非每次定制 prompt 工程**。Refine 的要害不是任何一份 rubric，而是**写 rubric 的 meta-prompt**——把「每个查询做一次 prompt 工程」变成「跑一遍固定 meta-prompt 就产出约定形状」。**可迁移**：当你发现自己在为每个 case 手搓 prompt，退一层去写「生成这些 prompt 的 prompt」，并固定输出 schema + 版本戳。

5. **逐级升级、代价接力**（严格前向、无回边）。四阶段是一条严格前向升级链，每阶段交给下一阶段一个更精炼的对象，各付一种不同的代价；没有任何从后往前的箭头，返工靠**重跑一个阶段**。人的判断只花在最前端，后面每步用几何/采样/点积把它逐级摊还。**可迁移**：把「昂贵的人工判断」当稀缺资源，设计一条链让每个后续步骤都在放大/复用前一步的判断，而不是重新索取判断。

## 一句话贯通的迁移模式

> tune 一个交互 loop 直到人的直觉被捕获为**校验过的例子** → 把例子**几何式扩张** → 把扩张**蒸馏成可读规则** → 把规则**降本成分类器**以求规模。

whitepaper §5 明说：这条弧**没有任何一处专属于销售转写或中文**。只要「某专家握着一个模糊概念，需要在一个大到读不完的语料里被*找到、达成共识、并铺开*」，这套就适用——**底座会变，harness 不会。**

## 边界：Deka 刻意不是什么（§5）

这些是刻意的范围选择、不是缺失功能，每一条都是为了**把人的判断而非某个指标留在 loop 中心**：

- **不是 RAG**——从不让模型基于 chunk 作答，只定位 + 标注。
- **不是全自动优化器**——agent 只提议并解释，每个有后果的步都要人确认。
- **一次只调一个查询**，不做查询间排序。
- **把 embedding 模型当固定输入**，不评估替代。

*可迁移的收尾判断*：明确写下「我这个系统**不做**什么」，往往和写清它做什么一样重要——它是保证「人的判断留在中心」这个设计意图不被功能蔓延冲淡的护栏。
