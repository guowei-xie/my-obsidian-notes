## 1. LLM 主观分 + 规则客观锚，双轨融合

**做法**：给一个"评价/评分"任务两条独立评分轨——LLM 负责语义理解（`llm_score`），一套确定性规则负责客观基准（`rule_score`），等权融合，并把客观轨单独暴露成一个可解释指标（`rule_anchor_score`，"达到 Top 的百分之几"）。

**本项目证据**：`evaluator.py:197-203` 融合 `0.5*llm + 0.5*rule`；`rule_score` 用图谱 `example_count` 加权命中率（`signal_retriever.py:164-180`），把"和 Top 销售比"变成有据可查的数字，而非 LLM 拍脑袋。`rule_score=0`（无数据）时回退纯 LLM 分——**规则轨缺数据不该拖累结论**。

**为什么值得搬**：任何"LLM 当裁判"的场景（内容质量分、代码评审分、答案打分）都受 LLM 打分漂移之苦。只要你有一份客观事实（历史命中率、测试通过率、检索覆盖率），就能造一条规则锚轨，既抗漂移又可解释。关键设计点：①用权重（example_count）区分"命中优质 vs 命中冷门"；②规则轨无数据时优雅退化而非归零。

**迁移边界**：需要有一份可信的客观基准数据；等权是本项目的选择，别处该按两轨可信度调权。

## 2. 按依赖性质分级降级，把"静默故障"显性化

**做法**：面对"外部依赖不可用"，不要一律 try/except 吞成一个 WARNING。按**故障性质**分级：部署错误（该修）用 ERROR 并给修复指令；临时不可用（可容忍）用 WARNING；功能降级走 fallback。最危险的是**静默降级**——服务表面正常但核心功能永久失效，必须专门检测并升级告警。

**本项目证据**（`app.py:62-72`，git `38448c`）：`ModuleNotFoundError`（缺 neo4j 驱动=部署错，v2 永久失效）→ ERROR + "请 pip install 后重启"；Neo4j 网络临时不可用 → WARNING（开发允许）；v2 运行异常/检索空 → 回退 v1。这个设计是线上事故复盘的产物：原来"缺驱动"和"网络抖动"共用一个 WARNING，运维不看日志就发现不了 `rule_anchor_score` 恒 0。

**为什么值得搬**：任何有可选依赖 / 降级路径的系统，都有"降级被静默吞掉"的盲区。分级的判据是"**这个错该由谁在什么时候修**"——部署期能修的要吵、运行期容忍的可以静。

## 3. 截断即失败，不把残缺产物喂给下游

**做法**：LLM/外部调用的产物在进入解析前先验证完整性，残缺就**在源头显式 raise**，而不是让它变形成下游一个面目全非的错误。

**本项目证据**（`openai_chat.py`，git `2691dd7`）：`finish_reason=='length'` 直接 raise 带 max_tokens 上下文，而非把被截断的 JSON 交给 `json.loads` 变成 `JSONDecodeError` 再静默回退 v1。配套：给足 max_tokens（3000→8000）+ prompt 里加硬性长度上限（`evaluation_v2/system.txt` 尾段约束 JSON ≤6000 字符、优先压缩非关键字段、禁止半截字符串）。

**为什么值得搬**：错误在传播链上越走越失真——`finish_reason` 是"被截断"的第一手信号，丢掉它，下游只能看到"JSON 解析失败"这种误导性症状。**在信息最完整处报错**。

## 4. 难度/模式即 prompt 参数，而非代码分支

**做法**：把"行为强度/风格"这类可枚举的变体，做成**注入 prompt 的一段文本模板**，而不是散落在代码里的 if-else 或多个模型。

**本项目证据**（`system_role_builder.py:12-32`）：hard/medium/easy 三档难度只是替换家长 `system_role` 尾部一段规则文本（异议坚持强度、机会信号释放主动性、报名门槛），主流程零分支、零额外模型。非法值兜底 medium。

**为什么值得搬**：LLM 应用里大量"变体"（语气、严格度、角色）本质是提示词差异。用数据（模板 dict）表达变体，比用控制流表达更易扩展、易 A/B、易让非工程同事改。

## 5. LLM 输出防御性解析：永远在模型边界兜底

**做法**：假设 LLM 会违反你的 schema，在解析入口做类型/范围/枚举兜底，而不是让脏数据流进业务逻辑。

**本项目证据**：`script.py:14-49` 的 `_first_or_none`（单值字段收到数组取首元素）、`child_age` 的"8岁"→8 / "未知"→None、`_clamp_int`（分数越界夹紧，`evaluator.py:286-291`）、`matched_approach_ids` 只保留候选集内 id 防幻觉（`evaluator.py:193-194`）、`_validate_script` 修复 id 冲突与非法 first_objection。

**为什么值得搬**：结构化输出（哪怕开了 JSON mode）仍会有单值/数组、类型、越界、幻觉 id 等偏差。把兜底集中在 Pydantic 校验器 + 一个 validate 函数里，业务层就能假设数据是干净的。

## 6. 私有二进制协议用能力探测做跨版本兼容

**做法**：依赖库跨大版本改了 API（参数名、行为），用 **try + 捕获特定错误 + 回退**做能力探测，而不是"部署机装哪个版本就硬编哪个"。

**本项目证据**（`volc_session.py:82-92`，git `d57c225`）：先试 `additional_headers=`（websockets 14+），`TypeError` 且信息含该参数名时回退 `extra_headers=`（13.x）。此前 `5b7e969` 为修部署机硬切一个，反把本地另一版本弄挂——单选硬编码在多环境下必然来回打架。

**为什么值得搬**：多环境（本地/CI/生产）依赖版本难统一时，能力探测比锁版本更鲁棒。判据要精确（匹配错误里的参数名），别用宽泛的 `except Exception` 掩盖真错误。

## 7. 端到端实时语音的工程细节清单

一组"做实时音频才会踩到"的小手法，值得作为 checklist（证据见 [[01-实时语音全双工桥（火山 dialog 协议）]]）：
- **边到边写盘**：长会话音频直接落盘不在内存累积（`ws_practice.py:107`）；
- **双声道分轨录音**：上下行分左右声道合成 WAV，复盘能分辨谁说话（`audio.py:merge_stereo`）；
- **采样率转换分快慢路径**：整数倍走 stride、非整数倍走线性插值（`audio.py:resample_pcm16`）；
- **格式转换点要标清**：下行 Float32、存盘要 int16、回浏览器不转——每个转换点都是潜在 bug（`ws_practice.py:233`）；
- **双协程 + 单 stop_event 协调全双工收尾**，finally 里 finish→cancel→关文件顺序固定。

## 8. 同一知识资产的多消费者读写生态

**做法**：一份核心知识资产（这里是 Neo4j 经验图谱）由多个服务按"写/读"角色分工消费，共享 client、缓存、词表、坐标系，避免每个服务各建一套。

**本项目证据**：蒸馏服务**写**图谱 → [[SalesCopilot 策略生成服务/00-总览|策略服务]]**在线读**生成策略 → 本系统**读**做评价锚定。三者共享 `Neo4jReadClient`（`neo4j_client.py` 顶注"复用自 Strategy"）、`CatalogCache`、受控词表 catalog、S0-S4 坐标系。同一份"什么方法有效"被三种用途复用。

**为什么值得搬**：当一份知识/数据有多种下游用途时，与其每个下游各自 ETL、各建 schema，不如把它当作共享资产，读写分离、client/词表下沉为公共库。代价是耦合 schema——变更要协调多方。
