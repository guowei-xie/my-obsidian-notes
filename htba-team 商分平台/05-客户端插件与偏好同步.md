# 客户端插件与偏好同步

> 子笔记，回链 [[00-总览]]。设计信条：**薄壳**——插件代码不含任何业务知识/SQL/口径，能力全部服务端动态下发。

## 三端目标

`plugins/README.md` 声明三个已实现目标：**claude-code / codex / openclaw**。`plugins/cursor/` 仅有 `__pycache__` 残留，无实现文件，未落地。

| 目标 | 形态 | MCP 配置 | hooks | 特有脚本 |
|---|---|---|---|---|
| claude-code | shell hooks + Python | `.mcp.json`（http transport，`${HTBA_GATEWAY_URL}/mcp/v1` + `Bearer ${HTBA_TOKEN}`） | `hooks/hooks.json`（SessionStart + PreToolUse） | `render_mcp_config.py` / `mask_diff.py` / `append_pref.py` |
| codex | shell hooks + Python | `.mcp.json` | `hooks.json`（同上，PreToolUse matcher 多 `apply_patch`） | `gateway_tool.py` / `detect_data_tool_use.py` / `score_collection_opportunity.py` / `collection_hint.py` / `render_data_collector.py` |
| openclaw | **TS/Node 包**（编译产物 `dist/index.mjs`） | 无 `.mcp.json`，靠 `openclaw mcp set` 或 onboarding 写 `~/.openclaw/openclaw.json` | TS `before_tool_call` | `src/commands/*.ts` |

三端共性：本地状态根 `~/.htba-team/`（`token`(600) / `cache/<role>.json` / `preferences.md`）；都复用 `plugins/_shared/` 的 Python 脚本（bootstrap 时同步进各包 `scripts/_shared/`）。

## bootstrap：拉包 + 注入（SessionStart）

`claude-code/scripts/bootstrap.sh` 核心：

1. source `~/.htba-team/env` 兜底环境变量，确保默认 `preferences.md` 存在
2. 无 token/gateway 直接跳过
3. `list_role_packs` → `[{code,current_version}]`；网关不可达退回本地缓存；返回 `[]` 清空缓存
4. 逐角色比对本地缓存版本，**版本不同才** `get_role_pack` 覆盖写 `cache/<code>.json`，并 prune 已撤销角色
5. `get_system_agent`（带 `local_checksum`，支持 `not_modified`）写 `cache/system-agent-data-collector.md` + `.checksum`
6. 退出码：0 全成功 / 1 配置缺失 / 2 部分角色失败

**token 烘焙**：写入 token 后立即用 `render_mcp_config.py` 把真实网关 URL+token 烘焙进已装插件的 `.mcp.json`，使 MCP server 不依赖启动终端是否 `source` 过 env（每次 SessionStart 也重烘焙）。

**system_prompt compose**（SessionStart hook）：从 cache 派生 `<project>/.claude/skills/<role>/`（SKILL.md + references + sql-examples + workflows + methods），再把所有 role 的 system_prompt / preferences / change_summary 拼成 `<additional-system-instructions>...</additional-system-instructions>` 注入。Codex 版把同样内容拼进 `hookSpecificOutput.additionalContext` JSON 返回，另写 `.codex/htba-team/loaded-roles.json`。

**离线降级**：网关不可达用本地 `cache/<role>.json`，并在上下文显式提示「使用本地缓存版本 X（同步于 …）」。

## method 脚本：物化 + 共享 invoker（不让 LLM 照抄）

设计要点：method 的 `script_example` **不**作为示例让 LLM 读后重写，而是作为模板 `.py.tpl` 随角色包物化，一行命令执行——避免 LLM 二次改写漂移。

- `_shared/materialize_methods.py`：把 `pack.methods[]` 写成 `<methods_dir>/{run.py, <id>.py.tpl, <id>.json, .manifest.sha256}`，sha256 指纹命中即整体跳过（run.py 升级也算变化）。codex 走 CLI 形态遍历 cache 物化，claude-code 走函数 import 形态。
- `_shared/htba_run_method.py`（共享 invoker，仅 stdlib）：读 `<id>.json` 的 `params_schema` 做必填/多余字段/浅类型校验（bool 不当 int）→ 把入参双重序列化拼到 `.py.tpl` 前面（脚本直接 `params["xxx"]` 取值、无需 argparse）→ 写 `~/.htba-team/.run/<id>.<sha8>.py` subprocess 执行、GC 7 天前旧脚本 → 透传 stdout/stderr/exit code，失败 stderr 首行固定 `HTBA_METHOD_ERROR <id> <kind>`（kind ∈ missing_param/unknown_param/type_mismatch/missing_template/runtime_error）。
- 会话入口写在派生 SKILL.md：`python methods/run.py <method_id> '<params_json>'`。

## MCP 工具名 SoT

`_shared/htba_mcp_naming.py`：**唯一**定义工具名识别正则的地方，明令禁止源码写死前缀字面量。导出 `DATA_TOOLS`（run_query/run_template_sql/describe_table/list_tables）与取数子集 `QUERY_TOOLS`；正则 `MCP_TOOL_NAME_RE` 兼容 `mcp__plugin_<name>_htba-team__<tool>` 与 `mcp__htba-team__<tool>`。shell 版 `htba_mcp_naming.sh` 提供同款 ERE + 数组（注释要求两者同步）。消费脚本双候选寻址：部署版 `scripts/_shared` 优先、源码版 `plugins/_shared` 回退。

## preferences.md：本地真理 + 乐观锁跨端同步

- **本地真理副本** `~/.htba-team/preferences.md`，所有同步不阻塞本地写。SessionStart 首装时从 `defaults/preferences.md` `install -m 600` 创建，内容拼进注入的「## 用户个人偏好」段。
- **写保护**（PreToolUse hook）：拦对 preferences.md / token / cache 的写，**仅 data-collector 放行**（检查 stdin 的 agent_id/subagent_type/agent_name + 环境变量）。openclaw 用 TS `before_tool_call` 拦 `WRITE_TOOLS` + 破坏性 Bash 正则。
- **同步** `_shared/sync_pref.py`（状态落 `preferences.meta.json`：version/hash/sync_enabled/dirty/冲突路径）：
  - `pull`：`get_preference` 带 local_version，服务端更新则备份本地后覆盖；本地与远端各自有改动 → 写 `preferences.remote-<ts>.md`、返回冲突码 2、提示 `/htba-team:prefs-resolve`
  - `push`：`put_preference` 带 base_version + source_client；422 PREF_CONFLICT 同样落 remote 备份；软上限 20KB
  - `set-sync on|off` → `set_preference_sync`
  - 全局 flock 互斥防 bootstrap+append 并发写乱 meta；bootstrap 每次拉一次远端（claude 传 `HTBA_SOURCE_CLIENT=claude`、codex 传 codex）
- data-collector 的 `preference` 类候选走 `append_pref.py` append-only 本地写，**永不上报**。

## data-collector：silent / interactive 双模式

**触发已改「模型自驱 in-band」，不再用 Stop hook**（`hooks.json:2` 明示；doctor 明示「已无 Stop hook 与时间节流」）。两条路径：

- **模型自驱（silent，每会话至多一次）**：模型完成实质取数分析后自行判断有可沉淀信号才发起。**不用 AskUserQuestion、不打断**；对 `category ∉ {preference, skill_meta}` 的候选，脱敏通过后默认 `user_confirmed=true` 直接 `submit_feedback`；**脱敏不确定的候选直接丢弃**；提交后回答末尾附一句非阻塞告知。
- **手动 `/collect`（interactive）**：用 `AskUserQuestion` 逐条勾选、默认全不勾选、只提交勾选项。

共用 §任务 step 0/0.5/1/2/3/4（判断/批次上下文/识别/提炼/脱敏/写 staging）与全部红线，**唯一区别在 step 5-6 是否征询用户**。staging 落 `~/.htba-team/.staging/<batch_id>.json`（700/600），提交 200 后立即删除。客户端脱敏 `mask_diff.py` 与服务端 `common/masking.py` 通过 `tests/unit/test_masking_parity.py` 保持双向一致。

## Codex 触发可靠性三层补强（Codex 独有）

Codex 会话可能不暴露 htba-team MCP namespace，靠 transcript 识别取数不可靠，故补：

1. **受控 shell fallback** `gateway_tool.py`：MCP 不可用时用它打网关，成功后写脱敏 marker `.codex/htba-team/used-data-tool.jsonl`（source=`codex-shell-fallback`）
2. **marker + transcript 双源识别** `detect_data_tool_use.py`：扫 transcript 的 `tool_use` 块（避免 deferred_tools 广播误报）+ 读 marker + 识别文本痕迹；区分 DATA_TOOLS / QUERY_TOOLS
3. **启发式打分** `score_collection_opportunity.py` + 兜底 `collection_hint.py`：`ask.md` 给最终答案前必跑 `collection_hint.py`，按强信号（显式 collect 意图/口径修正/重复失败/infra 5xx）+ 弱信号（手写 SQL/重复维度）+ mode（quiet/balanced/eager，env `HTBA_DATA_COLLECTOR_MODE`）判断是否提示；只提示不自动上报
4. **交互层适配** `render_data_collector.py`：base agent + Codex overlay，把 `AskUserQuestion` 换成 `request_user_input`，强制用 `gateway_tool.py submit_feedback --staging-path --confirm-ids` 提交；overlay 只改交互层，不得改 §任务/§数据结构/§红线

openclaw 无脚本探针，靠 `ba-ask` skill 内置「模型自驱、每会话至多一次」约束，手动入口 `openclaw htba-team-collect`。
