# 模块 5 · 发布上线全流程(含域名/DNS/反向代理)

> 时长:75 min | 形式:动手工作坊 | ★主线 | 受众:PM/管理层/BI分析师

---

## 一、本节目标

上午你在自己电脑上做出了一个能跑的小工具,但它只属于你这一台机器。这一节,我们把它真正「搬上线」——做成一个**有公开链接、同事点开就能用**的应用。

学完本节,你应当能:

- 看懂 4~5 个主流托管平台的差别,知道什么场景该选谁。
- 亲手把上午的 Demo 部署成一个公开链接(以 Streamlit Cloud 为主线)。
- 理解 GitHub 代码托管、环境变量/API Key 该怎么安全放置。
- 用「店名 / 黄页 / 门卫」三个比喻,讲清域名、DNS、反向代理是什么、各管什么。
- (可选)把又长又不正式的默认链接,换成 `tool.公司.com` 这种自己的地址。

一句话:**上一节告诉你「开餐厅还差什么」,这一节带你把店真正开起来、挂上招牌。**

## 二、讲师讲稿 A:托管平台(⏱ 15 min)

**讲解要点**:托管平台 = 一台 24 小时开着、对外服务的「公共电脑」。你不用自己买服务器、装系统,把代码交给它,它帮你跑起来并给你一个公开网址。区别只在于:上手难不难、适合做什么、免费够不够用。

**讲解词(可照念)**:
「上一节说,上线第一件事是把程序搬到一台『永远开着、谁都能连』的电脑上。好消息是,这台电脑你不用自己准备——有一堆公司专门提供这种服务,叫『托管平台』。就像你想摆摊卖东西,不用自己盖房子,租个现成的铺面就行。我们今天选其中最简单的一家:**Streamlit Cloud**,因为它对纯 Python、零前端的小工具最友好,免费、五分钟能上线。」

**类比**:托管平台就是「商场招租」。Streamlit Cloud 是手把手的孵化器档口,Vercel 是装修精致的旗舰店铺,自建服务器则是自己买地盖楼——能力最强,但你得当物业、保安、电工全包。

### 托管平台对比表

| 平台 | 上手难度 | 适合场景 | 免费额度 | 适合谁 |
|---|---|---|---|---|
| **Streamlit Cloud** | ★☆☆☆☆ 最简单 | 纯 Python 数据应用、内部小工具、原型 Demo | 免费,公开应用基本够用 | 本节主线;PM/BI 首选 |
| **Hugging Face Spaces** | ★★☆☆☆ 简单 | AI 模型演示、Gradio/Streamlit 应用 | 免费 CPU,GPU 另付费 | 想展示 AI 模型效果的人 |
| **Render / Railway** | ★★★☆☆ 中等 | 需要后端、数据库的正经小应用 | 有免费额度,闲置会休眠 | 想做得更「像个产品」的人 |
| **Vercel** | ★★★☆☆ 中等 | 前端网站、Next.js 等 web 应用 | 个人免费额度慷慨 | 有前端项目或正式对外网站 |
| 自建服务器(云主机) | ★★★★★ 最难 | 完全自主、规模化、强合规 | 无免费,按月付费 | 交给专业工程团队 |

**讲解词**:「记一个原则:**越往上越省心,越往下越强大。** 我们做内部小工具,选最省心的就对了。等真要做成大规模对外产品,再交给研发团队往下面走。」

## 三、动手:部署上午的 Demo(以 Streamlit Cloud 为主线,⏱ 30 min)

> 总思路:**代码先放到 GitHub(网上的代码仓库)→ 让 Streamlit Cloud 读这个仓库 → 它自动跑起来并给你公开链接 → API Key 单独偷偷放,不写进代码。**

### 第 0 步:准备账号

- **做什么**:注册 GitHub 和 Streamlit Cloud。
- **怎么做**:用工作邮箱注册 [github.com](https://github.com),再到 [share.streamlit.io](https://share.streamlit.io) 用「Sign in with GitHub」一键登录。
- **预期结果**:两个账号都能正常打开后台页面。

### 第 1 步:理解为什么要用 GitHub

- **做什么**:明白 GitHub 是干嘛的。
- **怎么做**:把它理解成「代码的网盘 + 历史存档」。托管平台不读你电脑上的文件,只读 GitHub 上的;把代码放上去,平台才看得到。
- **预期结果**:你知道「上线」= 让平台读到你 GitHub 里的代码。

### 第 2 步:把 Demo 代码放上 GitHub

- **做什么**:创建一个仓库(Repository),把上午的 `app.py` 和 `requirements.txt` 传上去。
- **怎么做**:GitHub 右上角「+」→ New repository → 起名如 `my-first-app` → 选 Public → 用网页的「Add file → Upload files」直接拖入两个文件 → Commit。
  - `requirements.txt` 里写明用到的库(如 `streamlit`、`openai`),每行一个,平台靠它知道要装什么。
- **预期结果**:仓库页面能看到你的两个文件。

### 第 3 步:在 Streamlit Cloud 部署

- **做什么**:让平台读你的仓库并运行。
- **怎么做**:Streamlit 后台点「Create app」→ 选刚才那个仓库 → 主文件填 `app.py` → Deploy。
- **预期结果**:出现部署日志,约 1~3 分钟后得到一个公开链接,形如 `my-first-app.streamlit.app`。

### 第 4 步:安全放置 API Key(关键!)

- **做什么**:让程序能用上你的 API Key,但**绝不把 Key 写进代码上传**。
- **怎么做**:在 Streamlit 应用的「Settings → Secrets」里,用「环境变量/密钥」的方式填入,如 `OPENAI_API_KEY = "sk-xxxx"`;代码里用 `st.secrets["OPENAI_API_KEY"]` 读取。
  - **为什么**:代码是 Public 的,谁都看得到。Key 写进代码 = 把家门钥匙贴在大门上,别人会拿去刷你的账单。环境变量是「单独锁在保险柜里」,只有程序运行时才取用。
- **预期结果**:刷新应用,功能正常,而 GitHub 上的代码里看不到任何密钥。

### 第 5 步:分享给同事验收

- **做什么**:把链接发给隔壁同事,让他在自己电脑打开。
- **怎么做**:复制 `xxx.streamlit.app` 链接,发到群里。
- **预期结果**:对方无需装任何环境,点开即用。**这就是「上线」成功的那一刻。**

## 四、讲师讲稿 B:域名 · DNS · 反向代理(⏱ 20 min)

**讲解要点**:上面拿到的 `xxx.streamlit.app` 能用,但又长又不正式。想换成 `tool.公司.com` 这种自己的地址,就要认识三件事。一个比喻全串起来:**域名是店名,DNS 是电话黄页,反向代理是前台/门卫。**

**讲解词(可照念)**:
「你的应用现在住在一台服务器里,这台机器真实的『门牌号』是一串数字 IP,像 `76.76.21.21`,没人记得住。于是我们给它起个好记的『店名』——这就是**域名**。可全世界这么多店,顾客报出店名,怎么找到具体在哪条街哪个门牌?靠一本**电话黄页**,按店名查到门牌号——这就是 **DNS**。到了店门口,还得有个**前台/门卫**统一接待、验明身份、再领你进对应的房间——这就是**反向代理**。」

- **域名(店名)**:在注册商(阿里云、腾讯云、Cloudflare、GoDaddy 等)按年购买。`company.com` 是主域名;`tool.company.com` 是子域名,**一个主域名下可以免费随便加很多子域名**,不同工具各占一个,不用重复买。

- **DNS(电话黄页)**:把域名翻译成 IP。你访问网址时,浏览器先问 DNS「它在哪台机器上」,拿到地址再去访问。改了解析后要等几分钟到几小时才全网生效,这个等待叫 **DNS 传播**。常用记录类型够用就好:

| 记录类型 | 作用 | 一句话理解 | 上线时用到吗 |
|---|---|---|---|
| **A 记录** | 域名 → IP 地址 | 直接写门牌号 | 自建服务器时用 |
| **CNAME 记录** | 域名 → 另一个域名 | 「我家地址同某某店」 | **★托管平台最常用** |
| **TXT 记录** | 一段文本说明 | 给平台「验明正身」 | 偶尔做域名验证用 |

- **反向代理(前台/门卫)**:站在你应用前面,对外只露一个入口,再把请求分发给后面的应用。它负责:统一入口、配 HTTPS、把多个服务挂在同一域名下、限流挡攻击。常见角色:Nginx(经典自建)、Cloudflare(最省心,注册即用,还自带防护)。**关键点:用 Streamlit / Vercel 这类平台时,反向代理平台已经帮你做好了**,你只管「域名 + DNS 解析」;只有自建服务器才需要自己配 Nginx。

- **HTTPS / 小锁**:地址栏那把小锁,代表传输已加密。如今多数平台和 Cloudflare 都**自动免费签发证书**,你了解「为什么需要、由谁负责」即可,不用手动操作。

**一条龙串讲**:买域名 → 在 DNS 后台加一条 CNAME 指向托管平台 → 平台自动配好反向代理与 HTTPS(小锁自动出现) → 同事用 `tool.company.com` 直接访问。**全程你真正动手的只有「加一条 DNS 记录」这一步。**

## 五、动手(可选):把自定义域名指向应用(⏱ 10 min)

> 没有公司域名的学员看演示即可;有域名的可现场操作。

- **第 1 步 做什么**:在托管平台拿到目标地址。
  **怎么做**:Streamlit/Vercel 的「Settings → Custom domain」里填入你想用的 `tool.company.com`,平台会给出一个 CNAME 目标(如 `xxx.streamlit.app` 或一串平台地址)。
  **预期结果**:复制下这个目标地址。

- **第 2 步 做什么**:在域名后台加 DNS 解析。
  **怎么做**:进域名注册商后台 → 解析/DNS 设置 → 添加记录:类型选 **CNAME**,主机记录填 `tool`,记录值粘贴上一步的目标地址,保存。
  **预期结果**:后台出现一条新的 CNAME 记录。

- **第 3 步 做什么**:等待生效并验证。
  **怎么做**:等几分钟到几小时(DNS 传播),用浏览器打开 `tool.company.com`。
  **预期结果**:能正常打开应用,地址栏出现小锁(HTTPS 平台自动配好)。

## 六、常见问题与排错

| 现象 | 可能原因 | 怎么解决 |
|---|---|---|
| 部署日志报 `ModuleNotFoundError` | `requirements.txt` 漏写了某个库 | 补上缺的库名,重新 Commit |
| 应用能开但功能报 Key 错误 | 没在 Secrets 里配 API Key | 到 Settings → Secrets 填入,刷新 |
| 自定义域名打不开 | DNS 还没传播 / CNAME 填错 | 等待并核对记录值;用「DNS 检查」工具查 |
| 没有小锁 / 提示不安全 | 证书还在自动签发中 | 多等几分钟,通常平台自动完成 |
| 应用半天打不开、转圈 | 免费额度休眠(Render 等) | 首次访问会唤醒,稍等;或换平台 |
| GitHub 上传后平台看不到改动 | 改了本地没 Commit | 确认在 GitHub 网页能看到新文件 |

## 八、讲师备注与易错点

- **时间分配**:动手部分(第三节)是全场重心,务必留足 30 min,允许个别同学卡住时邻座互助。
- **最高频翻车点是 API Key**:反复强调「绝不把 Key 写进代码上传到 Public 仓库」,这是安全红线,也是非工程同学最容易踩的坑。可现场演示「Secrets 怎么填」。
- **GitHub 对小白门槛偏高**:建议直接用网页版「Upload files」拖拽上传,**不要**现场教 git 命令行,会拖垮节奏。
- **比喻要讲透**:店名/黄页/门卫这组比喻是本节灵魂,讲第四节时先把比喻立住,再对应术语,学员接受度最高。
- **反复强调一句话**:用 Streamlit/Vercel,**反向代理和 HTTPS 平台都包了,学员只需操心「域名 + 一条 DNS 解析」**。避免他们误以为要自己装 Nginx、申请证书。
- **域名环节量力而行**:多数学员没有公司域名权限,第五节以演示为主,不要求人人动手,避免冷场。
- **网络与账号**:提前确认现场网络能访问 GitHub 与 Streamlit;准备一个已部署好的「标准答案」应用作兜底演示。
