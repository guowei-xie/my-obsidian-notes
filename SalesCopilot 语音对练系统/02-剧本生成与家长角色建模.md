## 剧本数据模型（`src/models/script.py`）

`PracticeScript` 是对练的中枢契约，两条管线（语音、评价）都消费它：

```
PracticeScript
├─ persona: Persona            家长人设（name/relation/child_age/grade/city/occupation/background）
├─ objections: [Objection]     异议 2~4，id=O1/O2...
├─ opportunities: [Opportunity] 机会信号 1~4，id=P1/P2...（总信号 3~7）
├─ first_objection_id          开场抛出的异议
├─ pre_brief: PreBrief         给销售的背景+考核要点（不剧透异议）
├─ success_criteria            register_required + must_resolve(通常=所有 core 异议)
└─ raw_dialogue_excerpt        原始对话（仅服务端持久化，对练前不返前端）
```

**Objection / Opportunity 同构**：都有 `id/title/content/trigger/level(core|normal)/mapped_factors`。区别是语义——异议是阻力、机会是正向信号；`mapped_factors` 分别挂图谱的负向/正向 Factor。

**LLM 输出防御性解析**（本文件的精华，`script.py:14-49`）：
- `_first_or_none`：LLM 偶尔把单值字段写成数组（如 `child_age=[8,8]`），取首元素兜底；
- `child_age` 校验器：`"未知"/"未提及"/""` → None，字符串 `"8岁"` → 剥离"岁"转 int，失败返 None；
- 所有文本字段 `mode="before"` 先过 `_first_or_none` 再 `str()`。

这是"**永远不信任 LLM 输出格式，在模型边界做兜底**"的典型（[[04-方法论·可迁移模式]]）。

## 生成流程（`src/pipeline/script_generator.py`）

`generate_from_sample(config_path, sample_id, catalog)`：
1. `fetch_dialogue_text` 取样本原始对话，超 `_MAX_DIALOGUE_CHARS=12000` 截断；
2. `_render_catalog_block`：把 `catalog.factors` 按极性分三桶（正向→建议给 opportunities、负向→建议给 objections、中性/其他），渲染成 prompt 可读块；**catalog 为空时给明确 hint**"本次请将所有 mapped_factors 留空数组"（`_EMPTY_CATALOG_HINT`），而不是让 LLM 瞎猜；
3. 填充 `prompts/script_gen_v2/user.txt` → LLM（deepseek-r1, temp 0.5）→ `PracticeScript.model_validate`；
4. `_validate_script` 做结构校验与修复。

**`_validate_script` 的健壮性修复**（`script_generator.py:90-106`）：
- 无 objections 直接 raise；
- 总信号数不在 [3,7] 只 **warning 不阻断**；
- `first_objection_id` 不在异议集合里 → 强制回退到第一个异议；
- **机会 id 与异议 id 冲突时给机会重命名 `P{n}`**——因为评价阶段用 id 做信号索引，撞名会串数据。

CLI（`_main`）支持 `--sample` 单独调试，自己拉 catalog 再生成。

## 剧本生成 prompt（`prompts/script_gen_v2/`）

`system.txt` 是"资深销售教练设计岗前对练剧本"的角色，硬约束提炼进 prompt：
- persona 各字段**必须单值**（呼应 `_first_or_none` 兜底）；多孩家庭只挑当下沟通主体；
- objections 2~4（title ≤10 字，content 50~120 字家长口吻），从"参考因素清单"挑 0~2 个**负向** Factor 作 mapped_factors，找不到留空；
- opportunities 1~4，挑**正向** Factor；
- 总信号 3~7，按样本信号浓度自适应；
- pre_brief 的 `user_background_summary` **只含家长基础情况，不剧透异议/机会**；key_points 3~5 条告诉销售"会被考核什么"；
- 输出纯 JSON 无围栏。

`user.txt` 把 `sample_id` + `catalog_block` + `dialogue_text` 三段填进去。

## 家长角色建模（`src/pipeline/system_role_builder.py`）

`build_system_role(script, difficulty)` 把剧本拼成注入火山 `dialog.system_role` 的一大段中文：
1. **persona_block**：把结构化人设拼成自然语言小传；
2. **objections_block**：`- [O1] 标题（core）：内容（触发时机：...）`，"你心里装着以下异议，将在合适时机说出来"；
3. **opportunities_block**（有机会信号才拼）：机会信号 + "按难度规则决定主动释放程度，但不要明说你在释放机会"；
4. **通用对话规则**：口语化中文、开场即抛 first_objection、每次只说一个意思(≤30字)、销售绕过要拉回、**不暴露剧本结构元信息**、只有核心异议都被认可且销售明确推进报名才同意（说"好那我们办理报名手续吧"）；
5. **难度规则**（尾段拼接，见下）。

`build_hello_text`：用 first_objection 生成家长开场白 `"老师你好，咱直接说哈：{content}"`——对应火山的 `SAY_HELLO`，让家长先开口。

## 难度即 prompt 参数（`_DIFFICULTY_RULES`）

三档难度**只是替换 system_role 尾部的一段行为规则文本**，无任何额外代码/模型分支——这是很划算的设计（[[04-方法论·可迁移模式]]）：

| 难度 | 异议表现 | 机会信号释放 | 报名门槛 |
|---|---|---|---|
| **hard** | 反复追问、质疑、打断、对比竞品、提新顾虑，轻易不松口 | 心里有但不主动暴露，**要销售明确发问、用方法挖掘才挤牙膏式透露** | 所有核心异议给出有充分细节的应对 + 抓住核心机会才考虑 |
| **medium** | 每异议 1-2 轮辩驳，应对得当（解释+举例/数据）就被说服 | 按 trigger 时机**自然释放一次**，等销售识别；没接住不重复 | 核心异议解决 + 核心机会被接住 |
| **easy** | 每异议只提 1 次，不辩驳 | **非常主动释放，几乎不用挖掘** | 走完流程、所有信号被跟进即同意 |

难度非法值兜底为 `medium`（`system_role_builder.py:84`）。

## 剧本从哪来：sample vs template（`src/api/sessions.py`）

- **sample 模式**：`POST /api/sessions/start` → `asyncio.to_thread(generate_from_sample)`（LLM 调用放线程池不阻塞事件循环）→ 写 meta + script → 返回 `session_id` + `pre_brief`（**只返 pre_brief，不返 objections**，保证对练前不剧透）；
- **template 模式**：直接把用户模板转成 `PracticeScript`（无 opportunities，跳过 LLM）；
- **`/{id}/restart`**：复用已有剧本另开 session，跳过剧本生成（同一剧本可反复练）；
- **`/{id}/result`**：必须 `finished_at` 存在（未结束返 409），才返回完整剧本 + 评分 + 原始 dialogue（此时才允许"剧透"）。

样本筛选口径（`src/db/mysql.py`）：`distill_key_moments` 中 `human_reviewed=1 AND density='high'`，按 sample_id 去重（同一样本可能有多条 high 片段）。
