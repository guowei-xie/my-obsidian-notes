# 场景设计详述

--- 

## V1 落地焦点

四个场景是完整产品的全貌，但 V1 只聚焦**场景 1 的核心子集**：

> **"销售现在最该跟谁，以及怎么跟。"**

V1 嵌入首课回访场景，做两件事：
1. **跟进优先级**（有排序、有原因的用户清单）
2. **下一步动作建议**（基于 Top 经验蒸馏的策略卡片）

选择这个切入点的理由：
- 频次高：每天都在发生
- ROI 高：首课→年课是最大的转化漏斗
- 经验依赖强：Top 与普通人差距最大的节点之一
- 数据就绪：对话 + 行为 + 画像数据已具备

以下是四个场景的完整设计。

---

## 场景 1：首课前 — 意向分类 + 策略生成（服务于销售个体）

### 触发时机

销售在首课电访前，系统自动完成意向分析并生成策略卡片。

### 处理流程

```
用户数据（画像 + 行为 + 跨渠道对话记录）
  ↓
Step 0: 跨渠道上下文聚合
  ├─ 渠道来源：直播间内容/卖点/承诺
  ├─ 客服记录：问卷结果、初始诉求
  └─ 销售对话：进班后的沟通
  ↓
Step 1: 标签提取
  ├─ 事实标签：用户画像、行为埋点、渠道信息
  └─ 推断标签：AI 从全链路对话中抽取
  ↓
Step 2: 话题识别（在聊什么）
  ↓
Step 3: 因素提取（每个话题下的积极/消极信号）
  ↓
Step 4: 意向推导（由话题×因素综合推导 → S0-S4）
  ↓
Step 5: 策略生成（RAG: Top 经验 + 用户上下文）
  ↓
输出：策略卡片 → 销售端
```

### 标签提取的三层结构：话题 → 因素 → 意向

意向不是独立判定的标签，而是**从话题和因素中推导出来的结论**。

```
对话文本
  ↓
话题识别（在聊什么）: 学习情况、课程方案、价格费用...
  ↓
因素提取（信号是正是负）: 每个话题下的积极/消极信号 + 原文证据
  ↓
意向推导（综合判定）: 话题×因素组合 → S0-S4
```

**示例推导链：**
```
话题: 学习情况     → 积极因素: "孩子数学不错，喜欢编程"（学习兴趣）
话题: 价格费用     → 积极因素: "这个课多少钱？"（主动询价）
话题: 时间安排     → 消极因素: "周末排得太满了"（时间冲突）
───────────────────────────────────────────────────────
综合: 积极因素主导 + 出现询价信号 → S3（需求明确），趋向 S4
```

### 意向分类体系

不是简单的 ABCD 等级评分，而是**阶段序列**，支持排序 + 流转（状态机）。
每个阶段的判定都可追溯到具体的话题×因素证据链。

| 阶段 | 定义 | 推导逻辑 | 典型话题×因素组合 |
|------|------|---------|------------------|
| **S0** | 暂缓 / 流失 | 明确拒绝信号，消极因素压倒性主导 | 决策过程×"不需要" / 孩子兴趣×"不想学" |
| **S1** | 沉默用户 | 无话题交集，或无因素信号 | 无实质对话 / 仅"嗯""好的" |
| **S2** | 需求模糊 | 有话题但弱积极，未形成方向 | 学习情况×"随便看看" / 课程了解×被动回应 |
| **S3** | 需求明确 | 多话题积极因素主导，主动表达 | 学习目标×目标明确 + 课程了解×主动咨询 |
| **S4** | 强购买意愿 | 出现强购买信号 | 价格费用×主动询价 + 时间安排×主动约课 |

**状态流转规则：**

```
         ┌──────────────────────────────────┐
         ↓                                  │
S0 ←── S1 ──→ S2 ──→ S3 ──→ S4            │
 ↑      ↑      ↑      ↑      │             │
 └──────┴──────┴──────┴──────┘             │
       （任意阶段可回退至 S0）              │
                                            │
S4 ──→ 成交 ──→ 退出状态机                │
S0 ──→ 多次确认 ──→ 标记流失 ──→ 退出     │
```

**关键特性：**
- 有序：S1 < S2 < S3 < S4，可排序，支持"优先联系高意向用户"
- 可流转：用户状态会随新信息更新，不是一次性判定
- 可解释：每次分类附带具体证据（对话原文 + 行为数据）

### 因素分析

对意向分类的**原因**进行结构化推理，分为驱动因素和阻塞因素：

#### 驱动因素（推动意向前进）

| 因素类型 | 示例 | 信号强度 |
|---------|------|---------|
| 目标驱动 | 考试/升学/比赛（信奥、蓝桥杯） | 强 |
| 痛点明确 | "孩子数学不好"、"逻辑能力差" | 强 |
| 时间窗口 | "暑假想报个班"、"下学期想开始" | 中 |
| 主动行为 | 问价、约补课、主动加微信 | 强 |
| 社交背书 | "朋友家孩子也在学"、"老师推荐" | 中 |
| 孩子兴趣 | "孩子很喜欢这个课" | 中 |

#### 阻塞因素（阻碍意向推进）

| 因素类型 | 示例 | 化解难度 |
|---------|------|---------|
| 价格敏感 | "太贵了"、"能不能便宜点" | 中 |
| 决策权模糊 | "等孩子他爸回来再说"、"我做不了主" | 中 |
| 时间冲突 | "时间安排不过来"、"太忙了" | 低 |
| 信任/效果怀疑 | "学了有用吗"、"能出什么成绩" | 高 |
| 外部条件 | 设备不满足、网络环境差 | 低 |
| 竞品比较 | "在看其他机构"、"XX 也不错" | 高 |
| 年龄/阶段顾虑 | "孩子太小了"、"现在学会不会太早" | 中 |

### 策略生成

**核心理念：不提供话术，提供策略。**

策略 = "行为埋点" + "沟通记录" + "Top 经验蒸馏"

#### 策略卡片结构

```yaml
用户概要:
  基本信息: "XX市，X年级，首次体验课"
  当前意向: S2（需求模糊）
  关键标签: [社交背书, 孩子有兴趣, 时间冲突]

意向推进目标: S2 → S3（需求模糊 → 需求明确）

关键问题:
  - 用户尚未建立"课程方案 ↔ 学习目标"的明确关联
  - 尚未进入价格/决策信息阶段

驱动因素（可放大）:
  - 社交背书: "朋友家孩子也在学"
  - 孩子兴趣: 体验课参与度高（完课率 100%，作品提交 2 次）

阻塞因素（需化解）:
  - 时间冲突: "周末排满了"

行动路径:
  步骤1 - 强化需求绑定:
    做什么: 明确用户目标与编程之间的对应关系
    为什么: 用户有模糊需求但未关联到具体课程价值
    参考: Top销售在此阶段会先聊孩子的具体情况，不急于介绍课程

  步骤2 - 引导方案对比:
    做什么: 提供不同课程/路径的对比，帮助用户形成选择框架
    为什么: 让用户从"要不要学"转变为"选哪个学"
    参考: 给出2-3个适配方案，降低决策复杂度

  步骤3 - 化解时间阻塞:
    做什么: 提供灵活的时间方案（录播补课、调班）
    为什么: 时间冲突是最易化解的阻塞因素
    时机: 在需求明确后再提，避免过早暴露"在推销"

  步骤4 - 引导进入决策信息:
    做什么: 在方案明确后，自然引入价格、时间安排等信息
    为什么: 此时用户已有倾向，价格信息是推进而非阻碍

执行约束:
  - 避免过早直接报价
  - 避免继续泛介绍课程信息
  - 不要跳过决策人确认
  - 不要死板发送 SOP 模板消息
```

### 数据输入

| 数据源 | 内容 | 用途 |
|--------|------|------|
| 用户画像 | 城市、年级、设备、渠道来源 | 基础特征 |
| Leads 评分 | 历史模型打分 | 先验意向参考 |
| 行为埋点 | 页面浏览、创作行为、课程进度 | 行为特征 |
| 渠道/直播间数据 | 来源直播间、直播内容摘要、卖点/承诺 | 渠道上下文，理解用户预期 |
| 客服沟通记录 | 问卷结果、初步沟通内容、用户初始诉求 | 前置需求信号 |
| 销售对话记录 | 微信/IM/电话（进班后） | 推断标签的核心来源 |
| 履约数据 | 完课率、作业提交、出勤 | 用户投入度 |

### 跨渠道上下文融合

用户的旅程从下单就开始了，但传统模式下销售只能基于进班后的信息了解用户：

```
信息断裂现状:
  直播间 ──→ "信奥赛升学加分，暑假集训营"（用户被什么打动）
  客服   ──→ "孩子五年级，想提升逻辑思维"（用户的初始诉求）
  销售   ──→ 从零开始了解 ← 前两段信息几乎全部丢失
```

Sales Copilot 将三段信息串联，让策略生成基于完整的用户旅程上下文：

| 阶段 | 信息 | 串联后的策略价值 |
|------|------|----------------|
| 直播间/渠道 | 下单直播间的主题、卖点、承诺 | 知道用户被什么打动，承接而非矛盾 |
| 客服 | 问卷结果、初步沟通中的诉求和顾虑 | 跳过重复提问，直接切入核心问题 |
| 销售 | 进班后的沟通记录 + 行为数据 | 在完整上下文中做判断 |

**串联示例：**
```yaml
渠道背景:
  来源: "XX老师信奥专场直播"
  直播卖点: 信奥赛升学加分 + 暑假集训营
  触发预期: 用户大概率对竞赛路径有兴趣
客服记录:
  问卷: 五年级，有Scratch基础
  初始诉求: "想让孩子系统学一下"
建议调整:
  - 承接直播间信奥卖点，强化"现在开始→信奥路径"的可行性
  - 不要泛泛介绍课程（用户已有基本认知）
  - 直接从"系统学习"需求切入方案推荐
```

> Top 销售已经本能地在做这件事——主动了解直播间内容、关联用户需求。Sales Copilot 让这种能力从个人技巧变成系统能力。

### 边界情况处理

| 情况 | 处理方式 |
|------|---------|
| 无对话记录（全新用户） | 仅基于行为+画像给出 S1/S2 初步判断，策略聚焦"破冰" |
| 对话内容极短/无实质信息 | 标记为 S1（沉默用户），策略聚焦"建立联系" |
| 信号矛盾（既问价又说太贵） | 同时列出驱动和阻塞因素，策略聚焦"化解核心阻塞" |
| 多轮对话跨度长 | 以最近一轮对话为主要判据，标注意向变化趋势 |

## 场景 2：首课后 — 服务质量评价（服务于销售管理）

### 管理范式转换

传统销售管理驱动的是"努力"，Sales Copilot 驱动的是"判断质量"。

```
传统管理看什么:                     Sales Copilot 看什么:
  ✗ 今天打了多少个电话？              ✓ 需求沟通中 40% → 异议处理中 25% → 即将关单 10%
  ✗ 发了多少条消息？                  ✓ 有 30% 用户在"异议处理"环节响应不到位
  ✗ 有没有按 SOP 执行？              ✓ 张三在"化解价格异议"上弱于团队均值
```

不再看"有没有做动作"，而是看"关键判断是否到位"。

### 触发时机

首课电访完成后，系统对销售的沟通过程进行多维度质量评价。

### 评价维度

#### 维度 1：关键事件覆盖率

**定义：** 销售是否做了在当前阶段"该做的事"。

**核心公式：**
```
覆盖率 = Σ(已发生事件 × 权重) / Σ(应发生事件 × 权重)
```

"应发生"取决于用户当前的**履约 + 意向**阶段。

**关键事件清单（示例）：**

| 关键事件 | 触发条件 | 权重 | 识别方式 |
|---------|---------|------|---------|
| 了解孩子学习情况 | 所有用户 | 高 | 对话中提及成绩/学习习惯/年级 |
| 了解学习目标 | 所有用户 | 高 | 对话中提及目标/期望/为什么学 |
| 反馈课堂表现 | 已完成首课 | 高 | 对话中提及课堂表现/老师评价 |
| 介绍课程方案 | S2 及以上 | 中 | 对话中提及课程内容/路径 |
| 了解时间安排 | S2 及以上 | 中 | 对话中提及时间/排课 |
| 确认决策人 | S3 及以上 | 高 | 对话中确认"谁来决定" |
| 推进成交 | S4 | 高 | 对话中提及报名/付款方式 |

**关键特性：**
- 事件有权重：不是简单的"做了/没做"计数
- "应发生"是动态的：不同意向阶段，应做的事不同
- 识别基于对话分析：AI 从对话中判断事件是否发生

#### 维度 2：意向构成分析

**定义：** 首轮电访后，该销售所服务用户的意向分布。

```
示例输出:
  销售A 首访后意向分布:
    S0 (流失):     5%   ← 关注：是否可挽回？
    S1 (沉默):    15%   ← 关注：是否尝试了破冰？
    S2 (需求模糊): 40%   ← 正常
    S3 (需求明确): 30%   ← 好
    S4 (强意愿):   10%   ← 优秀
```

**分析价值：**
- 对比不同销售的意向分布差异
- 结合用户进班时的初始条件（leads 评分、渠道来源），评估销售的"推进能力"
- 追踪意向分布随时间的变化趋势

#### 维度 3：因素构成分析

**定义：** 对暂缓/流失类用户，阻塞因素的构成分析。

```
示例输出:
  销售A 的 S0/S1 用户阻塞因素分布:
    价格敏感:    35%
    决策权模糊:  25%
    信任怀疑:    20%
    时间冲突:    15%
    其他:         5%
```

**分析价值：**
- 如果某销售的流失用户大量集中在"信任怀疑" → 培训方向：加强价值传递能力
- 如果团队整体"决策权模糊"占比高 → 流程优化：在首访中增加"决策人确认"环节
- 针对性指导，而非泛泛"加强沟通"

#### 维度 4：机会利用率 / 异议处理率

**定义：** 用户发出关键信号后，销售是否"接住了"。

**信号分类：**

| 类型 | 信号示例 | 期望响应 |
|------|---------|---------|
| 正向信号 | 问价、约课、问报名方式 | 及时推进成交流程 |
| 负向信号（异议） | "太贵了"、"没时间"、"再看看" | 识别 → 回应 → 化解 |

**机会利用率：**
```
机会利用率 = 被响应的正向信号数 / 总出现正向信号数
```

**异议处理率（两层漏斗）：**
```
响应率 = 被回应的异议数 / 被识别的异议数
  ↓
缓解率 = 被缓解的异议数 / 被回应的异议数
```

**判定标准：**
- "被响应"：销售在信号出现后的合理时间窗口内（同一对话轮次或下一轮次）做出了针对性回应
- "被缓解"：用户在销售回应后，未再重复同一异议，或表现出态度软化

### 质量评分汇总

```
单次服务质量 = 
    α × 关键事件覆盖率 
  + β × 机会利用率 
  + γ × 异议响应率 × 异议缓解率

建议权重: α=0.4, β=0.3, γ=0.3（可根据业务调优）
```

### 管理端输出

- **团队仪表盘：** 各销售质量评分排名、趋势、维度对比
- **个人报告：** 具体到每通对话的质量拆解，标注"做得好"和"可改进"
- **培训建议：** 基于因素构成和薄弱维度，自动生成针对性培训主题

## 场景 3：续报前 — 意向分类 + 策略生成（服务于销售个体）

### 与场景 1 的关系

复用场景 1 的核心框架（意向分类 → 因素分析 → 策略生成），但数据源和上下文更丰富。

### 关键差异

| 维度 | 场景 1（首课前） | 场景 3（续报前） |
|------|----------------|----------------|
| 数据丰富度 | 少量行为 + 首次对话 | 完整学期行为 + 多轮对话 |
| 意向基线 | 从 0 开始判断 | 有历史意向变化轨迹 |
| 用户认知 | 对产品了解少 | 已有产品使用体验 |
| 驱动/阻塞因素 | 偏"预期型" | 偏"体验型" |
| 策略重点 | 建立连接、激发需求 | 巩固价值、化解续费障碍 |

### 续报特有的驱动因素

| 因素类型 | 示例 |
|---------|------|
| 学习成果 | 孩子进步明显、比赛获奖 |
| 习惯养成 | 孩子主动要求上课 |
| 路径依赖 | 已学到某个阶段，中断可惜 |
| 升级需求 | 想从 L1 进阶到 L2 |

### 续报特有的阻塞因素

| 因素类型 | 示例 |
|---------|------|
| 效果不达预期 | "学了一学期感觉没啥变化" |
| 兴趣衰减 | 孩子不想学了 |
| 服务不满 | 老师/课程/排课不满意 |
| 竞品替代 | 转去其他机构 |
| 经济压力 | "今年预算紧" |

### 额外数据源

| 数据源 | 内容 | 用途 |
|--------|------|------|
| 课程履约数据 | 完课率、出勤率、作业提交率 | 量化用户投入度 |
| 学习表现数据 | 作品质量、能力评估、比赛成绩 | 量化学习成果 |
| 历史对话全量 | 学期内所有沟通记录 | 追踪意向变化轨迹 |
| 历史意向标签 | 各阶段的意向分类结果 | 意向演变趋势 |

## 场景 4：续报后 — 服务质量归因（服务于销售管理）

### 核心问题

续报结果（续/未续）的差异，多大程度上可归因于"服务质量"？

### 服务深度建模

**定义：** 好服务 = 覆盖 × 质量 × 时机

**量化公式：**
```
服务深度 = Σ(关键事件权重 × 是否发生 × 质量评分 × 时间衰减)
```

| 组成部分 | 含义 | 示例 |
|---------|------|------|
| 关键事件权重 | 不同事件的重要程度不同 | "确认决策人"权重 > "介绍课程" |
| 是否发生 | 0/1 | 是否做了该做的事 |
| 质量评分 | 0-1 连续值 | 做了，但做得好不好 |
| 时间衰减 | 越接近决策点影响越大 | 续报前 1 周的沟通 > 学期中的沟通 |

### 归因方法论

#### 方法 1：分组对比

控制**非服务因素**（用户特征、阶段）后，对比不同服务行为的续报差异。

```
分析框架:
  控制变量: 用户 leads 评分、渠道来源、年级、地区、班型
  自变量: 服务深度、各维度质量得分
  因变量: 续报（0/1）
  
  对比方式:
    - 相同意向阶段下，服务深度高 vs 低 的续报差异
    - 相同用户条件下，不同销售的续报差异
```

#### 方法 2：回归建模

```
续报 ~ 用户特征 + 状态特征 + 服务特征

  用户特征: leads_score, grade, city_tier, channel, device_type
  状态特征: intent_stage, days_since_first_class, class_completion_rate
  服务特征: service_depth, event_coverage, opportunity_utilization, objection_handling
  
  输出:
    - 各特征的边际贡献（系数 / SHAP 值）
    - 可控因素（服务特征）的提升空间估计
```

#### 方法 3：倾向得分匹配（PSM）

```
处理组: 接受了"高质量服务"的用户（服务深度 > P75）
对照组: 接受了"一般服务"的用户（服务深度 < P25）

匹配维度: 用户特征 + 初始意向阶段
  
  → 匹配后对比续报率差异 = 服务质量的因果效应估计
```

### 归因输出

| 输出内容 | 受众 | 用途 |
|---------|------|------|
| 动作贡献度排名 | 运营/策略 | 哪些销售行为对续报贡献最大 |
| 阶段关键动作 | 运营/策略 | 每个意向阶段最有效的动作是什么 |
| 销售差异分析 | 管理者 | 控制用户条件后，谁的服务真正更好 |
| 意向流转分析 | 管理者 | 销售是否在"推进意向"，而不是停留 |
