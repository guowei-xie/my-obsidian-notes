# Sales Copilot（销售副驾）— 产品方案

---

## 0. 战略叙事：为什么是这件事

### 0.1 AI 拥抱的第一性问题

"全面拥抱 AI"很容易滑向一个默认姿势：把人今天做的事拆出来、封装好、交给 AI 执行。
这背后隐含了一个前提——**"今天组织里的大部分动作本来就是对的，只是效率不够高。"**

但现实不是。组织的问题从来不只是"做得慢"。

如果这个问题没想清楚，"拥抱 AI"很可能变成：更快地执行低价值动作、更规模化地复制错误、更自动化地制造幻觉。

所以，最先该问的不是"AI 能帮我们做什么"，而是——

> **"我们这家公司，真正是靠什么活着的？"**
> "最核心的结果，究竟是靠哪一些人、在哪些判断上，硬撑出来的？"
> "这些判断里，哪些应该被剥离成系统能力？"

### 0.2 从"岗位动作"到"组织价值"

以班主任/课程顾问为例——

表面上的工作：加微、发消息、打电话、挖需、记录意向、处理异议、关单...
这些都可以拆成 Skills，很多都可以 Agent 化。

但这个岗位的**组织价值**不是"做这些动作"，而是：

> **帮组织高质量地完成用户理解、价值传递、决策推动和收入转化。**

视角一旦切换：
- 有些动作可以被替代（比如辅导答疑）
- 有些动作应该被重构（比如固化的 SOP、千篇一律的电访框架）
- 有些动作根本不应该继续存在（比如营销感过重、毫无针对性的群发钩子）
- **有些原本依赖人经验的判断，应该上移为系统能力** ← 这是 AI 最值得切入的地方

### 0.3 真正值得 AI 的地方

真正值得优先 AI 的，不是"最通用的地方"，也不是"最容易推的地方"。
而是**"最接近核心结果，同时又最依赖人脑经验的地方"**。

一个环节如果同时满足：
- 高频发生
- 投入大量人力
- 高度依赖经验判断
- 不同人之间表现差异巨大
- 做得好坏显著影响结果

那它几乎天然就是 AI 最值得切入的地方。

在我们公司，这个地方就是**销售转化环节**（含续报，本质也是销售转化）。

### 0.4 判断，而非执行

轮岗 CT 时跟着群里 SOP 走，一天轰炸二三十条消息给用户。看着那堆模板，第一反应是"发这些有啥用"，但转念一想"万一就因为我发了这一条，他就报了呢"。

那个"万一"，背后藏着的是——**在信息不足时，我们用"动作的勤奋"去掩盖"判断的懒惰"。**

组织真正稀缺的不是"执行动作"，而是"在不确定中做对判断"：
- 这个用户值不值得继续投入？
- 用户讲的需求是真需求还是在敷衍？
- 这个节点最该推进的是信任、价格还是紧迫感？
- 什么时候该跟、什么时候该"先别烦他"？

这些判断决定了后续资源该往哪里走。**真正能带来改变的 AI，不是提供"答案参考"，而是进入"动作分配"。**

### 0.5 灵宝隐喻：副驾的产品范式

《王者荣耀》的 AI 陪伴"灵宝"：在玩家最容易做错判断的瞬间，给出足够靠谱的建议 + 一个 Next Best Action。

它没有替玩家打游戏，也没有把菜鸟变成高手。
它做的事很朴素：**把原本只有高手才会在意的判断，在合适的时机、合适的上下文里，递到了面前。**

Sales Copilot 要做的事，在范式上和灵宝一样：
- 不是"等你来问"的知识库 → 而是"关键节点主动出现"的副驾
- 不是替代执行 → 而是**重塑判断的分布**
- 不是让高手更强 → 而是**让普通人更稳定地做出不那么差的判断**

这一点极其重要。因为对"正态分布型"业务来说，真正决定结果的，不是"有没有超级高手"，而是**平均水平能不能被系统性抬高**。

### 0.6 Top 经验的本质：不可说的潜意识

销售从来不缺高手。但如果高手的能力只属于他自己，组织上限就永远卡在"下一条鲶鱼什么时候出现、以及它愿意待多久"。

高手真正的价值，往往不在于标准动作，而在于**能在极短时间里，基于大量模糊信号，做出微妙但正确的判断**。这种能力很难用线性 SOP 封装。

但这种"不可说"的经验，恰恰是组织能力最脆弱的地方，也是 AI 最可能建立壁垒的地方。

> AI 擅长的，正是从高维、模糊的数据里，找到人类能隐约感知但没法清晰表述的模式。

所以方向不是"让 AI 学 Top 的标准动作"，
而是**用 AI 把 Top 们的"潜意识"集体外化出来——把高手凭感觉做对的事，拆成组织可以系统做对的事。**

一旦做到这一步，AI 不再只是工具，它开始参与组织能力本身的形成。

### 0.7 信息孤岛：被割裂的用户旅程

用户到达销售手中之前，已经走过了一段旅程：

```
用户旅程:
  下单（渠道：合作直播间 / 广告 / 转介绍...）
    → 客服加微（目标：问卷填写 + 初步沟通，方式：微信/电话）
      → 进班加微（销售正式承接）
        → 首课回访 → 续报...
```

三个触点的信息彼此隔离：
- **渠道/直播间**：用户因什么内容下单，主播讲了什么卖点、做了什么承诺
- **客服**：用户填了什么问卷，初步沟通中透露了什么诉求和顾虑
- **销售**：只能从进班加微后开始了解用户，前两段信息几乎全部丢失

部分渠道的用户来自各种合作直播间。Top 销售已经在本能地弥补这个断裂——他们会主动了解用户来自哪个直播间，关联直播内容来挖掘需求。但这完全靠个人意识和信息搜集能力。

**Sales Copilot 的机会**：将渠道、客服、销售三段信息系统性串联。让每个销售在首次接触用户时，就拥有完整的用户旅程上下文。这不是锦上添花，而是让 AI 做到人很难做到的事——**跨系统的信息整合与上下文贯穿**。

## 1. 产品定义

### 一句话

在正确的时机，驱动正确的动作，产生正确的影响。

### 完整定义

Sales Copilot（销售副驾）= 在销售关键节点，基于用户状态与上下文，主动给出更接近 Top Sales 判断的建议系统。

**关键词拆解：**
- **关键节点**：不是全流程覆盖，是选择性切入最有价值的判断点
- **用户状态与上下文**：不是静态画像，是动态推理的意向 + 因素
- **主动给出**：不是"等你来问"，是系统推送
- **更接近 Top 的判断**：不是标准答案，是蒸馏自 Top 经验的策略
- **建议系统**：副驾，不是代驾

### 核心范式转换

| 维度 | 传统模式 | Sales Copilot |
|------|---------|---------------|
| 管理对象 | 销售的"努力程度" | 销售的"判断质量" |
| 用户分级 | 经验/主观/leads 评分 | 行为 + 对话 → 动态意向推理 |
| 策略来源 | 固化 SOP / 个人经验 | Top 经验蒸馏 + 用户上下文 → 个性化策略 |
| 赋能时机 | 事后复盘 / 培训 | **事前**实时建议 |
| 经验沉淀 | 口口相传 / 留在 Top 脑中 | 系统化提取 → 组织能力 |
| 组织逻辑 | 靠少数人兜底 | **靠系统托底** |

### 不做什么

- **不做代驾**：不替代销售执行任何动作（不自动发消息、不自动打电话）
- **不做知识库**：不是"你来搜、我来答"的 QA 工具
- **不做通用提效**：不是日报总结、会议纪要这类通用 AI
- **不做全流程**：V1 只切一个节点，不铺全链路

## 2. 目标用户

| 角色 | 核心诉求 | 使用场景 |
|------|---------|---------|
| 课程顾问（销售个体） | 在关键节点获得判断支持：跟谁、怎么跟 | 首课电访前、续报沟通前 |
| 销售主管（管理者） | 从管理"是否努力"转向管理"判断是否到位" | 首课电访后、续报结束后 |
| 运营/策略团队 | 理解转化归因、验证策略有效性 | 续报后归因分析、策略迭代 |

## 3. 四大场景概览

| 场景 | 时机 | 服务对象 | AI 输出 | 核心价值 |
|------|------|---------|---------|---------|
| **场景 1: 首课前意向+策略** | 首课电访前 | 销售个体 | 意向分类 → 因素分析 → 回访策略 | 用 Top 思维武装每个人 |
| **场景 2: 首课后服务质量** | 首课电访后 | 销售管理 | 关键事件覆盖率、机会利用率、异议处理率 | 量化"好服务"，驱动培训 |
| **场景 3: 续报前意向+策略** | 续报沟通前 | 销售个体 | 意向分类 → 因素分析 → 回访策略（复用场景 1） | 长周期用户的精准续报 |
| **场景 4: 续报后归因分析** | 续报窗口结束 | 销售管理 | 服务深度评分、归因建模 | 从"服务质量"视角解释结果差异 |

## 4. V1 落地策略

### 4.1 为什么 V1 必须克制

以前的思路（实际上也这么做过）：
整理销冠话术 → 切片到向量库 → 接上聊天记录/画像/订单 → 做个助手页面 → 让大家"试着用起来"

这套思路最大的问题：**它默认销售会主动来问，并且大概知道自己什么时候该问什么。**
这本质上是"培优"逻辑——服务的是已经有意识的人，而不是真正需要被托住的中腰部。

### 4.2 V1 选择标准

从销售全链路（加微→首电→催课→回访→异议处理→关单）中选**一个**节点先切入。

选择标准：
- 频次高 — 每天都会发生
- 做对了很值钱，做错了很伤 — ROI 显著
- 很吃个人经验 — Top 与普通人差距最大的地方
- 信息相对充分 — 有足够数据支撑 AI 判断

### 4.3 V1 聚焦：首课回访

**V1 只回答一个问题：** "销售现在最该跟谁，以及怎么跟。"

嵌入首课回访场景，做两件事：

**1. 跟进优先级（跟谁）**
```
一个有排序、有原因的跟进清单：
  ① 张三妈妈 [S3·需求明确] — 主动问了价格和排课，窗口期短
  ② 李四妈妈 [S2·需求模糊] — 孩子体验课完课率100%，家长尚未明确需求
  ③ 王五妈妈 [S1·沉默] — 加微后未互动，建议降低优先级
  ...
```

**2. 下一步动作建议（怎么跟）**
```
张三妈妈:
  当前阶段: S3 → 目标: S4（推进成交）
  渠道上下文: 来自"XX信奥专场直播"，客服沟通中表示"想让孩子系统学"
  驱动因素: 主动问价 + 孩子兴趣高 + 直播信奥卖点匹配
  阻塞因素: 时间安排冲突
  建议动作: 承接直播信奥卖点，结合孩子情况推信奥路径；先解决排课，再推报名
  不建议: 泛泛介绍课程（用户已有认知）、忽略直播间已建立的预期
```

### 4.4 V1 对销售管理的改变

从看"过程量"变成看"有效结果"：

```
传统管理视角:
  今天打了多少个电话？发了多少条消息？

Sales Copilot 视角:
  - 需求沟通中 40% → 异议处理中 25% → 即将关单 10%（意向漏斗）
  - 有 30% 的用户在"异议处理"环节响应不到位（改进焦点）
  - 张三在"化解价格异议"上表现弱于团队均值（针对性辅导）
```

### 4.5 产品形态原则

| 原则 | 说明 |
|------|------|
| 嵌入而非独立 | 不做独立 App，嵌入现有 CRM/企微工作流 |
| 推送而非搜索 | 系统主动在关键时点推送，不等销售来找 |
| 策略而非话术 | 提供"为什么做、做什么"，不提供逐字话术 |
| 建议而非指令 | 始终是"参考"，销售保留判断权 |
| 可溯源 | 每条建议可追溯到具体数据证据 |

## 5. 产品路线图

```
Phase 0 ─ 数据管道 MVP（已完成）
  ├─ 对话数据导出 & 结构化存储
  └─ 现有基建梳理（leads 特征表、行为埋点、RQI prompt）

Phase 1 ─ 标签体系 + 意向分类 + 假设验证
  ├─ 跨渠道数据串联（直播间 + 客服 + 销售三段数据打通）
  ├─ 三层标签体系构建（事实 → 行为 → 推断）
  ├─ 标签提取 Agent（对话 → 话题 → 因素 → 意向）
  ├─ 离线评估：分类准确率 & 业务一致性校验
  └─ 假设验证 1/2/3（见 04-validation.md）

Phase 2 ─ V1 落地（场景 1: 首课前策略）
  ├─ Top 经验蒸馏 Agent（离线批量）
  ├─ 策略生成 Agent（实时 RAG）
  ├─ V1 交付：跟进优先级 + 动作建议
  └─ 嵌入 CRM/企微，小范围灰度

Phase 3 ─ 服务质量评价（场景 2）+ 反馈闭环
  ├─ 关键事件识别 & 覆盖率计算
  ├─ 机会利用率 / 异议处理率
  ├─ 管理端仪表盘
  └─ 策略效果闭环 v1（显式+隐式反馈）

Phase 4 ─ 续报场景 + 归因分析（场景 3/4）
  ├─ 续报前策略（复用 Phase 2 架构）
  ├─ 服务深度建模
  ├─ PSM / 回归归因
  └─ 模型迭代闭环
```

## 6. 反馈闭环：最难也最关键的事

> 真正难的不是模型能力，而是业务反馈闭环。能闭环才能进化。

一个功能单元 = 规则 + 机器学习 + LLM，根据场景进行编排。
但如果没有闭环，系统只能靠初始设计吃老本，无法自我进化。

```
┌─────────────────────────────────────────┐
│              反馈闭环三层               │
│                                          │
│  Level 1（短期）: 销售显式反馈          │
│    策略是否被查看/采纳/有用              │
│              ↓                           │
│  Level 2（中期）: 业务结果隐式反馈      │
│    使用策略后意向是否推进/是否成交       │
│              ↓                           │
│  Level 3（长期）: 模型迭代              │
│    经验库更新 + 检索权重调优 + Prompt 优化│
│                                          │
└─────────────────────────────────────────┘
```

详见 [03-architecture.md](03-architecture.md) 反馈闭环设计章节。

## 7. 成功指标

### 产品级
| 指标 | 定义 | 目标 |
|------|------|------|
| L1→年课转化率提升 | 实验组 vs 对照组 | ≥ 2pp |
| 续报率提升 | 同上 | ≥ 1.5pp |
| 策略采纳率 | 销售查看并使用策略的比例 | ≥ 60% |
| 中腰部转化率标准差 | 排除 Top/Bottom 后的波动 | 下降 ≥ 15%（更稳定） |

### 系统级
| 指标 | 定义 | 目标 |
|------|------|------|
| 意向分类准确率 | F1-score（加权） | ≥ 0.80 |
| 标签覆盖率 | 已提取标签用户 / 全量用户 | ≥ 95% |
| 策略生成延迟 | P95 端到端延迟 | ≤ 5s |

### 组织级（长期观测）
| 指标 | 定义 | 意义 |
|------|------|------|
| 新人达标周期 | 新销售达到团队平均转化率的天数 | 系统托底能力 |
| Top-Bottom 差距收敛 | 标准化转化率的 P80/P20 比值 | 均值抬升效果 |

## 8. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 对话数据质量不稳定（ASR 错误、缺失） | 标签准确率下降 | 多源交叉校验，置信度阈值过滤 |
| 模型幻觉导致错误策略 | 销售误判用户 | 策略仅作"建议"呈现，人工兜底；定期抽检 |
| 销售不使用/不信任 AI 建议 | 产品成为摆件 | 先证明价值（A/B test），渐进式引入，嵌入而非独立 |
| "培优"而非"托底" | 只有强者更强，均值不变 | 推送而非搜索、默认呈现而非主动寻找 |
| 闭环数据积累太慢 | 系统无法进化 | Phase 2 即开始采集反馈，不等 Phase 4 |
| 隐私合规 | 对话数据处理风险 | 遵循数据最小化原则，脱敏处理 |

## 9. 历史渊源

三年前公司 AI Hackathon 的夺冠项目——《销售副驾·金点子助手》。
功能很简单：销售与用户沟通时，右侧实时弹出跟进建议和话术参考。
当时技术受限，实现得比较"画饼"，但大家对产品理念是极度认可的。

它当时已经模模糊糊指向了核心需求：**销售需要的不是事后复盘，而是实时、在线的决策支持。**

三年前画出的那张饼，正是今天 AI 该去真正烙熟的那一张。
