# htba-team 商分团队多客户端 AI 插件配套服务

> 项目入口笔记（八段概览）。技术深挖见子笔记：[[01-架构与部署]] · [[02-MCP网关与SQL安全]] · [[03-内容资产·角色包·三件套]] · [[04-反馈飞轮·内容提案]] · [[05-客户端插件与偏好同步]]

## 一句话是什么

一套让商分团队在 Claude Code / Codex 里用**自然语言**做数据分析的系统：启动时按 token 自动装载**本岗位角色包**（口径 + SQL 模板 + 方法 + 交付工作流），所有业务库查询由**单一 MCP 网关**代执行并强制表/列级权限、SQL AST 白名单与全量审计，使用中暴露的经验缺口由本地 `data-collector` 提炼成结构化候选变更回流后台，驱动角色包持续迭代。

## 场景叙事与价值

**痛点**（PRD §1.1）：① 资深商分的口径与方法学只在文档/脑子里，新人重复踩坑；② 口径变更后旧文档继续被引用，分析结果不一致；③ MySQL 账号粒度授权，缺表/列级管控与审计。

**没有它 vs 有了它**：

| 维度 | 没有它 | 有了它 |
|---|---|---|
| 口径复用 | 口径散落文档/脑中，新人问人 | 口径固化为内容资产，按岗位角色包自动下发 |
| 口径迭代 | 改文档后旧引用继续跑，结果失真 | 内容仓库「编辑即生效」+ content_hash 过时检测，运营据红点重组角色包版本 |
| 数据权限 | MySQL 账号级授权，粗放 | 网关单一出口：表/列级 ACL + 行过滤 + AST 校验 + 强制 LIMIT + 脱敏 + 审计 |
| 经验沉淀 | 靠人主动写文档 | data-collector 每轮结束把缺口提炼为候选变更，用户确认后回流飞轮 |
| 个人习惯 | 无处安放 | `preferences.md` 本地常驻，覆盖更新永不丢，可选跨端同步 |

**目标用户**：商分团队成员（业务侧、会写点 SQL）、资深商分/负责人（沉淀口径）、平台运营（1-2 人，管 token/内容/版本）、数据安全（看审计）。**初始三角色**：经营分析 / 销售运营分析 / 课导履约分析（PRD §2.1）。

## 核心功能逻辑

**三层架构**（详见 [[01-架构与部署]]）：客户端插件（薄壳 loader）→ MCP 网关（唯一数据出口）→ 平台 MySQL + 业务 DuckDB；旁挂 FastAPI + Vue3 运营后台。

主链路（用户首次使用，PRD §10.1 Flow A）：

```
OA 审批 → 运营后台建/绑 token → 客户端 token-set
 → SessionStart：bootstrap 拉角色包 + 拉全局 data-collector + 注入 system_prompt/preferences
 → 用户提问 → LLM 按 system_prompt+references+模板 → 调 MCP 工具
 → 网关：鉴权→限流→SQL AST 校验→表/列 ACL→行过滤→强制 LIMIT→执行→脱敏→审计→返回
 → 本轮结束 → data-collector 提炼候选变更 → 用户逐条确认 → 上报 / 写本地偏好
```

四条关键子系统：

1. **MCP 网关 + SQL 安全**（[[02-MCP网关与SQL安全]]）：19 个 MCP 工具，REST `/mcp/v1/{tool}` 与 JSON-RPC `/mcp/v1` 共享同一 registry；`sqlglot` AST 八层校验；列 ACL 用**黑名单**语义（`!col` 才禁）；对外还有独立的「数据应用 `/api/v1`」通道给非 AI 系统查数。
2. **内容资产 · 角色包 · 三件套**（[[03-内容资产·角色包·三件套]]）：metric/method/sql_template/system_prompt/workflow 五类**单版本**资产（`code` 唯一 + `enabled` + `content_hash`）；角色包 `compose_version` 引用资产 + 私有 `table_acl` 拼装出只读派生的 references 三件套；后台 RBAC 用权限码 + 路由级 `require_perm`。
3. **反馈飞轮**（[[04-反馈飞轮·内容提案]]）：`submit_feedback` → 反馈池 → 采纳落**素材池（FeedbackMaterial）** → 运营/skill 基于素材发起 **ChangeProposal（含 candidate/agent/human 多份 revision）** → apply 写目标资产并重算 hash → 角色包版本红点 → 重组发布。
4. **客户端插件**（[[05-客户端插件与偏好同步]]）：claude-code / codex / openclaw 三端；薄壳不含业务知识；method 脚本随角色包物化为 `.py.tpl` 由共享 invoker 执行；偏好乐观锁跨端同步；采集分 silent（模型自驱静默上报）与 interactive（`/collect` 逐条勾选）双模式。

## 方法论 · 可迁移的做法

这一段是这个项目最值得学的地方——不是「它有什么功能」，而是「它用什么套路解决了什么类问题」。

1. **单一数据出口 + 横切治理下沉到网关**：客户端**不持有任何 DB 凭证或文件访问**，所有查询走网关代执行，把鉴权/ACL/AST 校验/限流/脱敏/审计这些横切关注点集中在一处。可迁移到任何「多客户端共享受控数据源」场景——治理逻辑只写一遍、审计天然全量。（`gateway/server.py` `_auth_dep` 前置守卫；`query_service.run_guarded_select` 单一执行管道被 MCP / 对外 API / 后台试跑三条链路复用）

2. **权限用黑名单而非白名单**：授权一张表默认可查全部列，要禁列才显式写 `!col`。取舍是**降低运营配置负担**（新列自动可见，不必每加一列改 ACL），代价是需要主动维护敏感列黑名单。这是「默认开放 vs 默认封闭」的经典权衡，选了前者并用脱敏兜底。（`sql_guard.parse_denied_columns` 仅认 `!col`）

3. **防御纵深，且顺序即安全边界**：AST 校验八层有意排序——**先拦分号多语句、再拦系统库（information_schema）**，把「绕过 ACL 读元数据」堵在表 ACL 判断之前；LIMIT 表达式非字面量时**保守降级**为默认值而非放行。安全设计里「层的顺序」和「不确定时往安全侧倒」是可复用的原则。（`sql_guard.validate_sql` docstring 明列顺序）

4. **内容与引用分离，用 content_hash 做「过时」信号而非强一致**：内容资产「编辑即生效、无版本号」，角色包 compose 时把所引用资产的 `content_hash` **快照**进 manifest。二者解耦——编辑内容不会即时改变已发布角色包，但后台能实时算出「哪些版本引用了旧内容」并打红点，把「是否升级」的决策权交回运营。这是**最终一致 + 显式过时提醒**替代「改一处联动改全部」的漂亮做法。（`impact_svc._stale_reason` 四态：content_changed/disabled/deleted/missing_snapshot）

5. **派生产物只读、单一来源可回溯**：references 三件套（tables/metrics/methods.md）不是可编辑文件，而是 compose 时从内容仓库 + `table_acl` 自动拼装。杜绝了「文档与真相不一致」——想改内容必须回到源头。凡「展示层」都应是「数据层」的纯函数投影。

6. **采集飞轮拆成两阶段，中间加素材池缓冲**：反馈不直接改资产，而是「反馈池 → 采纳落素材池 → 素材发起提案 → 提案 apply 才写资产」。素材可被多个提案复用、提案可挂 candidate/agent/human 多份修订对比后再选一份合入。**把「原始信号」和「可执行改动」解耦**，让人类审核点落在最有价值的一环（选 revision + apply），而非每条原始反馈。

7. **同一份提示词/脚本，一处定义多处派生**：MCP 工具名有唯一 SoT（`htba_mcp_naming.py`，禁止散落字面量前缀）；method 脚本一份 `.py.tpl` 随角色包物化到客户端由共享 invoker 执行（LLM 不重写、避免照抄漂移）；data-collector 是全局 SystemAgent，一份 base + 各端 overlay 只改交互层。**「SoT + 派生」对抗多端一致性腐化**。

8. **让「找不到」变成硬规则而非 prompt 祈祷**：system_prompt 强制「取数前先读 metrics.md 找口径，找不到就停手 + 让 data-collector 产出缺口候选」。把「知识边界」从模糊的 prompt 工程变成**可执行的停手信号 + 采集动作**，缺口自动成为迭代输入。

9. **失败即产品输入**：网关拿到 `BACKEND_TABLE_MISSING/COLUMN_MISSING` 时自动起草 `infra_bug` 素材（带 LRU 去重防 retry 风暴、带客户端 SQL 误用过滤），不必等用户上报就让运营看到数据源漂移。**把错误信号结构化沉淀**是低成本的可观测性。

10. **薄壳 + 服务端动态下发 + 本地个人层物理隔离**：插件壳不含任何业务知识，能力由服务端按 token 动态返回；用户个人偏好 `preferences.md` 与角色包物理分离，覆盖更新永不冲掉。**「可覆盖的公共层」与「永不覆盖的个人层」分离**是配置分发的通用范式。

## 关键概念与术语表

- **角色包（role pack）**：一个商分岗位的完整能力包 = system_prompt + references 三件套 + sql_templates + methods + workflows + 私有 table_acl。
- **内容资产**：metric / method / sql_template / system_prompt / workflow 五类，**单版本**（`code` 唯一 + `enabled` 开关 + `content_hash`），编辑即生效。
- **references 三件套**：tables.md / metrics.md / methods.md，compose 时**自动派生的只读产物**，不可直接编辑。
- **content_hash / 过时引用（stale ref）**：资产规范化字段的 sha256；compose 快照进 manifest，当前 hash 与快照不一致（或资产停用/删除/无快照）即「过时」，据此提醒运营重组版本。
- **token**：一用户一 token（终身唯一），可绑 N 个角色包，OA 审批后运营手工录入。
- **pin / 版本指派**：在 `token_role_packs.pinned_version` 记某 token 应用某版本，网关拉 manifest 时 pin 优先于 current_version。
- **released（已发布）**：同一 role_pack 同一时刻仅一条 released，对全量用户生效。
- **data-collector**：全局 SystemAgent，每轮结束把经验缺口提炼为候选变更；silent（自驱静默）/ interactive（`/collect` 逐条）双模式。
- **FeedbackMaterial（素材池）**：反馈采纳后的可消费素材（available/consumed/archived），可被多个提案复用。
- **ChangeProposal（内容提案）**：锁定一个目标资产的变更草案，挂 candidate/agent/human 多份 revision，apply 时写资产并重算 hash。
- **数据应用（DataApp）**：非 AI 客户端（BI/ETL）走 `/api/v1` 只读查数的实体，与角色包解耦，凭 `dak_` 前缀 API key 调用。
- **MCP 网关**：所有业务库访问的唯一出口（业务 DuckDB read_only + 平台 MySQL），做鉴权/ACL/AST/审计。

## 上手 / 使用路径

**读代码的入口顺序**：`README.md` → `docs/PRD.md`（架构真相，任何架构变更须先改它）→ `src/htba_team/gateway/`（网关）→ `src/htba_team/admin/`（后台）→ `plugins/`（客户端壳）。

**本地起服务**（README「本地开发」）：

```bash
uv venv && source .venv/bin/activate && uv pip install -e ".[dev]"
cp deploy/config/config.dev.ini deploy/config/config.dev.secret.ini   # 填 DuckDB 路径 + 平台 MySQL
HTBA_CONFIG=deploy/config/config.dev.secret.ini alembic -c src/migrations/alembic.ini upgrade head
HTBA_CONFIG=... python -m uvicorn htba_team.gateway.server:app --reload --port 8089   # 网关
HTBA_CONFIG=... python -m uvicorn htba_team.admin.server:app  --reload --port 8090   # 后台(API+SPA)
cd src/htba_team/admin/web && npm install && npm run build       # 首次构建前端
python -m pytest -q
```

**生产**：裸机 + systemd 双进程（gateway:8089 / admin:8090），`scripts/server_bootstrap.sh` 幂等 bootstrap，`scripts/rollout.sh` 一键滚动升级（拉代码→重建→重启→健康检查，失败打印回滚命令）。

**技术栈**：Python 3.11 + FastAPI + `duckdb` + `aiomysql` + `sqlglot` + SQLAlchemy/alembic；前端 Vite + Vue 3 + Element Plus + Pinia + Monaco；客户端 Bash hooks + Python scripts + markdown skills。
