# Deka — 定义与嵌入知识对齐工作台

> 项目入口笔记（八段概览）。技术深挖见子笔记：[[01-架构与数据底座]] · [[02-四阶段方法]] · [[03-方法论·Harness与可迁移模式]]

## 一句话是什么

Deka（**De**finition and Embedding **K**nowledge **A**lignment）是一个 human-in-the-loop 工作台：领域专家只对「这段内容算不算数」下判断（FIT / NOT_FIT / DISCARD），机器负责全部检索数学（混合检索、RRF 融合、几何扩张、判据蒸馏、分类器），最终把「找像这样的内容」这个模糊意图，变成对整个向量语料库里**每一条相关 chunk 的可复现标签**。

## 场景叙事与价值

**痛点**（whitepaper §1）：作者手里有一批客服/销售对话转写语料——记录了销售如何应对砍价、如何劝续报、客户反复出现的疑虑——里面沉淀着组织的经营知识，但几乎无法利用：**量太大读不完，且是中文**。要解锁它，核心能力其实很朴素——「问一个具体问题，可靠地拿回回答这个问题的那些对话片段」。

**难点是分工不对称**：只有懂业务的领域专家能判断一个片段是否**真的**命中（renewal 决策、客户砍价的真实语气），但这个专家**不该**需要懂 cosine/inner-product、reciprocal-rank fusion、index probe width 这些检索数学。Deka 就是化解这个不对称的 harness——**机器占有机制，人占有判断**，把一小把专家裁决放大成对语料库里每条相关片段的标注。

**没有它 vs 有了它**：

| 维度 | 没有它 | 有了它 |
|---|---|---|
| 谁调检索 | 专家被迫学 cosine/RRF/probe width | 四个参数在第 1 轮锁死，专家只给内容裁决 |
| 覆盖面 | 人一轮只能读几十条，永远覆盖不了整库 | Phase 2 用 FIT 当查询把整库扫一遍 |
| 结果可信 | 一句 prompt 一次成型，无法复查 | 每轮以叙事日志落盘，session 可复现/可审计/可续跑 |
| 判据 | 只有「距离近」，说不清为什么算数 | Phase 3 蒸馏出可读、可改、可版本化的语言判据 rubric |
| 规模成本 | 全库用 LLM 逐条判，贵到离谱 | Phase 4 用逻辑回归以「一次点积/条」的成本铺满全库 |

**核心信念**（README §Learning the core idea）：*The ideas matter more than the code.* 这份仓库交付的是一个能跑的 demo，但它只是方法的一个**具体化身**；真正要读的是 whitepaper——那套把 model 和 human 编排成可靠仪器的 harness 才是贡献。

## 核心功能逻辑

**一个等式**：`Agent = Model + Harness`。大模型提供推理，但推理本身不是系统——它会漂移、编造、忘记试过什么、悄悄回答另一个问题。Harness 是模型周围让推理变可靠的一切：环境、约束、反馈、以及本该由模型脑内保存却被外化到磁盘的状态。（详见 [[03-方法论·Harness与可迁移模式]]）

**数据底座**（详见 [[01-架构与数据底座]]）：Milvus 里每行是一条对话转写的一个 chunk，带两个 BGE-M3 向量——1024 维 dense（cosine，管语义）+ learned-sparse（inner product，管口语↔正式词汇的桥接）；查询对两路同时发起，用 **reciprocal-rank fusion（RRF）** 按排名位置融合（不用原始分数，因两路分数尺度不可比）。旁挂 PostgreSQL 存 chunk 的原始整段文本，仅在人/LLM 要读上下文时查。一个 **scope 注册表**把人可读的名字映射到 `{collection, table}`，一套部署可服务多个语料。

**四阶段方法**（依次串行、每阶段可被操作者拒绝或配置关闭；只有 Phase 1 循环，详见 [[02-四阶段方法]]）：

```
模糊直觉 ──Probe──▶ 一组人工校验的 FIT/NOT_FIT 例子
        ──Harvest─▶ 一个跨全库的几何 cohort（近邻扩张）
        ──Refine──▶ 一份可读可审计的语言判据 rubric（+判过的样本）
        ──Apply───▶ 全库每条 chunk 的 KEEP/DROP 标签（廉价分类器）
```

每一步只买一样东西、付一种代价：Probe 用**人的注意力**买精度，Harvest 用**几何**买覆盖，Refine 用**一小把 LLM 调用**买可读性，Apply 用**一个廉价分类器**买规模。

## 方法论 · 可迁移的做法

以下是拿掉「销售对话」「中文」这两个具体前提后仍成立的套路（详展见 [[03-方法论·Harness与可迁移模式]]）：

1. **把人钉在「判断」上，永远不钉在「机制」上**——每一阶段专家的输入都是关于*内容*的裁决（这条算不算、这份 rubric 读着对不对、这个阈值能不能接受），从不是检索参数或数学。这是「有业务判断力但零检索背景的产品负责人」能开动整个系统的前提。
2. **偏向精度，并把犯错代价显式写出来**——从 Harvest 的「双锚点一致门」到 Apply 的「精度地板」，系统一致地偏向压制 false positive：**错收一条会污染下游所有东西，错漏一条以后还能靠更宽松的一遍捞回来**。Recall 被刻意当成更便宜的错误。
3. **锁死配置 + 叙事优于指标**——四个检索参数在第一轮开始就冻结，中途改旋钮会污染操作者正在读的信号；反思日志写成人可读的散文而非数字堆——因为没人能直读语料，累积的反思本身成了「从每个查询的角度看语料长什么样」的地图。
4. **一切外化、一切可复现**——状态以叙事日志和带版本的 artifact 存在磁盘，不在模型 context 里；rubric 盖上生成它的 meta-prompt 的 SHA-256，分类器拒绝在 rubric 漂移后的数据上运行。
5. **逐级升级，代价接力**——四阶段是一条严格前向的升级链，每阶段交给下一阶段一个更精炼的对象，且各自付一种不同的代价。人的判断只花在最前端，后面每步都在用几何/采样/点积把它「摊还」下去。

## 关键概念与术语表

| 术语 | 含义 |
|---|---|
| **Harness** | 模型周围让其推理可靠的一切：feedforward 约束、feedback 传感、外化状态。Deka 的真正贡献。 |
| **FIT / NOT_FIT / DISCARD** | 操作者对一个 chunk 的三种裁决：真命中 / 不命中 / 源头即坏（转写乱码、离题噪声，剔除以免流入后续阶段）。 |
| **hybrid / 混合检索** | dense（语义）+ learned-sparse（词汇关联）两路并行检索。 |
| **RRF（reciprocal-rank fusion）** | 融合两路排名的方法：候选融合分 = Σ 1/(k+r)，r 是它在某路里的排名，k 是平滑常数 `rrf_k`。用**排名位置**不用原始分数。 |
| **四个锁死轴** | `rrf_k` / `per_path_limit` / `top_k` / `active_paths`——Phase 1 唯一暴露且第一轮即冻结的四个参数。 |
| **三重收敛门** | Phase 1 停机条件：最新一轮 P@K ≥ 阈值 **且** 累计不同 FIT 数 ≥ 下限 **且** 累计不同 NOT_FIT 数 ≥ 下限。 |
| **span vs chunk 向量** | span 向量 `s_i` 嵌入操作者标出的概念承载片段（Phase 2 的查询起点）；chunk 向量 `c_i` 是该 FIT 在 Milvus 里被索引的向量。 |
| **T / δ_i / T'_i** | 基准半径 `T`=各 span leave-one-out 最近邻距离的 p90；per-anchor slack `δ_i`=span 到自身 chunk 的距离；有效半径 `T'_i = T + δ_i`。 |
| **anchor-frequency gate** | 一条候选只有被 ≥ f 个不同 FIT 锚点收入才保留（默认 f=2），用交集压噪。 |
| **rubric / meta-prompt** | rubric 是可移植的语言判据文档；meta-prompt 是「写 rubric 的 prompt」——让判据推导可复现，是真正的工程点。 |
| **scope** | 把人可读名字映射到 `{Milvus collection, Postgres table}` 的注册表，一套部署服务多语料。 |

## 上手 / 使用路径

**技术栈**：Python 3.11+（uv 管理）后端 FastAPI，前端 React + Vite；外部依赖 Milvus（向量库）、Embeddings 服务（产 dense+sparse）、OpenAI 兼容 LLM（reflection/rubric/judge）、PostgreSQL（可选，查原文）。

**最小跑起来**（README §Setup/Run）：

```bash
uv sync                                    # 装后端依赖
cp .env.example .env; cp config.yaml.example config.yaml   # 及 scopes/users
# 在 .env 填 OPENROUTER_API_KEY；config.yaml 指向你的 embed/milvus/postgres
# 生成登录 token 并把它的 sha256 写进 users.yaml（明文 token 只用于登录）
uv run deka-web                            # 后端 http://127.0.0.1:8787
cd web && npm install && npm run dev       # 前端 http://localhost:5173
```

- 唯一 Python 入口脚本是 `deka-web`（`pyproject.toml [project.scripts]`）。四个阶段也有 headless CLI：`python -m src.anchor <session_id>`（Phase 2）、`src.refine`（Phase 3）、`src.apply`（Phase 4）。
- **配置模板**（`*.example`，真名文件被 gitignore，缺失时 loader 回退到 example）：`config.yaml`（每阶段调参）、`scopes.yaml`（scope→collection/table）、`users.yaml`（web 鉴权）、`.env`（key/endpoint）。
- **先读 whitepaper**（README 明确建议）：`cd whitepaper && ./build.sh` 生成排版 PDF（pandoc + tectonic）；或直接读 `whitepaper/whitepaper.md`。

## 待确认与边界

- **本次萃取范围**：以 whitepaper + README + 核心 src 模块（session/anchor/apply/search）+ config + SYSTEM prompt 为主。未逐文件通读 `web/`（React 前端）、`tests/`、`src/refine` 与 `src/reflection` 的完整实现；这些层的细节以「待深挖」对待。
- **`config.yaml.example` 里的模型名**（如 `openai/gpt-5.4-mini`、`deepseek-v4-pro`、`qwen3.6-flash`）是模板占位/示例值，非硬绑定——README 与 whitepaper 都强调 embedder 与 LLM router 都是 provider-agnostic（任意 HTTP embedder + 任意 OpenAI 兼容端点）。真实部署以本地 `config.yaml` 为准。
- **worked session 的具体数字**（4 轮、32 FIT、cohort 533,595、KEEP 209,102 等，whitepaper 附录）是作者明示的**单次示例（illustration，非 benchmark）**，不能当作方法的准确率指标。
- **Deka 不是什么**（作者明示，whitepaper §5）：不是 RAG（从不让模型基于 chunk 作答，只定位+标注）；不是全自动优化器（每个关键步都要人确认）；一次只调一个查询、不做查询间排序；把 embedding 模型当固定输入、不评估替代。
- **`deka-course/`** 是从本代码库生成的交互式教学 HTML 课程（`index.html` 等），属衍生物而非核心系统；`docs/INFRA.md`（SYSTEM.md 引用的基础设施契约）在本次萃取的目录树中未见，需要 embed 端点/Milvus URI 细节时以实际仓库为准。
