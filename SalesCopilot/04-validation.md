# 假设验证方法论

---

## 验证逻辑总览

三个假设构成递进的验证链：

```
假设 1: 存在系统做功空间
  "好老师"与"差老师"对用户意向的影响差异显著
  → 证明：销售行为确实影响结果，AI 干预有意义
        ↓
假设 2: 做功价值可评估
  不同"意向阶段"和"因素组合"对转化的影响差异显著
  → 证明：AI 的标签体系能区分高/低价值用户状态
        ↓
假设 3: 可通过"副驾"干预精力分配
  前期行为对后期转化有预测能力
  → 证明：AI 可以提前识别机会，指导销售资源投入
```

**如果假设 1 不成立** → 销售行为对结果影响不大，AI 干预价值有限
**如果假设 2 不成立** → 标签体系无法有效区分状态，需要重新设计
**如果假设 3 不成立** → 前期信号对后期无预测力，"副驾"时机失效

---

## 假设 1: 好老师与差老师对用户意向的影响有很大差异

### 待证命题

> 控制用户条件后，不同销售顾问的服务行为对用户意向推进和最终转化的影响存在显著差异。

### 为什么需要验证

如果所有销售的效果差不多（即结果主要由用户自身条件决定），那么"提升服务质量"这个方向本身就没有足够的 ROI。

### 数据需求

| 数据 | 来源 | 粒度 | 时间范围 |
|------|------|------|---------|
| 用户-销售分配关系 | CRM | user × counselor | 至少 2 个完整学期 |
| 用户画像特征 | 数仓 | user 维度 | 同上 |
| Leads 评分 | Leads 模型 | user 维度 | 同上 |
| 转化结果 | 订单表 | user 维度 | 同上 |
| 销售行为数据 | 埋点 + 对话 | user × counselor | 同上 |

### 分析方法

#### 方法 A: 销售间差异分析

**Step 1: 构建"销售能力"粗排**
```
对每个销售计算：
  原始转化率 = 成交用户数 / 分配用户数

问题：原始转化率受用户质量影响，不公平
```

**Step 2: 控制用户质量后的标准化转化率**
```sql
-- 思路: 在相似用户条件下对比不同销售的转化率
-- 方法: 按用户特征分层后，计算各销售在每层的转化率

-- 用户分层维度: leads_score 分位数 × city_tier × grade_band
-- 标准化转化率 = Σ(层内转化率 × 层权重)
```

**Step 3: 统计检验**
```
H0: 控制用户条件后，各销售的转化率无显著差异
H1: 存在显著差异

方法:
  - 分层 χ² 检验（Cochran-Mantel-Haenszel test）
  - 混合效应 Logistic 回归:
      conversion ~ user_features + (1|counselor_id)
    检验 counselor_id 随机效应的方差是否显著 > 0
```

#### 方法 B: 意向推进能力差异

```
定义"意向推进率":
  对首访前为 S1/S2 的用户，首访后推进到 S3/S4 的比例

  推进率 = |{用户: S_after > S_before}| / |{用户: S_before ∈ {S1, S2}}|

在相似用户条件下对比各销售的推进率
  → 如果差异显著，说明销售行为确实影响意向流转
```

### 成功标准

| 指标 | 阈值 | 含义 |
|------|------|------|
| 销售间标准化转化率的变异系数 (CV) | > 0.15 | 存在有意义的差异 |
| 混合效应模型中 counselor 随机效应 | ICC > 0.05, p < 0.05 | 销售个体效应显著 |
| Top 20% vs Bottom 20% 标准化转化率之比 | > 1.3 | 好销售比差销售至少高 30% |

### 如果假设不成立

- 检查是否因用户分配机制（如轮流分配）导致差异被稀释
- 检查是否因样本量不足导致检验力不够
- 如果确实差异很小，考虑将产品重心从"提升个体质量"转向"流程自动化"

## 假设 2: 不同"意向"和"因素"对转化的影响差异很大

### 待证命题

> AI 提取的意向阶段（S0-S4）和因素标签（驱动/阻塞）对最终转化有显著的区分度，即标签体系具有业务价值。

### 为什么需要验证

标签体系是整个系统的基础。如果 AI 提取的标签与最终转化没有强关联，后续所有基于标签的策略和评价都没有意义。

### 数据需求

| 数据 | 来源 | 说明 |
|------|------|------|
| AI 提取的意向标签 | 标签提取 Agent 输出 | 需先完成 Phase 1 |
| AI 提取的因素标签 | 同上 | |
| 转化结果 | 订单表 | |
| 用户画像 | 数仓 | 作为控制变量 |

### 分析方法

#### 方法 A: 意向阶段与转化的关联分析

```
预期: 转化率应随意向阶段单调递增
  S0 < S1 < S2 < S3 < S4 （转化率）

验证:
  1. 计算各意向阶段的转化率 + 95% CI
  2. 趋势检验（Cochran-Armitage trend test）
  3. 计算 AUC: 用意向阶段预测转化的 ROC 曲线
```

#### 方法 B: 因素标签与转化的关联分析

```
分别分析驱动因素和阻塞因素:

驱动因素:
  - 每种驱动因素出现 vs 不出现时的转化率差异
  - 多种驱动因素叠加的效果（是否存在协同效应）
  - 排列各驱动因素对转化的边际贡献

阻塞因素:
  - 每种阻塞因素的"杀伤力"排序
  - 不同阻塞因素的"可化解性"（出现后仍能成交的比例）
  - 同时存在多种阻塞因素时的转化概率
```

#### 方法 C: 多因素 Logistic 回归

```
Model 1 (基线): conversion ~ user_features
Model 2 (加入意向): conversion ~ user_features + intent_stage
Model 3 (加入因素): conversion ~ user_features + intent_stage + factors

比较:
  - Model 2 vs Model 1: 意向阶段的增量解释力（ΔR² / ΔAIC）
  - Model 3 vs Model 2: 因素标签的增量解释力
  
  → 如果增量显著，说明标签体系提供了用户特征之外的额外信息
```

### 成功标准

| 指标 | 阈值 | 含义 |
|------|------|------|
| 意向阶段预测转化的 AUC | > 0.70 | 标签有区分度 |
| S4 vs S1 转化率之比 | > 3.0 | 阶段间差异显著 |
| Model 2 vs Model 1 的 LRT | p < 0.01 | 意向提供增量信息 |
| 至少 3 个因素标签的 OR | > 1.5 或 < 0.67 | 因素有实际影响 |

### 如果假设不成立

- 检查标签提取的准确率是否足够（F1 < 0.70 可能导致信号被噪声掩盖）
- 检查标签定义是否合理（可能需要调整分类粒度）
- 考虑是否时间窗口不对（标签提取时点 vs 转化发生时点的间隔）

## 假设 3: 前期行为对后期转化有预测能力

### 待证命题

> 用户在进班 - 首课阶段的行为特征（埋点 + 对话标签）对续报结果有预测能力，即可通过"副驾"在早期干预销售的精力分配。

### 为什么需要验证

Sales Copilot 的场景 1 在"首课前"给出建议。如果前期信号对后期结果没有预测力，那"副驾"给出的建议也没有参考价值。

### 数据需求

| 数据 | 来源 | 说明 |
|------|------|------|
| 进班 - 首课期间的行为数据 | 埋点 | 前 N 天的行为特征 |
| 进班 - 首课期间的对话标签 | 标签提取 Agent | 首课前的意向/因素 |
| 续报结果 | 订单表 | 续/未续 |
| 用户画像 | 数仓 | 控制变量 |

### 分析方法

#### 方法 A: 预测建模

```
特征集（仅使用前期数据）:
  X_user: leads_score, grade, city_tier, channel
  X_behavior: 前 7 天 [page_views, creation_count, class_attendance, parent_activity]
  X_tag: 首课前 [intent_stage, positive_factor_count, negative_factor_count]

目标:
  Y: 续报 (0/1)

模型:
  - Logistic Regression（基线，可解释）
  - XGBoost（性能上限，特征重要性）

评估:
  - 5-fold CV
  - 按时间划分 train/test（避免未来泄露）
  - 指标: AUC, Precision@K (K=分配容量)
```

#### 方法 B: 时间衰减分析

```
问题: 多早的行为仍然有预测力？

方法:
  - 分别用 [前3天, 前7天, 前14天, 前30天] 的特征建模
  - 对比各时间窗口的 AUC
  - 确定"可干预窗口"：在这个时点，预测已经足够准确，且仍有时间干预

预期:
  - AUC 随时间窗口增大而提升，但边际递减
  - 存在一个"甜点"窗口，比如首课后 7 天，已有足够信号
```

#### 方法 C: 特征重要性分析

```
目标: 识别"哪些前期信号最有预测力"

方法:
  - XGBoost 的 SHAP 值
  - 排列重要性 (permutation importance)

输出:
  - Top-10 预测特征排名
  - 每个特征的 SHAP 方向（正向/负向影响）
  → 指导"副驾"应该关注什么信号
  
预期有价值的特征:
  - 首课前的意向阶段（S3/S4 > S1/S2）
  - 家长回复响应速度（快 > 慢）
  - 体验课完课率（高 > 低）
  - 创作活跃度（多 > 少）
```

### 成功标准

| 指标 | 阈值 | 含义 |
|------|------|------|
| 前 7 天特征的 AUC | > 0.65 | 前期信号有预测力 |
| 前期特征 vs 仅用户特征的 ΔAUC | > 0.05 | 前期行为提供增量信息 |
| Precision@Top20% | > 1.5× 基线 | 前 20% 预测为"高续报"的用户，实际续报率是平均的 1.5 倍 |

### 如果假设不成立

- 可能说明续报主要由长期履约质量决定（而非前期信号），副驾的干预时点需要后移
- 检查是否因为前期数据太稀疏（如用户前 7 天几乎无行为）
- 考虑将预测目标改为"中期意向变化"而非"最终续报"

## 验证执行计划

### 优先级与依赖

```
假设 1 ─── 可立即验证（仅需历史数据，不依赖 AI 标签）
  │
  │ 通过后
  ↓
假设 3 ─── 可部分验证（用户特征+行为特征，不含 AI 标签）
  │         完整验证需等 Phase 1 完成（AI 标签提取）
  │
  │ 通过后
  ↓
假设 2 ─── 需等 Phase 1 完成（AI 标签提取后才能验证标签价值）
```

### 最小数据需求

| 假设 | 最小样本量 | 估算依据 |
|------|-----------|---------|
| 假设 1 | ≥ 30 个销售 × 每人 ≥ 50 个用户 | 检测 OR=1.3 的效应，power=0.80 |
| 假设 2 | ≥ 1000 个已标注用户 | 5 个意向阶段 × 每阶段 ≥ 200 |
| 假设 3 | ≥ 2000 个有完整前期数据的用户 | 预测建模需足够的正负样本 |

### 产出物

每个假设验证完成后，产出：
1. **分析报告**：方法、数据、结果、结论
2. **决策建议**：继续 / 调整方向 / 停止
3. **数据资产**：可复用的特征表和评估数据集
