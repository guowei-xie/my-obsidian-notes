# 四阶段管线与编排

> 子笔记 · 回 [[00-总览]]。本篇讲清「一次任务从提交到入库，逐阶段发生了什么、怎么编排、怎么断点续跑」。图谱结构与经验字段见 [[02-知识图谱与经验模型]]。

## 编排全景

`PipelineOrchestrator`（`pipeline/orchestrator.py`）在**后台守护线程**里跑完 4 个阶段（`api/routes.py` 的 `create_distill_task` 起线程，立即 202 返回 `task_id`）。每阶段结束把结果落进对应 MySQL 表，并通过 `progress_detail`（`{stage, processed, total, message}`）回写实时进度，前端轮询 `GET /tasks/{id}` 刷新。

```
run(task_id, request):
  Stage1 Fetch     → 落 distill_conversations，全文哈希去重
    ├ 去重后 0 条 → done（无新增样本）
  Stage2 KeyMoments→ 落 distill_key_moments，按阈值 retained
    ├ 无保留 → done
  Stage3 Distill   → 落 distill_distillations（LLM 萃取的 experience_json）
    ├ 无输出 → done
  Stage4 Ingest    → 落 distill_ingestions + 写 Neo4j + 写可视化 delta 表
                     批末 recompute_derived_metrics()
  → done
异常路径：TaskPaused→paused / TaskCancelled→直接返回 / 其他 Exception→failed
```

关键设计：**每个阶段都有「空结果即提前 done」的短路**，且各阶段入口先检查 DB 已产物——这既是正常流程，也是 `run_resume` 断点续跑的基础。

## Stage 1 · Fetch（拉取对话 + 全文去重）

- **拉取**：`fetch_and_store` 按 `counselor_id + user_id + 可选日期` 调对话 API（`[hetao_data].api_url`，APPCODE 认证，QPS 默认 5），把 `call`/`wechat_text`/`wechat_voice`/`wechat_meeting_voice_call` 等消息按时间排成 `[时间] 角色: 内容` 的 fulltext，写入 `distill_conversations`。`sample_id = {user_id}-{counselor_id}`。
- **全文哈希去重**（`_dedupe_conversations`）：对 `dialogue_text` 算 `sha256`（存 `dialogue_hash`），分两步过滤：
  1. **批内重复**：同一任务内 hash 相同的只留一条；
  2. **历史成功重复**：`get_successful_dialogue_hashes(hashes, exclude_task_id=task_id)` 查历史**已成功入库**的对话 hash，命中的丢弃——避免重复样本白白消耗后续 LLM/图谱处理。
- 进度 message 会明确报出「原始 N 条 / 批内重复 X / 历史重复 Y / 去重后 Z」。

## Stage 2 · KeyMoments（关键时刻筛选）

- 逐条对话调 LLM（`key_moments_v1` prompt），LLM 返回 `worth_extracting`、`experience_density`(high/medium/low)、`key_moments[]`、`overall_trajectory`。
- **阈值过滤**（`_should_retain`）：密度序 `high=0/medium=1/low=2`，保留条件 `density_rank ≤ threshold_rank` 且 `worth_extracting=true`。所以 `threshold=high` 只留 high；`medium`（默认）留 high+medium；`low` 全留。
- 结果写 `distill_key_moments`，`retained` 字段标记是否进入下一阶段。`(task_id, conversation_id)` 唯一键保证幂等。
- **容错**：LLM 失败的对话写一条 `retained=False` 的占位行（含 `_call_error`），不阻断其他对话。

## Stage 3 · Distill（经验萃取，标签受控）

这是**质量核心环节**。流程：

1. **读全局标签快照**：`build_tag_catalog(factor_rows=fetch_factor_catalog(), topics=fetch_topic_catalog())` 从 Neo4j 读一次当前所有 `Factor(name,polarity)` 与 `Topic(name)`，与内置 `DEFAULT_FACTOR_POLARITY`（8 正 + 8 负）合并，得到本任务不可变的 `TagCatalog`。
2. **注入 prompt**：`render_distill_user_prompt` 把 `{positive_factor_catalog}`/`{negative_factor_catalog}`/`{topic_catalog}`（顿号连接的词表）连同 `{key_moments}`/`{dialogue}` 填进 `experience_distillation_v1` user 模板。
3. **逐条萃取**：LLM 输出 `experiences[]` + `new_factor_labels[]` + `new_topic_labels[]`。
4. **标签一致性校验 + 修一次**（`_call_with_label_validation` → `validate_distillation_labels`）：
   - 校验每条经验用的 Factor/Topic 必须**来自快照，或已在本次 `new_*_labels` 中显式声明**（新标签须带 `reason`+`evidence`，Factor 还须 `polarity`）；
   - 空泛标签（`GENERIC_LABELS`：「其他」「话题」「因素」「未知」…）一律拒绝；
   - 不过关 → 把错误清单拼进 prompt **自动重试一次**；仍不过 → 抛 `label_validation_failed`。
   - 失败的对话写含 `_call_error` 的占位行，`experience_count=0`。
- 结果写 `distill_distillations`（整个 LLM 返回 JSON 存 `experience_json`）。

> 标签校验细节、意向阶段定义、经验字段结构见 [[02-知识图谱与经验模型]]。

## Stage 4 · Ingest（归一化 + 去重 + 图谱入库）

`IngestStage.run` 对每条 distillation 里的每条 experience 依次做：**解析 → 字段校验 → 预占位 → Approach 归一化 → 结构化去重 → 因素分类 + 边规划 → 写 Neo4j + 写可视化 delta**。返回 `{ok, failed, skipped, dedup_dropped}` 计数。

1. **解析 + 校验**：`parse_distillation_json` 跳过含 `_call_error` 的上游失败；`build_experience` 宽容映射（缺字段兜空）；`validate_experience` 强校验（类型合法、`from/to ∈ S0–S4`、`to ≥ from`、evidence 三段齐、approach 非空）。不过关 → `status="skipped"` 记原因。
2. **预占位**（`reserve_experience`）：对 `EXP-{sample_id}-{idx}` 做带 marker 的 `MERGE`，只有本次**真正新建**（`created=true`）才继续——替代逐条 existence check（免 N+1），并防止重跑时边计数重复累加。已存在则 `skipped`。
3. **Approach 归一化**（见 [[02-知识图谱与经验模型]]）：LLM 判 `matched/revise/new`，异常/空目录降级 `new`。**注意**：`example_count` 在归一化时就已自增，发生在去重闸门之前——所以即便下一步被去重丢弃，该方法的证据量仍被忠实计数。
4. **结构化去重**（`DeduplicatorState`，零 LLM）：按 `(approach_id, from_stage, to_stage)` 分桶，桶内已有经验中与当前 `factors_addressed` 的 **Jaccard 相似度 ≥ 0.5**（`factors_overlap_threshold`）的数量若已达 `max_similar_experiences`（默认 3），则丢弃当前经验（`status="skipped"`, `error_message="dedup_dropped"`, `dedup_dropped++`）。目的：保留最多 N 条相似经验维持证据多样性，又不让图谱被近似重复淹没。
5. **因素分类 + 边规划 + 写图**（`classify_factors`→`plan_edges`→`_write_to_graph`）：把因素按极性分组，按经验类型决策矩阵规划边集，写 Factor/Topic/Experience 节点与全部边；同时把子图 delta 写进 `distill_graph_nodes/edges` 供前端可视化。
6. **批末**：`recompute_derived_metrics()` 重算 `TRANSITION.success_rate`、`BLOCKS.block_strength`、`DRIVES.drive_strength`。

> ⚠️ 实际写入 DB 的 `ingestions.status` 只有 `ok/skipped/failed`（去重也是 `skipped`），**不是** `product_spec.md` 里写的 `done/deduplicated`。

## 任务状态机与断点续跑

- **状态**：`pending → running →（paused / cancelled / done / failed）`；`paused` 可 `resume` 回 `running`。
- **控制点**（`pipeline/control.py`）：`check_task_control` 在各阶段循环里被反复调用，读 DB 状态——`paused` 抛 `TaskPaused`、`cancelled` 抛 `TaskCancelled`，从而在**检查点**处优雅中断，已产结果保留。
- **恢复**（`run_resume`）：复用同一 `task_id`，靠 `count_conversations/count_key_moments/count_distillations` 判断各阶段是否已完成来跳过；MySQL 关键表用 `(task_id, conversation_id)` / `(task_id, experience_id)` 唯一键 + upsert 保证重入幂等，避免重复写入。Stage 4 因图谱写入天然幂等（见预占位）可安全重跑。
- **接口**：`POST /tasks/{id}/{pause,resume,cancel}`；`resume` 用 `resume_task_atomic` 原子切 `paused→running` 再起线程，防并发重复恢复。

## 配置与运行

- **多阶段 LLM 配置 + 继承**：`[llm.default]` 提供 `base_url/model/api_key/threads`；`[llm.key_moments]`/`[llm.distill]`/`[llm.approach_normalization]` 只需写与 default 不同的字段（如 Stage 2 用轻量模型、Stage 3 用强模型），缺失字段继承 default。
- **其他 section**：`[hetao_data]`（对话 API）、`[neo4j]`、`[mysql]`、`[server]`、`[dedup]`（`max_similar_experiences=3`、`factors_overlap_threshold=0.5`）。
- **启动**：`uvicorn src.main:app --reload`；lifespan 自动 `init_db`（MySQL 建表，幂等 + 对历史表补唯一键）与 `Neo4jWriter.init_schema`（建约束 + MERGE S0–S4 + Counter）。
- **入口**：`GET /` 返回 `static/index.html`（纯 HTML+JS 无构建）；`POST /upload`（表单 CSV，UTF-8/GBK 容错）或 `POST /distill`（JSON）建任务。
