## 系统架构总览

```
┌──────────────────────────── 应用层 ──────────────────────────────┐
│                                                                 │
│  销售端                        管理端                             │
│  ├─ 策略卡片（场景 1/3）       ├─ 质量仪表盘（场景 2）                │
│  └─ 多维表格 Demo             ├─ 归因报告（场景 4）                 │
│                              └─ 培训建议                         │
│                                                                 │
└────────────────────────────┬────────────────────────────────────┘
                             │ API
┌────────────────────────────┴──────────────────────────────────────┐
│                        智能层（Agent 编排）                         │
│                                                                   │
│  ┌─────────────┐  ┌─────────────┐  ┌──────────────┐               │
│  │ 标签提取     │  │ 经验蒸馏      │  │ 策略生成      │               │
│  │ Agent       │  │ Agent       │  │ Agent        │               │
│  │ (离线+实时)  │  │ (离线)       │  │ (实时)        │               │
│  └─────────────┘  └─────────────┘  └──────────────┘               │
│                                                                   │
└────────────────────────────┬──────────────────────────────────────┘
                             │
┌────────────────────────────┴──────────────────────────────────────┐
│                          数据层                                    │
│                                                                   │
│  MySQL          Milvus          GraphDB         Hive              │
│  ├─ 行为事实表   ├─ 对话向量      ├─ 经验图谱      ├─ 用户画像          │
│  ├─ 推断标签表   └─ 经验向量      └─ 策略关联      ├─ 行为埋点          │
│  └─ 策略推荐表                                    └─ 履约数据        │
│                                                                   │
└───────────────────────────────────────────────────────────────────┘
```

### 关键架构决策

| 决策        | 选择                     | 理由                                                            |
| --------- | ---------------------- | ------------------------------------------------------------- |
| Agent编排方式 | 顺序工作流（背景→标签→策略）        | 策略生成依赖前序背景+LLM结果                                              |
| LLM 选型策略  | 分级：高频分类用 Qwen/DeepSeek | 成本、速度、质量平衡                                                    |
| 向量检索      | Milvus                 | 寻找相似"用户背景+对话摘要"的 Top 经验                                       |
| 图存储       | GraphDB（Neo4j）         | 经验模式间的关联关系 "意向阶段→话题→因素→策略→结果（下一意向阶段）"天然是图结构，支持 GraphRAG 的多跳检索 |

## Agent 设计

### Agent 1: 标签萃取 Agent

**定位：** 运行时核心 Agent，从对话数据中提取 T3 推断标签。

```yaml
类型: 运行时 Agent（批量 + 按需触发）
输入:
  - 对话文本（结构化格式）
  - 标签体系定义（当前版本）
输出（三层结构：话题 → 因素 → 意向）:
  - 话题×因素: [{topic, factors: [{polarity, tag, proof}]}]
  - 积极因素汇总: [{tag, proof}, ...]
  - 消极因素汇总: [{tag, proof}, ...]
  - 意向分类: S0-S4 + 推导理由

处理流程:
  Step 1: 识别对话中涉及的话题
  Step 2: 在每个话题下提取积极/消极因素（附原文证据）
  Step 3: 综合所有话题×因素，推导意向阶段

Prompt 策略:
  - 结构化输出（JSON Schema 约束）
  - CoT 推理（先识别话题→再提取因素→最后推导意向）
  - 标签定义 & 示例内嵌于 System Prompt

模型选择: Qwen-Plus / DeepSeek-V3（高频调用，需控制成本）
评估方式: 经验校准 / 续报率区分度
```

完整 Prompt 见 [06-prompts.md](06-prompts.md) Prompt 1-1。

**批量 vs 按需触发：**
- **批量模式：** 每日凌晨对前一天新增对话批量处理，更新全量用户标签
- **按需模式：** 销售请求策略卡片时，作为工作流节点触发实时提取

### Agent 2: 销售经验蒸馏 Agent

**定位：** 离线批量 Agent，从 Top 销售的成功对话中提取可复用的经验、模式。

> 经验的完整定义、五种类型、萃取原则见 [05-experience-distillation.md](05-experience-distillation.md)。
> 完整的 Prompt 及执行工作流见 [06-prompts.md](06-prompts.md) Agent 2 章节。

```yaml
类型: 离线 Agent（定期批量执行）
输入:
  - 高转化对话样本集（按结果筛选：成交用户的完整对话历史）
  - 对话关联的用户特征标签+背景摘要
  - 对比组：低转化对话样本集（相似用户条件，未成交）
输出:
  - 结构化经验记录（关键时刻粒度，含情境/判断/方法/效果/证据）
  - 对比萃取洞察（成功 vs 失败的分歧点分析）

Prompt 策略:
  - 多步管线（定位→萃取→评审→归一化），分步控制质量
  - 对比分析框架（成功 vs 失败的对照）
  - CoT 深度推理

模型选择:
  - Prompt 1/3/4: Qwen-Plus / DeepSeek-V3（轻量级任务）
  - Prompt 2/5: Claude Sonnet / Opus（深度推理）
执行频率: n个月（随新成交数据积累或业务发生大幅变化）
```

**蒸馏管线（4+1 步）：**

```
Step 0: 样本筛选（代码/SQL，非 LLM）
  - 优先萃取"逆袭型"成交，销售贡献最大
  - PSM配对匹配：基于用户 特征维度（线索质量） + 首课前意向阶段
  ↓
Step 1: 关键时刻定位 [Prompt 1，轻量级]
  - 快速扫描对话，判断是否值得深度萃取
  - 标注关键时刻位置（用户态度变化点）
  - 过滤低价值对话，节省后续成本
  ↓
Step 2: 经验深度萃取 [Prompt 2，核心，见下方]
  - 对每个关键时刻做深度分析
  - 输出结构化经验记录（情境/判断/方法/效果/证据）
  ↓
Step 3: 人工审核入库
  - 5个维度评价（判断含量/可复用性/证据充分性/效果可观察性/标签准确性）
  - 经验判断 AI 结果的准确度，合格或修改后入库，不合格不入库
  ↓
Step 4: Approach 归一化 [Prompt 3]
  - 将经验中的方法描述匹配到已有 Approach 节点
  - 避免图谱节点碎片化
  ↓
Step 5（并行）: 对比萃取 [Prompt 4]
  - 成功+失败配对 → 对比分析 → 高可信度经验
  ↓
入库:
  - Milvus: 经验 embedding（向量索引）
  - GraphDB: TRANSITION/BLOCKS/DRIVES/RESOLVES/LEVERAGES 边（图索引）
```

**副产品：销售教练（模拟对练）**
```
蒸馏出的经验模式 → 可驱动一个"模拟用户"Agent
  - 模拟特定画像的家长
  - 按剧本抛出异议
  - 评价销售的应对质量（对策略的执行情况）
  → 训练新人、薄弱环节专项练习
```

### Agent 3: 策略生成 Agent

**定位：** 运行时核心 Agent，为销售实时生成个性化回访策略。

```yaml
类型: 运行时 Agent（按需触发）
输入:
  - 用户背景摘要（历史记录+渠道背景+客服沟通+问卷结果...）
  - 用户当前标签（T3: 话题×因素→意向）
  - 当前上下文摘要（首课前 / 续报前 沟通记录摘要）
输出:
  - 策略卡片（结构化 YAML/JSON）

Prompt 策略: GraphRAG（图谱查询 + 向量检索 + LLM 生成）
  - 图谱查询: 基于意向阶段和因素，查询推荐路径、化解方法、驱动方法
  - 向量检索: 补充语义相似的具体经验作为证据
  - LLM 生成: 结合图谱洞察 + 经验证据 + 用户上下文，生成个性化策略

模型选择: Qwen-Plus / DeepSeek-V3（高频调用）
```

完整 Prompt 见 [06-prompts.md](06-prompts.md) Prompt 3-1。
图谱结构（节点/边类型）与查询语句详见 [05-experience-distillation.md](05-experience-distillation.md) 3.2 节。

**GraphRAG 流程：**
```
1. 确定状态与目标
   - 当前状态: (意向阶段, 积极因素[], 消极因素[], 用户画像)
   - 目标状态: 下一个意向阶段（如 S2 → S3）
   ↓
2. 图谱查询（GraphDB）— 获取结构化洞察
   a. 路径查询:
      查询 当前阶段 → 目标阶段 的 TRANSITION（意向阶段转移）边
      → 获取: 该路径是否存在、有多少条经验支撑
   b. 阻塞分析:
      查询 用户当前消极因素 → BLOCKS（阻碍）→ 该 TRANSITION 的关系
      → 获取: 哪些因素在阻碍推进
   c. 化解方法:
      查询 RESOLVES（化解）该阻塞因素的 Approach（方法）节点
      → 获取: 推荐方法 + 各方法的经验证据数量
   d. 驱动利用:
      查询 用户当前积极因素 → DRIVES（驱动）→ 该 TRANSITION 的关系
      查询 LEVERAGES（利用）该驱动因素的 Approach（方法）节点
      → 获取: 可放大的积极信号 + 利用方法
   ↓
3. 向量检索（Milvus）— 补充具体证据
   - 从图谱查到的 Approach（方法）节点，沿 EVIDENCE_OF（证据）边找到关联经验
   - 若图谱证据不足，降级为向量检索:
     结构化过滤(from_stage（起始阶段）+ factors（因素）) + 语义排序 → Top-K 经验
   ↓
4. Context（上下文）组装
   ┌──────────────────────────────────────────────┐
   │  System Prompt: 策略生成规则 + 输出格式         │
   │                                              │
   │  用户上下文:                                   │
   │  - 背景摘要 + 当前标签萃取结果                   │
   │                                              │
   │  图谱洞察:                                     │
   │  - 推荐路径: S2→S3, 经验支撑 45 例              │
   │  - 阻塞化解: "价格敏感"→推荐方法                 │
   │    "先强化价值再谈价格"(23条经验支撑)             │
   │  - 驱动利用: "学习兴趣"→推荐方法                 │
   │    "用孩子兴趣撬动家长认同"(15条经验支撑)          │
   │                                              │
   │  参考经验（含对话原文证据）:                      │
   │  - 经验#017: S2阶段，用户嫌贵，销售...           │
   │  - 经验#042: 用户提到孩子喜欢，销售...            │
   └──────────────────────────────────────────────┘
   ↓
5. LLM 生成
   - 输出结构化策略卡片
   ↓
6. 后处理
   - 格式校验
   - 写入策略推荐表
   - 推送至销售端
```

**降级策略：**
```
图谱数据充足 → 完整 GraphRAG 流程（图谱洞察 + 经验证据）
图谱数据稀疏 → 降级为向量检索 RAG（跳过步骤 2，直接走步骤 3 向量检索）
向量检索也无结果 → 返回基于标签组合的模板策略
```

## 反馈闭环设计

> **真正难的不是模型能力，而是业务反馈闭环。**
> 如果没有闭环，系统只能靠初始设计吃老本，无法自我进化。

### 为什么需要闭环

```
没有闭环:
  蒸馏经验 → 生成策略 → 销售使用 → ???
  （不知道策略好不好，模型不会进步，最终沦为"摆件"）

有闭环:
  蒸馏经验 → 生成策略 → 销售使用 → 追踪结果 → 评估效果 → 优化模型
  （策略质量持续提升，系统越用越准）
```

**闭环的关键挑战：**
- 奖励信号滞后：成交周期长（1~2周），策略→结果的因果链很长
- 归因困难：用户转化是多因素共同作用，难以归因到单一策略

**应对策略：**
- 不等最终转化，先用"意向阶段变化"作为近端奖励信号（中间指标）
- 落地初期即开始采集反馈数据，不等闭环成熟才建
- 初期以"A/B 对比 + 人工评审"替代自动化评估

### 三层反馈机制

#### Level 1: 显式反馈（短期）

```
触发: 销售使用策略后
采集:
  - 是否查看了策略卡片 → was_viewed
  - 是否采纳了策略建议 → was_applied
  - 主观评价（有用/没用/部分有用）→ counselor_feedback
价值: 快速迭代策略呈现方式、过滤低质量策略
```

#### Level 2: 隐式反馈（中期）

```
触发: 用户阶段发生变化 / 成交 / 流失
采集:
  - 策略生成后，用户意向是否按预期方向流转
  - 使用了策略的用户 vs 未使用策略的用户，转化差异
  - 同一策略在不同销售手中的效果差异
价值: 评估策略的实际业务效果
```

#### Level 3: 模型迭代（长期）

```
触发: 积累足够 (策略, 上下文, 结果) 三元组后
动作:
  1. 经验库更新: 将新的成功案例纳入蒸馏，淘汰效果差的旧模式
  2. 检索权重调整: 效果好的经验模式提升检索权重
  3. Prompt 优化: 基于效果数据调优 Agent Prompt
  4. 评估基准更新: 用最新标注数据更新评估集
```

### 闭环数据流

```
策略推荐表                      推断标签表（前后对比）
  ├─ strategy_id               ├─ 策略前 intent_stage
  ├─ was_viewed                ├─ 策略后 intent_stage（Δ）
  ├─ was_applied               └─ 结果标签 (converted/not)
  └─ counselor_feedback
           │                           │
           └───────────┬───────────────┘
                       ↓
              策略效果评估样本
              (strategy_id, context, action, outcome)
                       │
           ┌───────────┴───────────┐
           ↓                       ↓
    经验库更新                Prompt/检索优化
    (Milvus 向量权重)        (A/B test 验证)
```

## 集成架构

### 与现有系统的集成

| 系统 | 集成方式 | 数据流向 |
|------|---------|---------|
| CRM | API 嵌入策略卡片 | Sales Copilot → CRM（推送策略） |
| 企业微信 / IM | 侧边栏或消息卡片 | Sales Copilot → IM（展示策略） |
| 对话系统 | API 拉取对话记录 | 对话系统 → Sales Copilot |
| 数据仓库（Hive） | 批量 ETL | Hive → Sales Copilot（用户特征） |
| 埋点平台（Sensors） | 批量 ETL | Sensors → Sales Copilot（行为数据） |

### 部署架构

```
┌─ 定时任务 ─────────────────────────────────┐
│  Cron: 每日凌晨                            │
│  ├─ 批量标签提取（全量用户 T3 标签快照）       │
│  └─ 特征/行为刷新（T1/T2 标签更新）           │
│                                           │
│  Cron: 每月                               │
│  └─ 经验蒸馏（新增样本）                     │
└───────────────────────────────────────────┘

┌─ 实时服务 ───────────────────────────────────┐
│  API: /api/strategy/{counselor_id,user_id}  │
│  ├─ 检查标签是否过期(是否有新增对话)             │
│  ├─ 过期则触发实时标签提取                      │
│  ├─ GraphRAG 检索 + 策略生成                  │
│  └─ 返回策略卡片                              │
└─────────────────────────────────────────────┘
```
