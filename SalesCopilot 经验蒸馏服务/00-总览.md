> 项目入口笔记（八段概览）。技术深挖见子笔记：[[01-四阶段管线与编排]] · [[02-知识图谱与经验模型]] · [[03-方法论·可迁移模式]]

## 一句话是什么

SalesCopilot-Distill 是一条**销售对话经验蒸馏管线**，封装成一个带前端页面的 FastAPI 服务：你提交一批「班主任 × 家长」的会话样本，它自动拉取对话全文、用 LLM 筛出有价值的对话、从中萃取结构化的「销售经验」，再把这些经验归一化、去重后写进 Neo4j 知识图谱，供下游做情境推荐、归因、路径分析。

## 场景叙事与价值

**问题**：优秀班主任（销售）促成转化的「话术判断」散落在成千上万条聊天记录里，无法沉淀、无法复用、无法教给新人。人工复盘一次只能看几十条对话，且口径不一、无法结构化检索。

**这个服务把复盘工业化**：从原始对话到一张「什么情境下、用户处于哪个意向阶段、遇到什么阻碍因素、销售用了什么方法、效果如何」的知识图谱，全自动、可追溯、可增量累积。

**它是一次重写**。同名前身项目 `SalesCopilot`（原项目）以「多脚本 + CSV 中间文件 + 人工审核」运行，痛点集中在：CSV 特殊字符解析错、LLM 非 JSON 输出无防御、以及**图谱里大量孤立 Factor 节点**（LLM 把「场景全景因素」和「本条经验实际处理的因素」填得不一致）。本服务的重写主线就是解决这三件事：CSV → MySQL、防御式 JSON 解析、以及从 prompt 与图谱构建两端根治孤立节点。差异全表见 [[02-知识图谱与经验模型]]。

**没有它 vs 有了它**：

| 维度 | 没有它（人工复盘 / 原脚本项目） | 有了它 |
|---|---|---|
| 中间态 | CSV 文件，特殊字符易解析错 | MySQL 逐阶段落表，可查、可断点续跑 |
| 执行 | 多脚本分步 + 人工审核 | 一次提交，后台线程全自动跑完 4 阶段 |
| 标签口径 | 每次 LLM 自由发挥，用词漂移 | 每任务从图谱读一次全局标签快照注入 prompt，沿用优先 + 新标签须声明 |
| 图谱质量 | 大量孤立 Factor 节点 | Factor 只从「实际处理的因素」建，天然有边 |
| 去重 | 无 | 同方法 + 同阶段路径 + 因素重叠下最多留 N 条，零额外 LLM |
| 可运维 | 无 | 暂停 / 恢复 / 取消 + 断点续跑 + 实时进度轮询 |

## 核心功能逻辑

**一条四阶段管线**，由后台线程编排器（`pipeline/orchestrator.py`）串起，逐阶段把结果落进 MySQL，最终写入 Neo4j（详见 [[01-四阶段管线与编排]]）：

```
提交样本(CSV/JSON)
  │
[Stage 1 Fetch]      调对话 API 拉全文 → 组装 fulltext → 存 MySQL
  │                  └ 完成后按 sha256 全文哈希去重（批内重复 + 历史成功重复）
[Stage 2 KeyMoments] LLM 判每条对话的关键时刻密度(high/medium/low) → 按阈值过滤
  │
[Stage 3 Distill]    先从 Neo4j 读全局 Factor/Topic 标签快照注入 prompt
  │                  LLM 逐条萃取结构化经验 → 标签一致性校验(不过关自动修一次)
[Stage 4 Ingest]     校验 → Approach 归一化(matched/revise/new) → 结构化去重
                     → 因素分类 + 边规划 → 写 Neo4j → 批末重算派生指标
```

- **输入→输出主链**：`{counselor_id, user_id, 日期范围}` → 对话全文 → 关键时刻标注 → 若干条 `Experience`（结构化经验）→ 图谱中的 `Experience`/`Approach`/`Factor`/`Topic`/`IntentStage` 节点与关系。
- **意向阶段 S0–S4**：贯穿全程的核心坐标系（S0 流失 → S4 强购买意愿）。每条经验都带 `from_stage → to_stage`，图谱的 `TRANSITION` 边即阶段跃迁。见 [[02-知识图谱与经验模型]]。
- **可运维**：任务状态机 `pending/running/paused/cancelled/done/failed`；`resume` 复用同一 `task_id`，靠 MySQL 已产物跳过已完成阶段从断点续跑。

## 方法论 · 可迁移的做法

这个项目最值得学的，是**在一条「LLM 深度参与」的数据管线里，如何把「LLM 该干的」和「程序该管的」切干净**——LLM 负责理解与生成，程序负责一致性、幂等、去重与图谱结构。核心套路（展开见 [[03-方法论·可迁移模式]]）：

1. **全局标签快照 + 沿用优先 + 新标签须举证**：用「受控词表」驯服 LLM 的用词漂移，让萃取结果跨任务可累积、可检索。
2. **结构化零成本去重**：用 `(方法, 阶段路径)` 分桶 + 因素集合 Jaccard 相似度做去重，完全不额外调 LLM。
3. **确定性 ID + 预占位 MERGE 保幂等**：`EXP-{sample_id}-{idx}` + Neo4j marker 预占位，让整条管线可安全重跑、可断点续跑。
4. **图谱边由「类型决策矩阵」生成，而非让 LLM 直接吐边**：LLM 只产语义字段，边的拓扑由确定性规则算，杜绝孤立节点。
5. **分层防御 + 单条失败不阻断整批**：LLM→LLM 环节宽容传递，LLM→程序环节严格校验；任务级 / 样本级 / 经验级三级容错。

## 关键概念与术语表

| 术语 | 含义 |
|---|---|
| 关键时刻 (Key Moment) | 对话中用户态度/意愿/认知发生**可观察变化**的节点；非 SOP、非纯信息传递 |
| 经验 (Experience) | 从一个关键时刻抽象出的结构化、可复用销售经验（情境+判断+执行+证据+检索标签） |
| 意向阶段 (IntentStage, S0–S4) | 用户购买意向 5 级：S0 暂缓/流失、S1 沉默、S2 需求模糊、S3 需求明确、S4 强购买意愿 |
| Factor（因素） | 影响转化的正/负面因素（如「价格敏感」负、「学习兴趣」正），带 `polarity` |
| Approach（方法） | 归一化后的销售方法/策略，图谱中的独立节点，`APR-{seq:04d}`，带 `example_count` |
| Topic（话题） | 经验涉及的话题标签（如「价格」「课程效果」） |
| experience_density | 一条对话关键时刻的密度评级 high/medium/low，Stage 2 用于阈值过滤 |
| sample_id | 样本标识，格式 `{user_id}-{counselor_id}` |
| 标签快照 (TagCatalog) | 每任务从 Neo4j 读一次的全局 Factor/Topic 全集 + 默认因素表，注入 Stage 3 prompt |

## 上手 / 使用路径

- **入口**：`src/main.py`（FastAPI app + lifespan 自动建 MySQL 表 / 初始化 Neo4j schema）。
- **跑起来**：`pip install -r requirements.txt` → `cp config.ini.example config.ini` 填 `[hetao_data]/[llm.*]/[neo4j]/[mysql]` → 建 MySQL 库 → `uvicorn src.main:app --reload` → 访问 `http://localhost:8000`。
- **最小用法**：前端上传 CSV（列 `user_id,counselor_id,start_date?,end_date?`）选阈值提交；或 `POST /distill` 传 JSON。轮询 `GET /tasks/{id}` 看进度，`done` 时返回汇总统计。
- **环境要求**：Python ≥ 3.11、MySQL、Neo4j；需网络可达对话 API 与 LLM 网关。
- 详见 [[01-四阶段管线与编排]] 的「配置与运行」。
