# 内容资产 · 角色包 · 三件套

> 子笔记，回链 [[00-总览]]。平台元数据 schema 名 `htba_team`；类型/约束以 `src/htba_team/common/models.py` 为准。

## 内容仓库：单一来源 + 覆盖优先级

**规则**（PRD §8.0）：

1. 任何字段/口径/方法的新增修改启停**只能发生在内容仓库**
2. 角色包新版本只能引用 `enabled=true` 的资产 code（`role_pack_svc._load_enabled` 提前失败，停用资产报 `ASSET_DISABLED 422`）
3. `table_acl` 是角色包**私有**，不进内容仓库
4. 工作流升级为独立资产 `htba_team_workflows`，与 metric/method/sql_template 同构
5. 三件套由 `compose_version` 在事务内拼装，前后台**不允许直接编辑**
6. compose 时把每个引用资产的 `content_hash` 写入 `manifest.asset_hashes`

## 五类内容资产（单版本对称）

统一约定：`code` 唯一 + `enabled` 停用位 + `content_hash` + `updated_at`；**无 draft/active/archived 三态、无版本号，编辑即生效**。

| 资产 | 表 | 关键字段 |
|---|---|---|
| **metric 指标** | `htba_team_metric_defs` | `code / name / definition(必填) / unit / drilldown_dims(JSON) / description / enabled / content_hash` |
| **method 方法** | `htba_team_method_defs` | `code / name / description(语义正文,必填)` + 可执行脚本三件套 `script_example(MEDIUMTEXT) / script_recommended_deps / params_schema(JSON [{name,type,description,required?}])` |
| **sql_template** | `htba_team_sql_templates` | `code / name / sql(MEDIUMTEXT) / params_schema(JSON) / owner / description / enabled / content_hash` |
| **system_prompt** | `htba_team_system_prompts` | `code / name / content(MEDIUMTEXT)`；与角色包一对一 `code={role_pack_code}__system_prompt`；全局提示词固定 code `__platform_global__system_prompt` |
| **workflow** | `htba_team_workflows` | `code / name / workflow_md(MEDIUMTEXT) / contract(JSON) / enabled / content_hash`；命名 `{role_pack_code}__{workflow_code}` |

表元数据 `tables_meta`（`name PK / schema_name / columns_json / owner / sensitivity(public/internal/sensitive) / description`）**无 content_hash**，不入过时检测。

## 角色包与 compose

**表结构**：`role_packs`（`code / name / current_version / status(draft/active/archived)`）；`role_pack_versions`（`role_pack_id / version / manifest_json / checksum / status(draft/released) / change_summary / released_at / ever_released_at`）；`token_role_packs`（PK `(token_id, role_pack_id)` + `pinned_version`）。

**compose_version**（`role_pack_svc.py:304-349`）拼装 `manifest_json`（初始 draft）：

```
_build_manifest（role_pack_svc.py:198-279）
  ├─ 加载 enabled 资产（缺失/停用即 404/422）
  ├─ system_prompt：平台全局段 prepend + 角色 system_prompt
  ├─ references 三件套自动派生（只读）：
  │    tables.md  ← tables_meta × table_acl.allowed_columns（每包私有）
  │    metrics.md ← metric_defs[enabled where code in metric_codes]
  │    methods.md ← method_defs[enabled where code in method_codes]
  ├─ sql_templates / methods / workflows（含 contract 快照）
  ├─ table_acl（替换式写入 htba_team_table_acl）
  └─ asset_hashes：每个引用资产的 content_hash 快照（供过时检测）
checksum = sha256:<hex>
```

**版本生命周期**：

- release：同一 pack 至多一条 released，切换时旧 released 自动回落 draft；首发写 `ever_released_at`、pack 置 active（`role_pack_svc.py:387-445`）。
- pin：`replace_version_assignment` 全量替换 `token_role_packs.pinned_version`；网关拉 manifest 时 **pinned 优先于 current_version**（`gateway/role_pack.fetch_manifest_for`）。
- `ever_released_at` 非空 = 「曾被外部看见」→ 编辑必须 fork 新版本；未 released 的 draft 支持**原地 PATCH 覆盖**，避免草稿期堆版本。
- 归档/删除守护：active 或有 released 版本或有绑定 token 时拒绝。

**角色包运营（operator）**：`htba_team_role_pack_operators` 一包一人（role_pack_id PK）、一人一包（admin_user_id UNIQUE）；绑定时自动挂载内置「角色运营」后台角色并对齐权限码，解绑自动卸载。

## content_hash 过时检测（编辑即生效的代价补偿）

- **计算** `content_svc.hash_for`（`content_svc.py:96-125`）：dict 字段顺序无关、list 顺序敏感、None 与缺省归一；**description 不入 hash（method 除外）**——它是后加的非语义元信息，入 hash 会让存量版本升级当天全被打 stale。
- **快照**：compose 把引用资产 hash 写 `manifest.asset_hashes[kind][code]`。
- **stale 判定** `impact_svc._stale_reason`（`impact_svc.py:73-82`）四态：
  - `content_changed`：当前 hash ≠ manifest 快照
  - `disabled`：资产已停用
  - `deleted`：资产已删
  - `missing_snapshot`：老 manifest 缺 `asset_hashes`
- 资产列表 `stale_ref_count`、资产详情 `references[].is_stale`、`/content-changes` 全景、角色包版本红点均为**实时扫描的派生数据**，无持久化日志。table_doc 不入 stale（无 hash 快照）。

## 后台 RBAC

- **无密码，纯飞书 OAuth**：`admin_users`（`username / display_name / lark_open_id/union_id/email / is_super / status`，`password_hash` 恒 NULL）；`admin_tokens`（`token_hash / admin_user_id / kind(session/pat) / expires_at / status`，session=飞书回调短期签发、pat=手动长期可撤销）。
- **权限码** `common/permissions.py` `ALL_PERMISSIONS`：12 模块 × read/write（`tokens/role_packs/system_agents/tables/content_assets/feedback/feedback_materials/change_proposals/plugin_builds/admin_users/admin_roles/data_apps`）+ 独立只读码 `duckdb.query`（业务库探查，比 tables.read 危险故单授）、`audit.read`、`user_preferences.read`。权限码为**应用侧常量不入库**，写入前白名单校验。
- **鉴权** `admin/auth.py`：`Authorization: Bearer <token>` → 查 active token → 载 active AdminUser → 聚合角色权限；超管（`is_super=1` 或 open_id 命中 `config.lark.super_open_ids`）直填全集；`require_perm(*codes)` 工厂超管 bypass、命中任意码通过；principal 进程内缓存 TTL 60s。
- **数据域**：`AdminPrincipal.scoped_role_pack_id`——超管恒全量，角色运营严格限本角色包；NULL 老数据仅全量视角可见。

## 后台模块与前端

后端 20 个 router 挂 `/admin/api/v1/*`，各自带 `require_perm`。前端 Vite+Vue3+Element Plus+Pinia+Monaco+markdown-it，按业务域分组：看板 / 访问治理（Token·角色包·数据应用·全局 Agent）/ 内容资产（表元数据 + 五类资产各含归档视图）/ 运营（反馈池·素材池·提案池·审计·用户偏好）/ 发布（插件打包）/ 系统（后台用户/角色）。命令面板用 fuse.js 模糊搜索 + 直跳前缀（`fb:123 / prop:456 / mat:789 / m:dau / sql:retention`）。

## 关键流程：商分专家迭代口径（PRD §10.2 Flow B）

```
后台 PATCH「新用户」口径 → content_svc 重算 content_hash（即生效）
 → /content-changes 实时扫描：某些角色包版本 manifest 快照不再匹配 → 列「过时引用」
 → 资产页 + 版本列表出红点
 → 运营撰写 role_pack_versions 新版本 vN（draft，compose 校验 enabled + 写最新 hash 快照）
 → (可选) PUT assignment 指派 1-2 个内部验证 token 到 vN
 → 看 audit_log 调用量 + 反馈池信号
 → 「设为发布中」：vN released，旧 released 自动回 draft，current_version 切 vN
 → 持有该角色 token 的用户下次启动自动拉 vN（被 pin 的仍以 pinned_version 为准；preferences 不受影响）
```

回滚（Flow D）：对上一稳定版本点「设为发布中」即自动把异常版本改回 draft。
