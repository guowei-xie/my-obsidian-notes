## 场景 1：首课前 — 意向分类 + 策略生成（服务于销售个体）

### 触发时机

销售在首课电访前，系统自动完成意向分析并生成策略卡片。

### 处理流程

```
用户数据（用户背景摘要 + 对话记录）
  ↓
Step 0: 组织记忆聚合 - 背景摘要
  ├─ 渠道来源：直播间内容/卖点/承诺
  ├─ 客服记录：问卷结果、初始诉求
  ├─ 往期记录（如有）：关键事件摘要
  └─ 销售对话：进班后的沟通
  ↓
Step 1: 标签提取
  └─ 推断标签：AI 从全链路对话中抽取
  ↓
Step 2: 话题识别（在聊什么）
  ↓
Step 3: 因素提取（每个话题下的积极/消极信号）
  ↓
Step 4: 意向推导（由话题×因素综合推导 → S0-S4）
  ↓
Step 5: 策略生成（Top 经验 + 用户上下文）
  ↓
输出：策略卡片 → 销售端
```

### 标签提取的三层结构：话题 → 因素 → 意向

意向不是独立判定的标签，而是**从话题和因素中推导出来的结论**。

```
对话文本
  ↓
话题识别（在聊什么）: 学习情况、课程方案、价格费用...
  ↓
因素提取（信号是正是负）: 每个话题下的积极/消极信号 + 原文证据
  ↓
意向推导（综合判定）: 话题×因素组合 → S0-S4
```

**示例推导链：**
```
话题: 学习情况     → 积极因素: "孩子数学不错，喜欢编程"（学习兴趣）
话题: 价格费用     → 积极因素: "这个课多少钱？"（主动询价）
话题: 时间安排     → 消极因素: "周末排得太满了"（时间冲突）
───────────────────────────────────────────────────────
综合: 积极因素主导 + 出现询价信号 → S3（需求明确），趋向 S4
```

### 意向分类体系

不是简单的 ABCD 等级评分，而是**阶段序列**，支持排序 + 流转（状态机）。
每个阶段的判定都可追溯到具体的话题×因素证据链。

| 阶段     | 定义      | 推导逻辑             | 典型话题×因素组合               |
| ------ | ------- | ---------------- | ----------------------- |
| **S0** | 暂缓 / 流失 | 明确拒绝信号，消极因素压倒性主导 | 决策过程×"不需要" / 孩子兴趣×"不想学" |
| **S1** | 沉默用户    | 无话题交集，或无因素信号     | 无实质对话 / 仅"嗯""好的"        |
| **S2** | 需求模糊    | 有话题但弱积极，未形成方向    | 学习情况×"随便看看" / 课程了解×被动回应 |
| **S3** | 需求明确    | 多话题积极因素主导，主动表达   | 学习目标×目标明确 + 课程了解×主动咨询   |
| **S4** | 强购买意愿   | 出现强购买信号          | 价格费用×主动询价 + 时间安排×主动约课   |

**状态流转规则：**

```                            
S0 ←── S1 ──→ S2 ──→ S3 ──→ S4              
 ↑      ↑      ↑      ↑      │              
 └──────┴──────┴──────┴──────┘              
       （任意阶段可回退至 S0）                 
                                            
S4 ──→ 成交 ──→ 退出状态机                    
S0 ──→ 多次确认 ──→ 标记流失 ──→ 退出          
```

**关键特性：**
- 有序：S1 < S2 < S3 < S4，可排序，支持"优先联系高意向用户"
- 可流转：用户状态会随新信息更新，不是一次性判定 （依触发阶段而定）
- 可解释：每次分类附带具体证据（对话 + 行为 + 推导）

### 因素分析

对意向分类的**原因**进行结构化推理，分为驱动因素和阻塞因素：

> 以下仅作示意
#### 驱动因素（推动意向前进）

| 因素类型 | 示例                | 信号强度 |
| ---- | ----------------- | ---- |
| 目标驱动 | 考试/升学/比赛（信奥、蓝桥杯）  | 强    |
| 痛点明确 | "孩子数学不好"、"逻辑能力差"  | 强    |
| 时间窗口 | "暑假想报个班"、"下学期想开始" | 中    |
| 主动行为 | 问价、约补课、主动加微信      | 强    |
| 社交背书 | "朋友家孩子也在学"、"老师推荐" | 中    |
| 孩子兴趣 | "孩子很喜欢这个课"        | 中    |

#### 阻塞因素（阻碍意向推进）

| 因素类型 | 示例 | 化解难度 |
|---------|------|---------|
| 价格敏感 | "太贵了"、"能不能便宜点" | 中 |
| 决策权模糊 | "等孩子他爸回来再说"、"我做不了主" | 中 |
| 时间冲突 | "时间安排不过来"、"太忙了" | 低 |
| 信任/效果怀疑 | "学了有用吗"、"能出什么成绩" | 高 |
| 外部条件 | 设备不满足、网络环境差 | 低 |
| 竞品比较 | "在看其他机构"、"XX 也不错" | 高 |
| 年龄/阶段顾虑 | "孩子太小了"、"现在学会不会太早" | 中 |

### 策略生成

**核心理念：不提供话术（或物料），提供策略。**

策略 = （"用户行为" + "沟通记录"） x "Top 经验蒸馏"

#### 策略卡片结构

> 以下仅作为结构示意：

```yaml
用户概要:
  基本信息: "XX市，X年级，首次体验课"
  当前意向: S2（需求模糊）
  关键标签: [社交背书, 孩子有兴趣, 时间冲突]

意向推进目标: S2 → S3（需求模糊 → 需求明确）

关键问题:
  - 用户尚未建立"课程方案 ↔ 学习目标"的明确关联
  - 尚未进入价格/决策信息阶段

驱动因素（可放大）:
  - 社交背书: "朋友家孩子也在学"
  - 孩子兴趣: 体验课参与度高（完课率 100%，作品提交 2 次）

阻塞因素（需化解）:
  - 时间冲突: "周末排满了"

行动路径:
  步骤1 - 强化需求绑定:
    做什么: 明确用户目标与编程之间的对应关系
    为什么: 用户有模糊需求但未关联到具体课程价值
    参考: Top销售在此阶段会先聊孩子的具体情况，不急于介绍课程

  步骤2 - 引导方案对比:
    做什么: 提供不同课程/路径的对比，帮助用户形成选择框架
    为什么: 让用户从"要不要学"转变为"选哪个学"
    参考: 给出2-3个适配方案，降低决策复杂度

  步骤3 - 化解时间阻塞:
    做什么: 提供灵活的时间方案（录播补课、调班）
    为什么: 时间冲突是最易化解的阻塞因素
    时机: 在需求明确后再提，避免过早暴露"在推销"

  步骤4 - 引导进入决策信息:
    做什么: 在方案明确后，自然引入价格、时间安排等信息
    为什么: 此时用户已有倾向，价格信息是推进而非阻碍

执行约束:
  - 避免过早直接报价
  - 避免继续泛介绍课程信息
  - 不要跳过决策人确认
  - 不要死板发送 SOP 模板消息
```

### 数据输入

> AI 拥有的上下文信息

| 数据源      | 内容                     | 用途             |
| -------- | ---------------------- | -------------- |
| 用户画像     | 城市、年级、设备、渠道来源          | 基础特征           |
| Leads 评分 | 历史模型打分                 | 先验意向参考         |
| 行为埋点     | 页面浏览、创作行为、课程进度、完课率、出勤等 | 行为特征 + 用户投入度   |
| 渠道/直播间数据 | 来源直播间、直播内容摘要、卖点/承诺     | 渠道上下文，理解用户预期   |
| 客服沟通记录   | 问卷结果、初步沟通内容、用户初始诉求     | 前置需求信号         |
| 往期体验记录   | 历次体验的对话、意向、阻塞因素、流失原因   | 知道上次卡在哪，直接解决问题 |
| 销售对话记录   | 微信/IM/电话（进班后）          | 推断标签的核心来源      |

### 组织记忆在策略生成中的应用

> "组织对用户的记忆"的概念与动机见 [00-overview.md](00-overview.md) 产品定义章节。以下聚焦其在策略生成中的具体落地。

**示例：重复体验用户的策略差异**
```yaml
往期记录:
  上次体验: 2025年寒假，意向达到S3，最终未转化
  流失原因: 时间冲突（周末排满），价格未进入讨论
  上次销售备注: "家长认可课程，但排课问题没解决"
本次渠道背景:
  来源: "XX老师信奥专场直播"
  直播卖点: 信奥赛升学加分 + 暑假集训营
客服记录:
  问卷: 五年级，有Scratch基础
  初始诉求: "想让孩子系统学一下"
策略要点:
  - 上次已认可课程价值，不需要重新建立认知
  - 核心问题是时间安排，优先提供灵活排课方案
  - 承接直播间信奥卖点，强化"现在开始→信奥路径"的紧迫性
  - 直接从方案推荐切入，跳过需求挖掘阶段
```

有组织记忆 vs 无组织记忆，策略生成的起点完全不同：无记忆时从 S1 破冰开始；有记忆时直接从上次断点继续推进。

## 场景 2：首课后 — 服务质量评价（服务于销售管理）

### 触发时机

首课电访完成后，系统对销售的沟通过程进行多维度质量评价。

### 评价维度

#### 维度 1：关键事件（话题）覆盖率

**定义：** 销售是否做了在当前阶段"该做的事"。

**核心公式：**
```
覆盖率 = Σ(已发生事件 × 权重) / Σ(应发生事件 × 权重)
```

"应发生"取决于用户当前的**履约 + 意向**阶段。

**关键事件清单（示例）：**

| 关键事件（话题） | 触发条件   | 权重  | 识别方式            |
| -------- | ------ | --- | --------------- |
| 了解孩子学习情况 | 所有用户   | 高   | 对话中提及成绩/学习习惯/年级 |
| 了解学习目标   | 所有用户   | 高   | 对话中提及目标/期望/为什么学 |
| 反馈课堂表现   | 已完成首课  | 高   | 对话中提及课堂表现/老师评价  |
| 介绍课程方案   | S2 及以上 | 中   | 对话中提及课程内容/路径    |
| 了解时间安排   | S2 及以上 | 中   | 对话中提及时间/排课      |
| 确认决策人    | S3 及以上 | 高   | 对话中确认"谁来决定"     |
| 推进成交     | S4     | 高   | 对话中提及报名/付款方式    |

**关键特性：**
- 事件有权重：不是简单的"做了/没做"计数
- "应发生"是动态的：不同意向阶段，应做的事不同
- 识别基于对话分析：AI 从对话中判断事件是否发生

#### 维度 2：意向构成分析

**定义：** 首轮电访后，该销售所服务用户的意向分布。

```
示例输出:
  销售A 首访后意向分布:
    S0 (流失):     5%   ← 关注：是否可挽回？
    S1 (沉默):    15%   ← 关注：是否尝试了破冰？
    S2 (需求模糊): 40%   ← 正常
    S3 (需求明确): 30%   ← 好
    S4 (强意愿):   10%   ← 优秀
```

**分析价值：**
- 对比不同销售的意向分布差异
- 结合用户进班时的初始条件（leads 评分、渠道来源），评估销售的"推进能力"
- 追踪意向分布随时间的变化趋势

#### 维度 3：因素构成分析

**定义：** 对暂缓/流失类用户，阻塞因素的构成分析。

```
示例输出:
  销售A 的 S0/S1 用户阻塞因素分布:
    价格敏感:    35%
    决策权模糊:  25%
    信任怀疑:    20%
    时间冲突:    15%
    其他:        5%
```

**分析价值：**
- 如果某销售的流失用户大量集中在"信任怀疑" → 培训方向：加强价值传递能力
- 如果团队整体"决策权模糊"占比高 → 流程优化：在首访中增加"决策人确认"环节
- 针对性指导，而非泛泛"加强沟通"

#### 维度 4：机会利用率 / 异议处理率

**定义：** 用户发出关键信号后，销售是否"接住了"。

**信号分类：**

| 类型 | 信号示例 | 期望响应 |
|------|---------|---------|
| 正向信号 | 问价、约课、问报名方式 | 及时推进成交流程 |
| 负向信号（异议） | "太贵了"、"没时间"、"再看看" | 识别 → 回应 → 化解 |

**机会利用率：**
```
机会利用率 = 被响应的正向信号数 / 总出现正向信号数
```

**异议处理率（两层漏斗）：**
```
响应率 = 被回应的异议数 / 被识别的异议数
  ↓
缓解率 = 被缓解的异议数 / 被回应的异议数
```

**判定标准：**
- "被响应"：销售在信号出现后的合理时间窗口内（同一对话轮次或下一轮次）做出了针对性回应
- "被缓解"：用户在销售回应后，未再重复同一异议，或表现出态度软化

### 质量评分汇总

```
单次服务质量 = 
    α × 关键事件覆盖率 
  + β × 机会利用率 
  + γ × 异议响应率 × 异议缓解率

（权重 α, β, γ 可根据业务调优）
```

### 管理端输出

- **团队仪表盘：** 各销售质量评分排名、趋势、维度对比
- **个人报告：** 具体到每通对话的质量拆解，标注"做得好"和"可改进"
- **培训建议：** 基于因素构成和薄弱维度，建立针对性培训主题

## 场景 3：续报前 — 意向分类 + 策略生成（服务于销售个体）

### 与场景 1 的关系

复用场景 1 的核心框架（意向分类 → 因素分析 → 策略生成），但数据源和上下文更丰富。

> 以下仅作为示意：

### 关键差异

| 维度      | 场景 1（首课前）   | 场景 3（续报前）     |
| ------- | ----------- | ------------- |
| 数据丰富度   | 少量行为 + 首次对话 | 更多课中行为 + 多轮对话 |
| 意向基线    | 从 0 开始判断    | 有历史意向变化轨迹     |
| 用户认知    | 对课程了解少      | 已有课程体验        |
| 驱动/阻塞因素 | 偏"预期型"      | 偏"体验型"        |
| 策略重点    | 建立连接、激发需求   | 巩固价值、化解续费障碍   |

### 续报特有的驱动因素

| 因素类型 | 示例               |
| ---- | ---------------- |
| 学习成果 | 孩子有进步            |
| 习惯养成 | 孩子主动要求上课         |
| 路径依赖 | 已学到某个阶段，中断可惜     |
| 升级需求 | 想从 体验课程 进阶到 正式学习 |

### 续报特有的阻塞因素

| 因素类型   | 示例          |
| ------ | ----------- |
| 效果不达预期 | "学了感觉没啥用"   |
| 兴趣衰减   | 孩子不想学了      |
| 服务不满   | 老师/课程/排课不满意 |
| 竞品替代   | 转去其他机构      |
| 经济压力   | "今年预算紧"     |

### 额外数据源

| 数据源    | 内容                  | 用途                |
| ------ | ------------------- | ----------------- |
| 课程履约数据 | 完课率、完课时长、作业提交率      | 量化用户投入度           |
| 学习表现数据 | 作品质量、能力评估           | 量化学习成果            |
| 历史对话全量 | 学期内所有沟通记录           | 追踪意向变化轨迹          |
| 历史意向标签 | 各阶段的意向分类结果          | 意向演变趋势            |
| 往期体验记录 | 历次体验周期的意向、阻塞因素、流失原因 | 识别跨周期的持续阻塞，避免重复犯错 |

## 场景 4：续报后 — 服务质量归因（服务于销售管理）

### 核心问题

续报结果（续/未续）的差异，多大程度上可归因于"服务质量"？

### 服务深度建模

**定义：** 服务深度不是独立模型，而是**场景 2 质量评价体系在续报阶段的复用 + 归因结果的反馈闭环**。

**量化公式：**
```
服务深度 = Σ(关键事件权重 × 是否发生 × 质量评分）
```

#### 关键事件权重：如何确定

基于历史数据，通过下方归因方法 2（回归建模）直接计算各服务动作对续报的边际贡献（SHAP 值），作为初始权重。

```
闭环：
  历史数据回归 → 初始权重
    → 线上服务深度计算
    → 新数据积累
    → 定期重跑归因 → 更新权重
```

关键事件清单直接复用场景 2 的清单（见维度 1），续报阶段可扩展额外事件（如"续费方案推荐"、"学习成果回顾"）。

#### 质量评分：如何计算

质量评分不是一个独立打分，而是**复用场景 2 中已有明确计算方式的维度**：

```
质量评分(事件_i) = 
    w1 × 该事件中的机会利用率（正向信号是否被接住）
  + w2 × 该事件中的异议处理率（响应率 × 缓解率）
```



**示例：**
```
事件: "确认决策人"（触发条件: S3 及以上）
  - 是否发生: 1（用户处于 S3，事件发生 → 满足触发条件）
  - 机会利用率: 1.0（用户主动提到"我做主"，销售顺势推进）
  - 异议处理率: N/A（该事件无异议，不计入）
  → 质量评分 = 1.0

事件: "介绍课程方案"（触发条件: S2 及以上）
  - 是否发生: 1
  - 机会利用率: 0.5（用户问了具体课时安排，销售未回应）
  - 异议处理率: 0.6（用户说"感觉内容太简单"，销售回应了但未缓解）
  → 质量评分 = 0.5 × 0.6 + 0.6 × 0.4 = 0.54
```

#### 服务深度计算示例

```
用户X 的服务深度:
  事件1 "了解学习情况":  权重 0.7 × 发生 1 × 质量 0.6 = 0.42
  事件2 "反馈课堂表现":  权重 0.8 × 发生 1 × 质量 0.9 = 0.72
  事件3 "确认决策人":    权重 0.9 × 发生 0 × 质量 0   = 0.00  ← 未做
  事件4 "续费课程推荐":  权重 0.8 × 发生 1 × 质量 0.5 = 0.40
  ───────────────────────────────────────────────
  服务深度 = 0.42 + 0.72 + 0.00 + 0.40 = 1.54 / 3.2(满分) = 48%
```

### 归因方法论

> 归因的输出不仅用于管理洞察，还应**反馈回服务深度模型**，更新关键事件的权重（见上方"归因反馈"）。

#### 方法 1：分组对比

控制**非服务因素**（用户特征、阶段）后，对比不同服务行为的续报差异。

```
分析框架:
  控制变量: 用户 leads 评分、渠道来源、年级、地区、班型
  自变量: 服务深度、各维度质量得分
  因变量: 续报（0/1）
  
  对比方式:
    - 相同意向阶段下，服务深度高 vs 低 的续报差异
    - 相同用户条件下，不同销售的续报差异
```

#### 方法 2：回归建模

```
续报 ~ 用户特征 + 状态特征 + 服务特征

  用户特征: Leads评分, 年级, 城市等级, 渠道来源, 设备类型
  状态特征（用户上课行为）: 完课率, 出勤率, 作业提交率, 作品完成数, 课堂互动频次
  服务特征:
    事件维度: 是否了解学习情况, 是否反馈课堂表现, 是否确认决策人, ...（各关键事件 0/1）
    因素维度: 驱动因素数, 阻塞因素数, 各因素类型是否出现（价格敏感, 时间冲突, ...）
    质量维度: 机会利用率, 异议处理率
  
  输出:
    - 各特征的边际贡献（系数 / SHAP 值）
    - 可控因素（服务特征）的提升空间估计
```

### 归因输出

| 输出内容    | 受众    | 用途                   |
| ------- | ----- | -------------------- |
| 动作贡献度排名 | 运营/策略 | 哪些销售行为对续报贡献最大        |
| 阶段关键动作  | 运营/策略 | 每个意向阶段最有效的动作是什么      |
